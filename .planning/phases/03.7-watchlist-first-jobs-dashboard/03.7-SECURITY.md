# Phase 03.7 — Security

> Retroactive STRIDE review of the current Watchlist Jobs, All Jobs, and
> tracker-backed applied-history implementation. The original Phase 03.7 plan
> predates formal threat-register blocks.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser route → authenticated shell | Every jobs, Watchlist, Tracker, Resume, Preferences, and Settings route is nested under `RequireAuth` | Session identity and private application/preferences data |
| Browser query → Supabase | Dashboard feed, tracker projection, and mutations cross the authenticated API/RLS boundary | Owner-scoped jobs, applications, events, and preferences |
| Stored URL → external employer | Apply links leave the application for an employer site | Public HTTPS job URL |
| Database projection → browser parser | `dashboard_applied_applications_v2()` adds normalized watched-company membership | Owner-scoped application snapshots and one boolean membership flag |

## Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation | Status |
|-----------|----------|-----------|----------|-------------|------------|--------|
| T-03.7-01 | Spoofing | Jobs and management routes | high | mitigate | `RequireAuth` wraps the shared `Shell`; protected routes are not mounted outside that boundary. | closed |
| T-03.7-02 | Information disclosure | Feed and applied-history reads | high | mitigate | Existing feed RLS remains authoritative. The v2 applied projection is `security invoker`, filters `application.user_id = auth.uid()`, and is executable only by `authenticated`. UI source scopes never widen account ownership. | closed |
| T-03.7-03 | Tampering | Watchlist source classification | medium | mitigate | Active rows require the normalized nested company relation. Applied rows require a database-derived boolean from `source_job_id → jobs.company_id → companies.id`; the client parser rejects missing, non-boolean, and extra fields and Watchlist filtering fails closed. | closed |
| T-03.7-04 | Spoofing / information disclosure | Employer Apply links | medium | mitigate | SQL emits only credential-free HTTPS values, `safeApplyUrl` revalidates them client-side, and new-tab links use `rel="noreferrer"`. | closed |
| T-03.7-05 | Denial of service | Dashboard filter/query input | medium | mitigate | Lifecycle/order/tier values are closed enums; company keys are normalized, deduplicated, control-character rejected, length bounded, and capped before the server request. Existing paged-feed limits remain in force. | closed |
| T-03.7-06 | Denial of service / tampering | Migration-to-web rollout | medium | mitigate | Migration 0058 introduces a versioned RPC instead of replacing the live eight-column RPC. The database can deploy first, and the strict new client switches only after v2 exists. | closed |

*Status: open · closed · open — below high threshold (non-blocking)*  
*Severity: critical > high > medium > low — only open threats at or above `workflow.security_block_on` count toward `threats_open`.*

<objective>
Apply the ingest predicate in the scheduler, record predicate-driven closure distinctly from upstream closure, and carry per-tenant Workday identity onto the poll path.

Purpose: this is where WD-COUNT is completed. The adapter returns a full reconciled observation so closure credibility survives; the scheduler derives the effective ingest set from it and computes closure against that set, so D-13 and D-14 hold without any observation losing credibility for a capacity reason.
Output: the predicate-aware scheduler, migration `0030_closure_reason.sql`, and a dedicated ingest test suite.

**Predicate scope, restated:** the predicate is applied to Workday pilot tenants only in this phase, using the location rule from that tenant's reviewed allowlist entry. D-15's location rule has no defined value for any other provider, and Paylocity has no detail fan-out to bound. Applying it to already-shipping providers would silently narrow their storage, which no decision authorises.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider observation -> ingest set | Where untrusted provider data becomes stored rows |
| ingest selection -> closure decision | Where a filtering decision can destroy or fabricate closure evidence |
| scheduler -> jobs table | Service-role writes that close user-visible rows |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-pasted URL -> `detectAts` | Untrusted free text selects, but never supplies, a server-owned identity |
| edge function -> `recruiting.paylocity.com` | Outbound unauthenticated request to a third party; response is untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.1-01-01 | Spoofing | `detect.ts` Paylocity host branch | high | mitigate | Exact host string equality only; no `endsWith`, wildcard, or subdomain match, so `recruiting.paylocity.com.attacker.example` cannot resolve |
| T-03.1-01-02 | Tampering | `detect.ts` GUID extraction | high | mitigate | Strict UUID regular expression on path segment 3; fixed five-segment path shape; query strings rejected; result lowercased so one board cannot mint two identities |
| T-03.1-01-03 | Information disclosure | outbound feed request | medium | mitigate | `redirect: 'error'` prevents a redirect from moving the request to an attacker origin; no credentials, cookies, or tokens are attached |
| T-03.1-01-04 | Denial of service | `pollPaylocity` response handling | medium | mitigate | Declared-length and actual-length byte caps, a job-count cap, a 15-second abort signal, and a two-attempt retry ceiling |
| T-03.1-01-05 | Tampering | provider payload -> stored snapshot | high | mitigate | All-or-nothing strict schema validation, https-only URL validation, duplicate-identifier rejection, and the D-27 company-identity cross-check; any failure degrades to closure-ineligible |
| T-03.1-01-06 | Repudiation | empty provider response | high | mitigate | A zero-length result is `implausible_empty` and closure-ineligible, so a broken or throttled board can never be read as a cleared board |
| T-03.1-01-07 | Elevation of privilege | new source union member | low | accept | The union member alone grants nothing; scheduling requires the SQL claim gate and dispatch gate added in later plans |
</threat_model>

<objective>
Build the pure ingest predicate that bounds Workday detail fan-out and storage (D-13, D-15). This plan has no dependency on either provider and runs in wave 1 alongside the Paylocity adapter.

Purpose: a single fixture-testable definition of "which postings on a complete reconciled list deserve a detail call and a stored row", with bounded reason codes that D-14's distinct closure recording depends on.
Output: `supabase/functions/_shared/ingest-predicate.ts` plus its test file.

**Scope boundary recorded deliberately:** this predicate is applied to the Workday pilot tenants only in Phase 03.1. D-15's location rule is defined per Workday tenant (`locationRule` on the allowlist entry, with BMO unfiltered) and has no defined value for Greenhouse, Lever, Ashby, SmartRecruiters, Recruitee, Adzuna, or Paylocity companies. Paylocity is additionally out of predicate scope because D-26 gives it descriptions inline and no detail fan-out, so there is nothing to bound. Applying the predicate to already-shipping providers would silently narrow their storage, which no decision authorises.
</objective>

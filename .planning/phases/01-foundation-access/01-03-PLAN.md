<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Email → browser | Password-reset links carry recovery tokens across an untrusted channel |
| Internet → pages.dev | Anyone can load the login page; auth is the only gate |
| Cloudflare build env → public bundle | Any env var entered there can end up in shipped JS |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Spoofing | Reset-link redirectTo (open redirect) | medium | mitigate | Supabase redirect allowlist contains only own origins (Task 2 step 5); redirectTo built from window.location.origin |
| T-01-07 | Elevation | Password change on a stolen session | medium | mitigate | current_password reauth attribute on updateUser (A7) in Settings password form |
| T-01-08 | Repudiation/Info disclosure | Partial delete-all (files linger after rows gone) | high | mitigate | Storage-first ordering + list/removed count equality assertion before RPC; verify-deletion.ts asserts both sides empty |
| T-01-02 | Information disclosure | Secret key in Pages build env or bundle | high | mitigate | Only VITE_ publishable vars entered in Cloudflare; post-build grep gate over src+dist |
| T-01-13 | DoS | Free project pause after 7 idle days | low | accept | Documented failure mode; Phase 2 pg_cron pipeline is the real fix; manual restore ~30 s (Pitfall 5) |
</threat_model>

# Phase 03.2: Code Review Report

**Reviewed:** 2026-07-22T21:14:23Z
**Depth:** standard
**Files Reviewed:** 22

## Summary

The dashboard filter and persistence boundaries are generally well-contained, but the required-experience parser violates the phase's core eligibility contract in both directions. The resize handle also has two incomplete pointer-lifecycle paths, and company search normalization is locale-dependent despite promising case-insensitive behavior.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: Required-experience parser both hides eligible jobs and keeps ineligible jobs

**File:** `supabase/functions/_shared/filters.ts:29-39`

**Issue:** The parser treats the first hyphenated range as required without checking whether the clause is optional, and the general matcher only checks optional words *before* the number. Consequently, `Preferred 5-7 years` and `5 years preferred` both return `5` and can incorrectly remove an eligible job. It also accepts every bare `N years` phrase regardless of whether it describes a work requirement, so text such as `Benefits vest after 5 years` is treated as required experience. In the other direction, `Math.min(...required)` lets a job with multiple mandatory requirements pass whenever any lower requirement is within the cap: `Requires 3 years SQL and 5 years industry experience` returns `3`, so a cap of 3 fails to remove a job that explicitly requires 5 years. These are direct violations of the phase contract that only explicit required minima above the cap exclude a job.

**Fix:** Parse clause-local candidates rather than returning the first range or accepting every years phrase. Require a positive requirement signal for ambiguous bare-year phrases, reject candidates with optional signals on either side in the same clause, collect all mandatory minima, and compare the highest mandatory minimum to the cap. Add regression cases for the four examples above. For example:

```ts
const mandatoryMinima = clauses.flatMap(parseMandatoryExperienceMinima)
return mandatoryMinima.length > 0 ? Math.max(...mandatoryMinima) : null
```

## Warnings

### WR-01: Pointer cancellation leaves a displayed width that is never persisted

**File:** `web/src/components/ColumnResizeHandle.tsx:40-48,113-114`

**Issue:** Pointer moves immediately update Dashboard state, but `pointercancel` calls `finishDrag(..., false)`, which neither commits the latest width nor rolls the state back to `startWidth`. After a browser/OS cancellation, the table therefore displays the dragged width for the rest of the mount while localStorage still contains the old width; the next refresh unexpectedly reverts it.

**Fix:** Give cancellation explicit semantics. Either persist `latestWidth` on cancel, or restore the pre-drag value so displayed and stored state agree:

```ts
if (commit) onWidthCommit(drag.latestWidth)
else onWidthChange(drag.startWidth)
```

### WR-02: A second pointer can orphan capture and leave document styles stuck

**File:** `web/src/components/ColumnResizeHandle.tsx:57-72`

**Issue:** `handlePointerDown` overwrites `activeDrag.current` even when a drag is already active. With a second touch on the coarse-pointer hit area, the first pointer remains captured, and the second drag snapshots the already-temporary `col-resize`/`none` body styles. Finishing the second pointer can then restore those temporary values permanently, while events from the first pointer no longer match the active ID.

**Fix:** Reject non-primary/concurrent pointer starts, or fully finish the active pointer before replacing it:

```ts
if (!event.isPrimary || activeDrag.current) return
```

### WR-03: Company search is not reliably case-insensitive across locales

**File:** `web/src/lib/dashboard.ts:24-26,42-48`

**Issue:** Both keys and queries use `toLocaleLowerCase()` with the browser's implicit locale. In Turkish locales, for example, `IKEA` normalizes to `ıkea` while a user typing `ikea` produces `ikea`, so the documented case-insensitive search fails and session hidden-key behavior differs by browser locale.

**Fix:** Use locale-neutral `toLowerCase()` for internal normalized keys and search needles, or pass one fixed locale deliberately in both functions.

# Phase 03.2 Validation Strategy

Formal Nyquist validation is disabled in `.planning/config.json`; this artifact records the proportionate verification contract used by the plans.

## Automated validation

- `cd web && npm test -- --run`
- `cd web && npm run build`
- `cd web && npm run lint`
- Focused tests for required-experience parsing, scoring-input invalidation, preferences/refilter, Dashboard company/tier helpers, Shell route width, and column-width persistence/resizing.
- Structural assertions for migration 0030 and the complete `filter_reason` set.

## Semantic edge coverage

- Required minimum exactly equal to cap remains eligible; values above cap reject.
- Preferred/desired/bonus/optional, missing, ambiguous, title-only, and provider-specific text remain eligible.
- All three score tiers selected initially and Weak rows remain reachable.
- Company search is truthful and staged; Reset/Show results and company+tier AND semantics are tested.
- Company/tier state resets on refresh/navigation; only guarded versioned column widths persist.
- Location replaces the list Match reason column while JobDetail retains Match reasons.
- Dashboard alone is full width; other routes retain the centered shell.
- Pointer cancel, keyboard bounds, malformed storage, denied storage, and narrow horizontal scrolling are covered.

## Manual release gate

Owner approval is required before hosted migration 0030, score-tick deployment, or web deployment. UAT evidence must record the exact release, test/build/lint results, and the D-01–D-17 behaviors above.

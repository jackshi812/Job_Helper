# Phase 04 — Application Tracker UI Design Contract

> Visual and interaction contract for the Application Tracker. Generated by
> gsd-ui-researcher for validation by gsd-ui-checker.

---

## Scope and Precedence

This contract covers the `/tracker` page, the expanded application detail row,
manual position capture, tracker-backed changes to Dashboard **Mark Applied** and
**Show applied**, and every loading, empty, validation, save, and recoverable
error state required by those flows.

`04-CONTEXT.md` is authoritative where the legacy roadmap or `TRAK-01` differs:
the lifecycle has exactly six stages. **Ready to Apply** replaces **Saved**, and
**Resume Prepared** is not a stage. Automated resume tailoring, resume
generation, application submission, manual-job ranking, and a Dashboard
**Save to tracker** action are out of scope.

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS v4 utilities and project-owned React components |
| Preset | Not applicable; `components.json` is absent and shadcn is not initialized |
| Component library | None; reuse native controls and existing project components such as `ConfirmDialog` and `ColumnResizeHandle` where appropriate |
| Icon library | None; use small project-owned inline SVGs with `currentColor`, never emoji |
| Font | Inter, then the existing system sans-serif fallback stack |
| Theme | Existing automatic light/dark theme from `prefers-color-scheme` |

Do not initialize shadcn or introduce a new component/icon dependency for this
phase. New tracker controls must use the same borders, radii, focus outlines,
button hierarchy, and coarse-pointer target treatment already present on the
Dashboard.

## Design Principles

1. **One table is the product.** Keep all applications in one compact,
   spreadsheet-like table. Do not introduce Kanban cards, stage columns, or
   separate active/terminal tables.
2. **Direct manipulation is visible and reversible.** Editable cells look
   interactive on hover/focus, commits report their own state, and failed drafts
   remain present for retry.
3. **History stays secondary but complete.** The main table exposes the current
   stage and relevant date; expanding a row reveals the full event ledger and
   preserved context without navigating away.
4. **Color reinforces text.** Every lifecycle color is paired with a written
   badge label. Color must never be the only indicator of stage, error, pin, or
   save state.
5. **Compact does not mean cramped.** Pointer rows may be dense; keyboard focus
   and coarse-pointer controls still meet the target-size contract below.

## Spacing Scale

Declared values are multiples of four:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Save-status gap, icon-to-label gap, timeline micro-spacing |
| sm | 8px | Cell-control gap, filter gap, badge horizontal rhythm |
| md | 16px | Table cell horizontal padding, panel padding, form gaps |
| lg | 24px | Header-to-filter and section spacing |
| xl | 32px | Expanded-row padding, timeline outer padding |
| 2xl | 48px | Major empty-state breathing room |
| 3xl | 64px | Reserved page-level separation; do not use inside table rows |

### Density and Exceptions

- Standard data cells: `12px 16px` padding and a 44px minimum row height.
- Header cells: `8px 16px` padding.
- Stage badges: `4px 8px` padding, full pill radius.
- Standard controls: 36px minimum height on fine pointers.
- All icon-only controls and every control under `pointer: coarse`: 44px square
  or 44px minimum height.
- Timeline nodes are a visual exception at 20px diameter; their interactive
  button hit area is 44px.
- Focus outlines are 2px with a 2px offset and do not count toward layout size.
- The manual draft row may expand vertically to fit validation and duplicate
  warnings. Existing saved rows remain compact.

## Typography

Use exactly these four sizes and two weights. Do not add medium, bold, or
extra-bold weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Table meta / status / badge | 12px | 400 or 600 | 1.4 |
| Body / cell / control | 14px | 400 or 600 | 1.5 |
| Section / empty-state heading | 16px | 600 | 1.25 |
| Page heading | 20px | 600 | 1.2 |

- Page title: 20px semibold with existing tight letter spacing.
- Column headers: 12px semibold, uppercase, tracking-wide.
- Editable values: 14px regular; use semibold only for the primary position
  link and buttons.
- Dates and save state: 12px regular; **Retry** is 12px semibold.
- Never reduce interactive text below 12px.

## Color

### Page-Level 60/30/10 Contract

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#f8fafc` | `#09090b` | Page background and open space |
| Secondary (30%) | `#ffffff` | `#18181b` | Table, expanded details, filter popovers, dialog surfaces |
| Accent (10%) | `#18181b` | `#f4f4f5` | Primary **Add position** button, selected neutral filter presets, focus outlines |
| Destructive | `#dc2626` | `#f87171` | Delete-event text, destructive confirmation, unrecoverable field error |

Accent is reserved for the primary CTA, selected neutral filter presets, and
keyboard focus outlines. Lifecycle colors are semantic colors and do not replace
the page accent. Do not make all links or editable cells accent-colored.

### Lifecycle Palette

Each row has both a written pill badge and a subtle matching treatment: a 4px
leading accent on the first visible cell plus a low-opacity row tint. Keep body
text at zinc-900/zinc-100 for contrast.

|-------|---------------|--------------|-------------------|
| Ready to Apply | `border-zinc-200 bg-zinc-50 text-zinc-700` | `border-zinc-700 bg-zinc-950 text-zinc-300` | zinc-300 / `zinc-50/40`; dark zinc-600 / `zinc-950/20` |
| Applied | `border-blue-200 bg-blue-50 text-blue-700` | `border-blue-900 bg-blue-950 text-blue-300` | blue-400 / `blue-50/35`; dark blue-700 / `blue-950/15` |
| Outreach Sent | `border-cyan-200 bg-cyan-50 text-cyan-700` | `border-cyan-900 bg-cyan-950 text-cyan-300` | cyan-400 / `cyan-50/35`; dark cyan-700 / `cyan-950/15` |
| Interview | `border-lime-200 bg-lime-50 text-lime-800` | `border-lime-900 bg-lime-950 text-lime-300` | lime-400 / `lime-50/40`; dark lime-700 / `lime-950/15` |

### Supporting Semantic Colors

- Recoverable warning / possible duplicate: amber-50, amber-200, amber-900 in
  light mode; amber-950, amber-900, amber-200 in dark mode.
- Saving / neutral metadata: zinc-500.
- Saved: emerald-700 light / emerald-400 dark, always with the word **Saved**.
- Retry / field error: red-700 light / red-400 dark, always with text or an icon
  plus accessible text.
- Timeline connector and node border: blue-600 light / blue-400 dark. Node
  centers use the secondary surface color.

## Page Anatomy

### Header

- Left: `Tracker` page heading.
- Below: `Track applications, update stages, and keep every follow-up in one place.`
- Right on wide screens, wrapped below the description on narrow screens:
  primary **Add position** button.
- Do not add metrics cards, charts, or a second page-level CTA.

### Filters

Place the filter bar 24px below the header and 16px above the table.

- Label the group **Stage filters**.
- Provide quick actions **Active stages**, **Terminal stages**, and **All stages**.
- Render the six individual stage toggles beneath or beside the quick actions
  when space permits. Each uses its written stage label and `aria-pressed`.
- Initial selection is exactly Ready to Apply, Applied, Outreach Sent, and
  Interview.
- **Active stages** selects those four. **Terminal stages** selects Offer and
  Rejected. **All stages** selects all six.
- Any independent toggle selection is valid. If no stage is selected, show the
  filtered empty state; do not silently reset the selection.
- Use stage color only as a small dot or border cue on filters. Pressed state
  must also be conveyed by fill, border, and `aria-pressed`.

Pinning is not a filter. Pinned applications always sort before unpinned
applications inside the selected stages. Within each group, sort by most recent
`updated_at`, then stable ID.

### Table Container

- Reuse the Dashboard pattern: rounded 8px bordered secondary surface with
  horizontal overflow, `role="region"`, `tabIndex={0}`, and accessible label
  `Applications; scroll horizontally to view all columns`.
- Keep one semantic `<table>` with a sticky header.
- Minimum table width: 1,224px. Do not transform rows into cards on mobile.
- Recommended fixed columns:

| Order | Column | Width | Contract |
|-------|--------|-------|----------|
| 1 | Expand | 48px | Chevron button; no text header, accessible name present |
| 2 | Pin | 48px | Star/pin toggle; no text header, accessible name present |
| 3 | Company | 176px | Editable for manual rows; read-only snapshot for system rows |
| 4 | Position | 248px | Job title link and optional resume indicator |
| 5 | Stage | 168px | Inline native/custom select with colored badge treatment |
| 6 | Stage date | 136px | Date-only value for the latest event |
| 7 | Notes | 288px | Two-line preview; inline edit affordance |
| 8 | Updated | 112px | Relative time with full localized timestamp in `title` |

- Column resizing may reuse `ColumnResizeHandle`; if enabled, persist widths
  under tracker-specific storage keys and keep the minimum table width. Resizing
  is optional and must not delay the core interaction contract.
- Pinned rows appear first. The pin cell must not visually imply that pinned
  rows are a separate table.

### Row Presentation

- Saved rows use a 44px minimum height and the lifecycle badge plus subtle row
  accent defined above.
- The Position link opens the preserved HTTPS job URL in a new tab and includes
  `↗` visually with `new tab` in its accessible name. If no valid URL exists,
  render the title as text, not a broken link.
- The resume indicator is a 16px document icon placed beside the position title,
  never a dedicated column. Its accessible label is
  `Resume linked: {resume label}`.
- System company and title snapshots are plain read-only text. Do not show a
  disabled input, lock icon, or edit affordance.
- Manual company and title cells gain a zinc hover background and edit affordance
  on focus/hover. Double-click, Enter, or F2 enters edit mode.
- Notes show up to two lines and 120 characters, then an ellipsis. The complete
  editable value is always available in the expanded row.
- The leading pin control uses an outline star when unpinned and filled star
  when pinned, plus `aria-pressed` and the names `Pin {position}` /
  `Unpin {position}`.

## Inline Editing Contract

### Entry and Keyboard Behavior

- Enter company/title edit mode for manual rows with double-click, Enter, or F2.
- Stage uses a select and commits immediately when changed.
- Pin commits immediately when toggled.
- Company, title, stage date, and the compact notes editor commit on blur or
  Enter. In multiline notes, `Ctrl+Enter` or `Cmd+Enter` commits and Enter adds a
  newline.
- Escape restores the last server-confirmed value and exits edit mode.
- Tab commits the current valid draft and moves through controls in DOM order.
- Keep focus in the edited cell after a recoverable failure.
- Never send a generic whole-row patch from a cell edit.

Changing stage inserts a new chronological event with `occurred_on` set to the
current date. Changing **Stage date** edits the latest event's `occurred_on`; it
does not create a second event. Dates are date-only in the UI and persistence.
`created_at` is retained solely for deterministic ordering and audit metadata.

### Per-Cell Autosave State

Every editable cell owns one of these states, keyed by
`applicationId:field`:

| State | Visible treatment | Accessibility |
|-------|-------------------|---------------|
| Saving | `Saving…` in 12px zinc-500 with a small nonessential spinner | `role="status" aria-live="polite"` |
| Saved | `Saved` in 12px emerald text with a check icon | Announce once in the same polite live region |
| Retry | `Couldn’t save. Retry` in 12px red; Retry is a real button | Error text uses `role="alert"`; button has the accessible name `Retry saving` and retries the unchanged draft |

- **Saved** remains visible until that cell is edited again or the row leaves the
  viewport; do not rely on a fleeting toast.
- Serialize writes to the same cell. A second edit must not be overwritten by an
  older response.
- A failed draft remains visible and is not replaced by stale server data.
- Page-level loading, another cell's save, or an unrelated row must not disable
  the whole table.
- Do not use a page-wide autosave indicator or success toast.

## Manual Position Capture

Selecting **Add position** inserts one unsaved draft row immediately under the
table header and focuses **Company**. If a draft already exists, focus its first
invalid field rather than inserting another.

The draft is a table row, not a modal. It may be taller than saved rows:

- Company cell: required text input.
- Position cell: required job-title input followed by required job-URL input.
- Stage cell: **Ready to Apply** by default and immediately editable.
- Stage date: current date, read-only until the row is created.
- Notes: optional compact textarea.
- The final cell area contains **Add position** and **Discard draft**.

Persist nothing until company, job title, and job URL are valid. Job URL must
parse as HTTPS. Location and job description are optional and can be added in
the expanded details after creation.

Use exact inline validation:

| Field | Message |
|-------|---------|
| Company | `Enter a company.` |
| Job title | `Enter a job title.` |
| Job URL empty | `Enter a job URL.` |
| Job URL invalid or non-HTTPS | `Enter a valid HTTPS job URL.` |

Associate each message with its field through `aria-describedby`, set
`aria-invalid="true"`, and focus the first invalid field after submit.

If normalized company/title resembles an existing application, show an amber
inline warning:

`Possible duplicate: {Company} — {Job title}. You can add it anyway.`

The warning does not disable **Add position** and requires no second
confirmation. On success, replace the draft with the saved Ready to Apply row
and announce `Position added.` On failure, retain every draft value and show:

`Couldn’t add this position. Check your entries and retry.`

**Discard draft** removes only the unsaved client draft and needs no destructive
confirmation.

## Expanded Application Detail

The expand button inserts a second `<tr>` immediately after its parent. Its
single `<td>` spans every visible column and has 32px padding. The button uses
`aria-expanded`, `aria-controls`, and the label
`Show details for {position}` / `Hide details for {position}`.

Only one row needs to be open at a time on small screens; multiple open rows are
permitted at 768px and above. Opening a row lazily loads the event ledger,
preserved job description, optional location, URL details, and resume label.

Order expanded content as follows:

1. Event timeline.
2. Full notes editor.
3. Position details and preserved job description.
4. Optional resume link.

Use a two-column detail grid at 900px and above. Below 900px, stack the sections
without changing table semantics.

### Horizontal Event Timeline

The timeline must visually follow
`references/stage-timeline-reference.png`:

- full-width horizontal connecting line;
- circular event nodes centered on the line;
- localized dates above the nodes;
- stage/event labels below the nodes.

Implementation contract:

- Use a horizontally scrollable region with label
  `Stage history for {position}`.
- Render events as an ordered list sorted by
  `occurred_on ASC, created_at ASC, id ASC`.
- Use 32px horizontal outer padding and at least 144px center-to-center node
  spacing. The line is 4px high.
- Each node is a 20px circle with a 4px blue border and the current detail
  surface as its center. The node's button hit area is 44px.
- Dates use localized medium form such as `Jul 18, 2026`, in 12px zinc text,
  above the line. Include `<time dateTime="YYYY-MM-DD">`.
- Labels use 14px semibold centered text below the line.
- The connector does not imply a fixed lifecycle. It connects the events that
  actually occurred and may move forward, repeat, or reflect a corrected stage.
- Repeated stages create separate nodes. A single occurrence is unnumbered.
  Once a stage repeats, label all its occurrences in chronological order:
  **Interview 1**, **Interview 2**, and so on. Apply the same rule to any stage
  that repeats. Ordinals are derived display text, never stored.
- Do not animate the connector. Under reduced motion, no timeline or row
  transition is permitted.

Selecting an event node opens an inline editor immediately below the timeline
with a stage select, date input, **Save event**, and **Delete event**. Its heading
is `Edit {event label}`. Saving reorders nodes and recalculates ordinals/current
stage when required.

### Event Deletion

Deleting a non-final event uses the existing `ConfirmDialog` pattern:

- Dialog title: `Delete timeline event?`
- Body: `Delete {event label} from {date}? The current stage may change.`
- Destructive action: `Delete event`
- Secondary action: `Keep event`

The final remaining event cannot be deleted. Disable or omit **Delete event**
and show:

`Every application needs one timeline event. Edit this event instead.`

If the server rejects a deletion after concurrent changes, retain the editor and
show:

`Couldn’t delete this event. Refresh the timeline and retry.`

The visible retry action may remain **Retry**; its accessible name is
`Retry deleting event`.

No whole-application delete control is introduced in this phase.

### Notes

- The expanded row shows the complete note in a textarea at least 160px high.
- Label it **Notes**; placeholder:
  `Add contacts, follow-ups, interview details, or next steps.`
- It edits the same single notes value as the table preview and uses the same
  per-cell Saving/Saved/Retry state.
- Preserve line breaks. Do not render notes as HTML.

### Position Details and Job Description

- Show company, job title, location, and HTTPS job URL.
- For system-discovered applications, these are read-only snapshots even if the
  source posting later changes or disappears.
- For manual applications, company/title remain editable inline in the main
  table; location, URL, and optional job description are editable here.
- Label the context section **Job description**.
- System HTML snapshots must use the existing sanitized JobDetail rendering
  pattern. Manual job descriptions render as plain text with preserved line
  breaks.
- Empty optional description copy:
  `No job description was saved for this position.`

### Resume Link

- Label the field **Linked resume (optional)**.
- Use a select populated only from the user's private Resume Library, with
  **No linked resume** as the first option.
- A selected resume shows its established resume label and an **Open resume**
  link/action.
- Never offer to generate, tailor, score, or rewrite the resume.
- If the linked resume is deleted elsewhere, the application remains, the
  reference clears, the main-row icon disappears, and this control returns to
  **No linked resume** without an error state.

## Dashboard Integration Contract

### Mark Applied

- Retain the Dashboard button label **Mark Applied**.
- Success removes the job from Active and creates/updates the same tracker
  application at **Applied** with today's event.
- Do not add **Save to tracker** and do not create an application merely because
  the external Apply link was opened.
- Remove the **Undo applied** action. A system job that was ever marked applied
  never returns to the Active queue.
- After success, announce:
  `{Job title} marked applied and added to Tracker.`

### Show Applied

**Show applied** uses tracker-backed system-application snapshots and remains a
compact Dashboard table. It contains every system job ever marked applied,
regardless of current tracker stage or source-posting status.

Render these columns in order:

1. Position
2. Company
3. Location
4. Applied date
5. Current stage
6. Apply link
7. Tracker link

Current stage uses the same badge palette as the Tracker. **Tracker link** is
`View in Tracker` and opens `/tracker` with the application row focused and
expanded. Do not preserve score, tier, or best-fit-resume columns in this
historical view, and do not restore live-job dependencies solely to populate
them.

## Loading, Empty, and Recovery States

- Preserve the table container during initial load and show
  **Loading applications…** with `role="status"`.
- A full-page query failure appears inside the table surface with the exact load
  error copy and a visible **Retry** button with accessible name
  `Retry loading applications`. Filters and header remain available.
- The initial empty state includes **Add position** as its action.
- The filtered empty state does not repeat the create CTA; it points users to
  stage filters.
- Expanded-detail failure is isolated inside the expanded row. It must not
  collapse the row or replace the parent application.
- Per-cell failures remain local as defined in the autosave contract.
- Duplicate warning is recoverable and nonblocking.
- Do not use browser `alert`, `confirm`, or transient toast as the only feedback.

## Responsive Behavior

### 1024px and Above

- Page header action aligns to the right.
- Filter quick actions and stage toggles share one wrapping row.
- Table remains at least 1,224px and scrolls only when the viewport/container is
  narrower.
- Expanded detail uses a two-column lower grid; timeline spans both columns.

### 768–1023px

- Header action wraps below the heading as needed.
- Filters wrap without horizontal page overflow.
- Table scroll container is the only horizontal overflow at page level.
- Expanded lower details stack when less than 900px.

### 320–767px

- Keep the semantic table and its 1,224px minimum width; do not replace it with
  cards or stage boards.
- Show a one-time visually present hint above the table:
  `Swipe horizontally to view and edit all columns.`
- Keep Expand and Pin as the leading columns so they appear first when the table
  is scrolled to its initial position.
- The manual draft retains required inputs in their table cells; focus must
  scroll the target cell into view.
- Expanded timeline has its own horizontal scroll and must not widen the page.
- All controls use a 44px minimum touch target.

## Accessibility Contract

- Preserve native `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`, and
  paired parent/detail `<tr>` semantics.
- The scroll region is keyboard focusable and has a visible 2px outline.
- Expand uses `aria-expanded`/`aria-controls`; Pin and stage filters use
  `aria-pressed`.
- Every icon-only control has an application-specific accessible name. Decorative
  icons use `aria-hidden="true"`.
- Every input has a programmatic label. Do not use placeholder text as the only
  label.
- Stage is never conveyed by color alone: full text appears in badges, selects,
  filters, and timeline nodes.
- Saving/Saved uses a polite live region; failed save/delete/create messages use
  `role="alert"`. Avoid announcing every keystroke.
- When a confirmation dialog opens, focus begins on **Keep event**, remains trapped
  in the dialog, Escape keeps the event and closes the dialog, and close returns
  focus to the originating event control.
- On row collapse, focus returns to that row's expand button.
- Timeline events are an ordered list; node controls expose label and date in
  their accessible names.
- External job links include `new tab` in their accessible name and use
  `rel="noreferrer"`.
- All text and controls meet WCAG AA contrast in both existing themes.
- Honor `prefers-reduced-motion`; no functionality depends on animation.

## Interaction State Matrix

| Interaction | Pending | Success | Recoverable failure |
|-------------|---------|---------|---------------------|
| Pin/unpin | Disable only that pin control; show Saving in cell | Reorder row into pinned/unpinned group; show Saved | Retain prior order and show Retry in pin cell |
| Stage change | Keep selected draft badge; Saving | Add dated event, update row badge/tint/date, reorder by `updated_at`; Saved | Keep selected draft and show Retry |
| Latest date edit | Keep edited date; Saving | Reorder timeline if open; recalculate current event as required; Saved | Keep date draft; Retry |
| Notes edit | Keep full local text; Saving | Update preview and full editor together; Saved | Keep local text in both surfaces; Retry |
| Manual company/title edit | Keep draft; Saving | Update row/link label; Saved | Keep draft and focus; Retry |
| Add position | Disable only draft submit; `Adding…` | Replace draft with saved row; announce `Position added.` | Keep all fields; show create error |
| Edit event | Disable editor submit; `Saving…` | Reorder nodes/ordinals and refresh current stage | Keep editor open with Retry |
| Delete event | Confirm dialog then disable destructive action | Remove node, recalculate ordinals/current stage | Keep editor open with deletion error |
| Link resume | Keep selected draft; Saving | Update resume icon and label; Saved | Keep selection; Retry |
| Expand row | Show isolated `Loading details…` | Render timeline/details without navigation | Keep row expanded with isolated Retry |

# Plan 04-06 — Owner UI Gap Closure

## Goal

Apply the owner's Tracker, Dashboard, resume-display, and navigation decisions
without weakening application ownership or the existing irreversible Mark
Applied contract.

## Locked Decisions

- `/tracker` uses the full available page width and does not require horizontal
  table scrolling; complete values wrap instead of truncating.
- The rightmost Tracker column is `Status`, not `Updated`, and reports the most
  recent row mutation as Saving, Saved, or Retry.
- Filter presets use one dropdown and the six individual stages use one
  dropdown.
- Owners can delete an application from Tracker or Dashboard Show applied only
  after confirmation.
- Deleting a system application removes Tracker history but does not clear
  `user_jobs.applied_at`, so it never silently returns to Active.
- Dashboard removes the Best fit/runner-up resume display and Resume Library
  query; the Resumes page and upload flow remain unchanged.
- Primary navigation is exactly Watchlist Jobs, All Jobs, Tracker, Resumes,
  Preferences, Settings. The existing `/watchlist` route remains available but
  is not a primary tab.

## Tasks

### 1. Owner-scoped application deletion

- Add forward migration `0056_delete_tracker_application.sql`.
- Add `delete_tracker_application(uuid) returns boolean` with authentication,
  owner predicate, empty search path, narrow authenticated execute grant, and
  postgres ownership.
- Add migration, schema-verifier, data-client, and UI tests.
- Reuse `ConfirmDialog` in Tracker and Dashboard applied history.

### 2. Tracker density and status

- Give `/tracker` the full-width shell.
- Remove the 1,224px minimum width, horizontal-overflow label/hint, and rigid
  pixel columns.
- Use a 100%-width fixed table with wrapped values and min-width-safe controls.
- Aggregate the latest row mutation into the rightmost `Status` cell.
- Replace the nine filter buttons with stage-group and individual-stage selects.

### 3. Dashboard and navigation cleanup

- Remove Dashboard resume-routing imports, query, mapping, cell, and column.
- Preserve the Resumes page and upload implementation unchanged.
- Apply the exact six-tab navigation order and update shell/dashboard tests.

### 4. Verification and release

- Run focused tests, full `npm test`, build, lint, and `git diff --check`.
- Refresh Phase 04 review/security/UI/verification evidence.
- Exact-approve and apply migration 0056, deploy the web release, verify live
  asset bytes, and resume owner UAT.

## Threat Model

| Threat ID | Component | Severity | Mitigation |
|---|---|---:|---|
| T-04-06-01 | application delete target | high | Security-definer RPC deletes exactly one `auth.uid()`-owned application or fails |
| T-04-06-02 | accidental destructive action | high | Explicit confirmation, cancel-first focus, pending state, and retained dialog on failure |
| T-04-06-03 | system job lifecycle | high | Delete never clears `user_jobs.applied_at`; deleted jobs stay out of Active |
| T-04-06-04 | stale caches | medium | Invalidate Tracker list/detail and Dashboard applied projections after success |
| T-04-06-SC | dependency supply chain | low | No install; reuse existing project dependencies and ConfirmDialog |

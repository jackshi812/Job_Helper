Consume the Plan 01 database contracts without renaming parameters or creating
generic row patches. Query keys are:
- `['tracker-applications', selectedStages]`
- `['tracker-application', applicationId]`
- existing `['resumes']`

Same-cell writes use stable TanStack mutation `scope.id` values of
`applicationId:field`, `retry: false`, retained mutation variables on failure,
and scoped invalidation. System HTML uses the existing JobDetail DOMPurify
configuration; manual descriptions and notes render as text.

Manual creation uses only
`create_manual_application(p_company text, p_title text, p_apply_url text, p_notes text, p_stage text, p_occurred_on date) returns table(application_id uuid, duplicate_warning boolean)`. The Plan 01 client
surface is
`createManualApplication(input: ManualApplicationCreateInput):
Promise<ManualApplicationCreateResult>`, where the input is exactly
`{ company, title, applyUrl, notes, stage }`; the client derives the current
date and sends it as `p_occurred_on`, while the result is
exactly `{ applicationId, duplicateWarning }`. Location and description are
post-create `updateApplicationTextField` operations and must not be added to
the create payload.
</interfaces>

## Trust Boundaries

OWASP ASVS Level 1; any HIGH or CRITICAL finding blocks completion.

| Boundary | Description |
|---|---|
| Editable Tracker cells → narrow RPCs | Field, text, stage, date, URL, pin, and resume values are untrusted |
| Stored JD/notes/URL → browser | Persisted content can still carry XSS or unsafe navigation |
| Timeline event editor → current-stage projection | Corrections/reordering must not produce a forged or stale aggregate |
| Resume Library → application link | A guessed hidden resume ID must never associate across owners |
| Local draft/cache → server state | Concurrent autosaves and failures must not overwrite newer drafts |

# Phase 02.1: Source Coverage Expansion - Context

**Gathered:** 2026-07-17
**Status:** Ready for research and planning

<domain>
## Phase Boundary

Expand the completed Phase 2 ingestion architecture beyond Greenhouse, Lever, and Ashby. This phase is a representative source-coverage proof, not a requirement to pre-populate 100 companies and not a promise to scrape every arbitrary career website. It adds one test company for each feasible additional platform, validates an agreed set of major finance-company career sites, adds a Link column, and hardens degraded-source behavior. Scoring, preferences, notifications, resume tailoring, and arbitrary universal scraping remain outside this phase.

</domain>

<decisions>
## Implementation Decisions

### Coverage strategy
- **D-01:** Use a **major-employers-first** strategy. Prefer stable shared adapters; add allowlisted company-specific adapters only when a branded site cannot be resolved to a reusable platform.
- **D-02:** Do not seed 100 companies in this phase. Prove connectivity with one publicly testable company per supported source platform.
- **D-03:** Preserve existing Greenhouse, Lever, and Ashby support. Research and attempt representative coverage for SmartRecruiters, Recruitee, Workday, Oracle Recruiting, iCIMS, SuccessFactors, and Eightfold.
- **D-04:** A named platform is a research target, not a pre-judged guarantee. If its public access path is authenticated, prohibited, bot-blocked, or too unstable for safe polling, document the evidence and leave it unsupported rather than disguising scraping as reliable coverage.

### Branded/custom finance validation set
- **D-05:** Validate direct-source coverage for: Morgan Stanley, Goldman Sachs, JPMorgan Chase, Bank of America, Citi, BlackRock, Wells Fargo, UBS, Barclays, Capital One, Fidelity, and Charles Schwab.
- **D-06:** Detect the underlying ATS/portal behind each branded domain first. Reuse a shared adapter when possible. Build a company-specific adapter only for a truly custom public source.
- **D-07:** Branded/custom adapters are explicit allowlist entries, not a generic arbitrary-HTML scraper.

### Watchlist link
- **D-08:** Add a **Link** column to the Watchlist table.
- **D-09:** The link uses the stored canonical job-search/careers URL and opens in a new tab with safe external-link attributes. Prefer a directly searchable job board over a generic corporate careers landing page.

### Failure semantics
- **D-10:** When a source is blocked, changed, failed, or implausibly empty, preserve last-known jobs and show **Degraded** with last-success time and useful error detail.
- **D-11:** A failed or implausibly empty observation must never mark jobs closed. Closure remains allowed only after a credible successful source response.
- **D-12:** Do not silently substitute Adzuna for a failed direct source in this phase. Direct-source degradation must remain visible and attributable.

### Activation
- **D-13:** Use staged activation for every new connector: manual verification, fixture/contract tests, several successful syncs, then scheduled polling.
- **D-14:** Keep unstable connectors manual or disabled until they meet the activation gate. The UI and planning artifacts must distinguish experimental, active, and degraded states.

### Claude's Discretion
- Select the representative company for each public platform based on a currently reachable, legally usable, publicly testable endpoint.
- Define adapter interfaces and whether platform detection uses URL patterns, a provider registry, or both.
- Choose the exact number of consecutive successful syncs required for activation, with a minimum of two observations across separate polling opportunities.
- Choose per-host rate limits, pagination caps, timeouts, and retry/backoff values within Supabase Edge and free-tier constraints.
- Group finance sites by their detected underlying provider after research; the named company list is fixed, but one shared adapter may satisfy several companies.

</decisions>

<specifics>
## Source Coverage Matrix for Research

| Class | Target | Expected approach | Planning caveat |
|---|---|---|---|
| Existing public APIs | Greenhouse, Lever, Ashby | Preserve current adapters and regression coverage | Must not regress existing watchlist rows |
| Additional public APIs | SmartRecruiters, Recruitee | Provider adapter using documented public posting/careers endpoints | Verify current auth and rate-limit behavior |
| Structured public portals | Workday, Oracle Recruiting, iCIMS, SuccessFactors, Eightfold | Detect tenant/site identity and use a dedicated public-portal adapter where safe | Official tenant APIs may require employer credentials; public website calls may be undocumented or change |
| Branded finance sites | Twelve fixed companies in D-05 | Resolve underlying provider first; allowlisted custom adapter only as fallback | Branded hostname does not imply a custom backend |

The planner should produce an evidence-backed matrix containing canonical careers URL, detected provider, public endpoint/access method, pagination/detail-fetch behavior, bot/terms constraints, representative test result, and disposition (`shared adapter`, `custom adapter`, or `unsupported with reason`).

</specifics>

<risks>
## Difficulties and Required Mitigations

- **Authentication mismatch:** Official Workday, SuccessFactors, and similar tenant APIs may require customer credentials and cannot be assumed available for arbitrary employers. Research the public candidate portal separately.
- **Bot protection and JavaScript rendering:** WAFs, CAPTCHAs, and browser-only rendering may be incompatible with scheduled Supabase Edge execution. Do not attempt CAPTCHA bypasses or login-protected extraction.
- **Schema drift:** Undocumented portal calls and custom pages can change without notice. Keep parsing isolated per adapter and maintain fixtures/contract probes.
- **False mass closure:** A portal outage can look like an empty board. Reuse and extend Phase 2's credible-success/implausible-empty guard before any stale-close operation.
- **Pagination and detail fan-out:** Some portals require multiple list pages plus one request per job description. Use bounded concurrency, host-specific throttling, and explicit incomplete-run semantics.
- **Multiple regions/locales:** One employer may expose separate country, language, student, and experienced-hire portals. Record coverage boundaries instead of claiming complete global coverage without evidence.
- **Cross-source duplicates:** Company-direct jobs may also arrive through Adzuna. Preserve stable provider IDs and existing normalized fingerprint deduplication.
- **Freshness:** Current user-approved aggregator cadence is 30 minutes from 06:00-noon Chicago and every two hours otherwise. Direct-source polling cadence and the original 5–15 minute product promise must be reconciled during planning per provider capacity.
- **Compliance:** Respect public access boundaries, robots directives, and site terms. No logged-in scraping, CAPTCHA bypass, or concealment of automated traffic.

</risks>

<code_context>
## Existing Code Insights

### Reusable assets
- `supabase/functions/_shared/adapters/` — current provider-specific polling modules and normalized `JobInput` contract
- `supabase/functions/_shared/detect.ts` — pure URL detection and polling-endpoint construction; currently restricts support to Greenhouse/Lever/Ashby
- `supabase/functions/verify-board/index.ts` — server-authoritative detection and one-live-call verification boundary
- `supabase/functions/poll-tick/index.ts` — provider dispatch, health updates, plausible-empty protection, ingestion, reopen, and closure behavior
- `supabase/functions/_shared/lifecycle.ts` — lifecycle plan that already avoids closure on empty returned sets
- `web/src/lib/watchlist.ts` and `web/src/pages/Watchlist.tsx` — Watchlist query/model and dense table where Link and Degraded details land

### Required schema changes
- `companies.ats_type` currently permits only `greenhouse`, `lever`, and `ashby`; expand through a migration without weakening validation.
- `jobs.source` currently permits only `greenhouse`, `lever`, `ashby`, and `adzuna`; add only source values backed by implemented adapters.
- Preserve stable provider/tenant identity separately from the human-facing canonical careers URL when a branded site resolves to a shared ATS.
- Model activation state explicitly if `experimental`, `active`, and `degraded` cannot be derived truthfully from existing fields.

### Testing expectations
- Pure URL-detection fixtures for each supported host/tenant pattern and explicit rejections for lookalike hosts.
- Provider response fixtures covering pagination, missing fields, empty boards, malformed responses, and detail-fetch failures.
- Regression proof that any failure or implausibly empty response preserves last-known jobs and never invokes closure.
- Hosted non-destructive probes for each activated representative source.

</code_context>

<deferred>
## Deferred Ideas

- Pre-populating a catalog of 100 companies — explicitly not required for this phase.
- A universal arbitrary-site scraper or headless-browser farm.
- Adzuna fallback that masks a failed direct source.
- Guaranteed global/locale-complete coverage for every named finance company.
- Scoring, feed, and notifications — remain Phase 3.

</deferred>

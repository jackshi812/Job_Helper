## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Catalog/browser identity → server fetch | Only frozen provider identities may select an origin, path, tenant, site, facet, or operation | Untrusted URL and catalog identity data |
| Provider response → normalized observation | External pagination, labels, counts, details, and country evidence are untrusted | Public provider job data |
| Observation → activation/lifecycle | Only exact, complete, server-timed evidence may activate a source; incomplete evidence cannot authorize closure | Monitoring health and job lifecycle authority |
| Cron/verifier → privileged database operations | Shared-secret/service-role callers cross into bounded RPC and fixture authority | Operational source state and disposable verification fixtures |
| Release manifest/approval → production | Human approval must bind exact target, source, hashes, actions, and limits | Schema, function, and scheduler mutations |
| Hosted state → Watchlist | Persisted catalog/company/job truth becomes signed-in monitoring status | Owner-visible company health and career links |

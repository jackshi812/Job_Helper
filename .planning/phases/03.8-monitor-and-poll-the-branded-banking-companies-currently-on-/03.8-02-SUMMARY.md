## Decisions Made

- Only exact registry object references authorize transport; copying or altering an identity cannot widen network authority.
- Oracle list requests use `findReqs;siteNumber=...,limit=...,offset=...` with comma-separated variables, matching the official live anonymous contract.
- Goldman role details use the public `GetRoleById` operation and require the exact reviewed Oracle Cloud application host and role path.
- A provider can return HTTP 200 and valid JSON yet still be non-credible: stable counts, every page, every retained detail, positive category, exact U.S. scope, and non-zero eligible output must all reconcile.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected Oracle finder-variable delimiters**
- **Found during:** Task 2
- **Issue:** The research example separated every Oracle finder variable with semicolons; the official endpoint interpreted the suffix as part of `SiteNumber`, bypassing the intended pagination and facet arguments.
- **Fix:** Kept the required semicolon after `findReqs` and used comma-delimited finder variables, then asserted the exact request and response metadata in deterministic tests.
- **Files modified:** `supabase/functions/_shared/adapters/oracle-recruiting.ts`, `web/tests/branded-adapters.test.ts`
- **Commit:** `38352d5`

**2. [Rule 1 - Bug] Corrected Goldman role-detail operation**
- **Found during:** Task 3
- **Issue:** The frozen identity named `GetRoleActionContent`, which the official Higher bundle uses for Contentful UI copy rather than role details.
- **Fix:** Pinned the identity and adapter document to the official anonymous `GetRoleById` contract and verified its exact variables and detail fields.
- **Files modified:** `supabase/functions/_shared/branded-identities.ts`, `web/tests/branded-identities.test.ts`, `supabase/functions/_shared/adapters/goldman-higher.ts`
- **Commits:** `7dfaf54`, `6747c4a`

**3. [Rule 1 - Bug] Aligned Goldman positive fixture list and detail categories**
- **Found during:** Task 3 GREEN verification
- **Issue:** The second synthetic list row advertised Technology while the fixture helper silently returned a Credit Risk detail, making the intended matching-category success case internally inconsistent.
- **Fix:** Derived the synthetic detail category fields from the corresponding list row; production reconciliation remained strict.

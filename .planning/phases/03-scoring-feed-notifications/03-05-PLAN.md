## Codex Review Disposition (03-REVIEWS)

- **F1 migration numbering — INCORPORATED.** Fixed name `0020_notifications.sql`; no OFFSET math.
- **F3 (enqueue/delivery non-atomic) — INCORPORATED.** Added `claim_notifications` SKIP LOCKED RPC; notify-tick claims queued rows (status 'claimed', claimed_at) before any external send, so concurrent ticks cannot double-SEND. Quiet-window releases the claim back to 'queued'.
- **F4 (transient failures permanently suppress retries; digest date advanced on failure) — INCORPORATED.** `status='failed'` is now terminal-only (410/404 'gone' or attempts>=5); transient push/Resend failures keep the row retryable with `retry_at`. `last_digest_date` advances only on a confirmed 2xx (or a deliberate empty digest), never on a failed send.
- **HTML injection in emails (Codex MEDIUM) — INCORPORATED.** Digest/fallback email construction HTML-escapes all third-party job titles, company names, and URLs before interpolation.
- **F6 dry-run transport (support for Plan 07's non-spamming verifier) — INCORPORATED.** notify-tick honors `x-notify-dry-run`/`NOTIFY_DRY_RUN` to run the full bookkeeping path with no real push/email send.
- **Full event/batch/attempt table redesign (Codex suggestion) — DEFERRED.** The three-table model (`notification_events`/`notification_batches`/`delivery_attempts`) is sound but heavyweight for 2 users; the added `claimed_at`/`attempts`/`retry_at` columns plus the claim RPC deliver the atomicity and retry-safety the finding requires without a schema overhaul. Revisit if delivery auditing needs per-attempt granularity.
- **Crash-after-external-send replay (Codex HIGH) — PARTIALLY MITIGATED / accepted.** The Resend Idempotency-Key prevents duplicate digest emails across a crash; push has no provider idempotency, so a crash between a successful push and the status write can, rarely, re-push once on the next tick. At 2 users with burst-collapse this is a tolerable single-duplicate worst case; documented as accepted.
- **Invalid-timezone throw starving notifications (Codex MEDIUM) — DEFERRED to Plan 06 input validation.** `quietHoursState`/`Intl` reject invalid zones; Plan 06 sets timezone from `Intl.DateTimeFormat().resolvedOptions().timeZone` (always valid) so arbitrary text cannot land. Wrap the per-user loop body so one user's bad zone cannot abort the tick (Promise.allSettled already isolates per-user failures).

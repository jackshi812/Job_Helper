    - `push` listener: `event.data?.json()` with fallback `{ title: 'New job matches', url: '/' }`; `showNotification(data.title, { body: data.body, data: { url: data.url }, tag: data.tag })` inside `event.waitUntil` (tag collapses repeats).

    Create `web/src/lib/push.ts` in the resumes.ts structure (auth guard first, then browser op, then table write):
    - `urlBase64ToUint8Array(base64: string): Uint8Array` helper (standard VAPID key conversion).
    - `export type PushStatus = 'enabled' | 'disabled' | 'unsupported' | 'dead-subscription'`
    - `export async function getPushStatus(): Promise<PushStatus>` — 'unsupported' when `!('serviceWorker' in navigator) || !('PushManager' in window)`; else compare `registration.pushManager.getSubscription()` endpoint against the user's stored push_subscriptions rows: subscription exists both places → 'enabled'; browser has none but DB has a row for this device pattern, or Notification.permission === 'denied' with a stored row → 'dead-subscription' (Pitfall 3 re-subscribe check); otherwise 'disabled'.
    - `export async function enablePushOnThisDevice(): Promise<void>` — MUST be called from a click handler: register '/sw.js', `Notification.requestPermission()` (throw bounded reasons 'permission denied' when denied), `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: urlBase64ToUint8Array(import.meta.env.VITE_VAPID_PUBLIC_KEY) })` (throw 'browser unsupported' when APIs missing, 'subscription failed' on subscribe rejection), then `supabase.from('push_subscriptions').upsert({ endpoint, subscription: sub.toJSON(), user_agent: navigator.userAgent }, { onConflict: 'endpoint' })`. If `VITE_VAPID_PUBLIC_KEY` is undefined, throw 'subscription failed' with a console.error of the bounded code 'vapid_key_missing' (key ships in Plan 07).
    - `export async function disablePushOnThisDevice(): Promise<void>` — unsubscribe the browser subscription and delete the matching endpoint row.

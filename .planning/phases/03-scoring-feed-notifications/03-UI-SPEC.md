# Phase 3 — UI Design Contract

**Sources:** Phase 1 CONTEXT D-13/D-14/D-15 (app name, system theme, dense-minimal style), Phase 3 CONTEXT D-14..D-21 (feed/detail/notification decisions), 03-RESEARCH.md (stack, structure), and the live codebase (`web/src/index.css`, `Shell.tsx`, `Watchlist.tsx` — the established Tailwind 4 zinc system Phase 3 MUST extend, not replace).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/dot gaps (`gap-1`), chip inner gaps |
| sm | 8px | Compact element spacing (`gap-2`), chip padding |
| md | 16px | Default element spacing, table cell x-padding (`px-4`) |
| lg | 24px | Section padding, `sm:px-6` page gutters |
| xl | 32px | Layout gaps between page sections (`mt-8`), page y-padding (`py-8`) |
| 2xl | 48px | Major section breaks (rare; single-column pages) |
| 3xl | 64px | Not used this phase |

Exceptions (existing dense-table conventions — keep them):

- Table row y-padding: `py-2.5` (10px) for dense rows, `py-3` (12px) for standard rows — matches Watchlist.
- Control heights: `min-h-9` (36px) buttons/inputs; `[@media(pointer:coarse)]:min-h-11` (44px) for touch targets — copy the existing button classes verbatim.
- Micro-gaps: `gap-1.5` (6px) inside label/input stacks and badges (existing pattern).

## Typography

Exactly 4 sizes, 2 weights — the set already in use. Do not introduce new sizes or weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cells | 14px (`text-sm`) | 400 | 1.5 (Tailwind default) |
| Label / meta / badges / secondary cell text | 12px (`text-xs`) | 400 (600 for badges + column headers) | 1.4 (`leading-[1.4]`) |
| Heading (card/section, e.g. job title in detail) | 16px (`text-base`) | 600 | 1.5 |
| Display (page `h1`) | 20px (`text-xl`) | 600 (`tracking-tight`) | 1.2 (`leading-tight` acceptable; existing pages use default — match `text-xl font-semibold tracking-tight`) |

- Column headers: `text-xs font-semibold tracking-wide uppercase` (existing Watchlist header row style).
- Score numeral in feed: `text-sm font-semibold` — same size as body, weight carries emphasis. No oversized score displays.
- JD snapshot prose (job detail): `text-sm` with default line-height inside the sanitized container; never restyle JD-supplied headings above 16px.

## Color

Zinc-neutral system with monochrome accent (Phase 1 D-15: "neutral palette, function over flair").

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#f8fafc` (`bg-slate-50`) / Dark `#09090b` (`bg-zinc-950`) | Page background (set by Shell — do not restate per page) |
| Secondary (30%) | Light `white` + `border-zinc-200` / Dark `bg-zinc-900` + `border-zinc-800` | Cards, table containers, header, panels; secondary text `text-zinc-600` / `dark:text-zinc-400` |
| Accent (10%) | Light `zinc-900` / Dark `zinc-100` (monochrome inversion) | See reserved list below |
| Destructive | Light `red-700` (borders `red-300`, hover `red-50`) / Dark `red-400` (borders `red-900`, hover `red-950`) | Error text and destructive buttons only |

Accent reserved for (explicit list — nothing else):

1. Primary action buttons (`bg-zinc-900 text-white` / `dark:bg-zinc-100 dark:text-zinc-900`): "Save preferences", "Enable push on this device".
2. Underlined text links (`text-zinc-900 underline decoration-1 underline-offset-4` / `dark:text-zinc-100`): "Apply ↗", job-title link to detail.
3. Focus rings: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-zinc-900 dark:focus-visible:outline-zinc-100` on every interactive element.

Semantic badge colors (fixed meanings — established by Watchlist; do NOT repurpose):

| Signal | Classes (badge pattern from `Watchlist.tsx` `StatusBadge`) | Phase 3 use |
|--------|------------------------------------------------------------|-------------|
| Positive | `border-emerald-200 bg-emerald-50 text-emerald-700` / `dark:border-emerald-900 dark:bg-emerald-950 dark:text-emerald-400` | **Strong** tier badge (score ≥75); "covered" keywords in gap panel |
| Neutral | `border-zinc-200 bg-zinc-50 text-zinc-600` (new neutral badge variant, dark: `border-zinc-800 bg-zinc-950 text-zinc-400`) | **Good** tier badge (50–74); resume-recommendation chip; gap-panel category chips |
| Warning | amber set (existing) | Reserved for degraded/experimental source states — NOT for Weak tier (Weak is not a warning) |
| Informational | `border-blue-200 bg-blue-50 text-blue-700` / `dark:border-blue-900 dark:bg-blue-950 dark:text-blue-300` | **New** badge on unseen feed rows only |
| Error | red set (existing) | Error banners, failed-push notices, destructive buttons |

- **Weak** tier (<50): no badge fill — plain `text-zinc-500` label. Weak rows only appear behind the all-jobs toggle.
- Filtered-out rows (all-jobs toggle): entire row `text-zinc-500` with the filter reason as `text-xs` secondary text; no color coding.

## Copywriting Contract

Tone: terse, factual, lowercase-sentence-case; no exclamation marks, no marketing voice (daily-use tool for 2 users).

| Element | Copy |
|---------|------|
| Primary CTA (feed row) | `Apply ↗` — underlined link opening the employer apply page (`absolute_url`) in a new tab |
| Primary CTA (preferences) | `Save preferences` |
| Primary CTA (push enable, Settings ▸ Notifications) | `Enable push on this device` |
| Feed empty state heading | `No matches yet` |
| Feed empty state body | `New postings are scored against your resumes and preferences within minutes of discovery. Set your preferences to start matching.` — with an underlined link to Preferences when no preferences row exists |
| Preferences empty state | Form shown directly (no empty state) with helper text: `Matching starts once you save at least one target title.` |
| Job detail gap panel empty | `No gaps found against your {resume name} resume.` |
| Error state (feed load) | `Couldn't load your matches. Check your connection and retry.` + `Retry` button |
| Error state (preferences save) | `Couldn't save preferences. Your changes are still in the form — retry.` |
| Error state (push subscribe) | `Push couldn't be enabled ({reason}). Email digests still work.` — reasons: `permission denied`, `browser unsupported`, `subscription failed` |
| Push disabled notice (dead subscription detected) | `Push is disabled on this device. Strong matches fall back to email.` |
| New badge | `New` |
| Tier labels | `Strong` / `Good` / `Weak` (exact casing, D-07) |
| Resume recommendation chip | `Best fit: {resume name}` — runner-up on near-tie: `also fits {name}` as `text-xs` secondary |
| Filtered reason labels (all-jobs toggle, D-04) | `excluded keyword: {kw}` / `location mismatch` / `title mismatch` |
| Stale score marker (D-10) | `scored {relative time}` as `text-xs text-zinc-500` |
| Dismiss action | `Dismiss` — no confirmation (recoverable via the dismissed filter, D-16); undo affordance: dismissed rows reappear under `Show dismissed` filter |
| Destructive confirmation | None — this phase has no destructive actions. Dismiss is recoverable; preference chip removal is instantly re-addable. Do not add confirm dialogs. |
| Push notification (single Strong) | Title: `Strong match: {job title}` — Body: `{company} · score {score}` — click opens `/jobs/{id}` |
| Push notification (burst-collapsed, D-18) | Title: `{n} strong matches` — Body: top job title + `and {n-1} more` — click opens the feed |
| Digest email subject (D-20) | `{n} new job matches` |

## Interaction & State Contract

- **Loading:** table containers show a single `p-4 text-sm text-zinc-600` "Loading…" row (existing Watchlist pattern). No skeletons, no spinners.
- **New badge lifecycle (D-16):** row marked seen (badge removed) when the job detail is opened or the row is dismissed — not on mere feed render.
- **Dismiss (D-16):** immediate optimistic removal from the default view; no dialog; recoverable via `Show dismissed`.
- **Preference save (D-04):** on save, show inline confirmation `Preferences saved — recent jobs re-filtering.` (`text-sm text-zinc-600`); no toast system exists — do not add one.
- **All external links** (`Apply ↗`, careers links): `target="_blank" rel="noreferrer"`, underlined-link style with `↗`.
- **Focus/keyboard:** every interactive element carries the standard focus-visible outline classes; chip remove buttons and Dismiss are real `<button>`s; sortable score header is a `<button>` inside `<th>` with `aria-sort`.
- **Notification click-through:** single-match push → `/jobs/{id}`; collapsed push → `/` (feed). Service worker focuses an existing tab before opening a new one.

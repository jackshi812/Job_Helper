## Trust Boundaries

| Boundary | Description |
|---|---|
| preference form -> Supabase | authenticated user input triggers a scoped server revision signal |
| Supabase rows -> React Query cache | stale server rows can outlive a preference mutation in browser memory |
| feed row -> dashboard | embedded job/pipeline state controls whether a row is represented as a current match |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-3-24 | Tampering | stale focused cache | high | mitigate | Cancel and remove feed cache only after the server signal succeeds, then refetch current data. |
| T-3-25 | Repudiation | false save success | medium | mitigate | Mutation success occurs only after upsert and RPC resolve; failures preserve state and show retry copy. |
| T-3-26 | Information Disclosure | feed list overfetch | medium | mitigate | List projection remains bounded and excludes JD bodies; detail projection remains separate. |
| T-3-27 | Elevation | cross-user feed | high | mitigate | Existing RLS-scoped user_jobs query is unchanged and no client pipeline write is added. |
| T-3-34 | Spoofing | company display fallback | high | mitigate | Render only normalized joined or source-provided names; identity-less rows are withheld and never assigned an invented label. |
</threat_model>

<objective>
Scoring pipeline vertical slice: a per-minute `score-tick` worker scans for (job, user) pairs lacking state, claims them with a SKIP LOCKED RPC, runs cheap filters (SCOR-01), routes to the best-fit resume by keyword overlap (D-06), and makes exactly one Gemini 2.5 Flash structured call per survivor producing score, tier, reasons, keyword gaps, and covered list (SCOR-02, SCOR-03, D-07, D-08, D-09; gap data feeds SCOR-05 in Plan 04). Filtered jobs keep rows with reasons (D-04); preference/resume edits flag recent jobs for refilter with rescore only on real change (D-10, Pitfall 6). Fully decoupled from 02.1-owned ingestion files.

Purpose: this is the heart of the phase — everything downstream (feed, detail, notifications) reads what this slice persists.
Output: migration 0019 (user_jobs + RPCs + cron), `_shared/routing.ts` + tests, `score-tick` edge function, refilter hooks in preferences.ts and resumes.ts.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JD text → Gemini prompt | untrusted third-party ATS content inside an LLM prompt |
| cron → score-tick | forged invocation |
| user → user_jobs | users may write only seen/dismiss columns |
| resume text → Gemini | PII to external provider |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-09 | Tampering | prompt injection via JD text | high | mitigate | Delimited data blocks + data-not-instructions line, responseSchema, server-side clamp + tierFor re-derivation, reasons rendered as plain text downstream (Pitfall 5) |
| T-3-10 | Spoofing | score-tick invocation | high | mitigate | x-cron-secret gate, verify_jwt off, secret Vault↔edge only |
| T-3-11 | Elevation | user altering own scores | high | mitigate | column-level grant update (seen_at, dismissed_at) only; RLS update policy own-row |
| T-3-12 | Information disclosure | resume/JD text in logs | high | mitigate | bounded diagnosticCode-style errors; explicit no-content-logging acceptance criteria |
| T-3-13 | DoS (budget) | scoring retry storm / cost creep | medium | mitigate | attempts < 5 in claim, AI_DAILY_SCORE_CAP guard, refilter-without-rescore economy (Pitfall 6) |
| T-3-14 | Information disclosure | resume PII → Gemini free tier | critical | mitigate | Single paid-tier GEMINI_API_KEY (provisioned under billing in Plan 02 checkpoint); no alternate endpoint/key path in code |
</threat_model>

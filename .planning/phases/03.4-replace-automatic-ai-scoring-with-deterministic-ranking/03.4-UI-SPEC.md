# Phase 03.4 — UI Design Contract

> Visual and interaction contract for replacing automatic AI scoring with deterministic ranking. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing manual Tailwind CSS design language; no shadcn initialization |
| Preset | Not applicable |
| Component library | None; use native semantic HTML and existing React patterns |
| Icon library | None; retain the existing restrained Unicode arrows and chevrons where already used |
| Font | Inter with the existing `ui-sans-serif`, system fallback stack |

Phase 03.4 extends the approved Phase 03.2/03.3 interface. It must not introduce a new visual language, dependency, component library, registry, Dashboard layout, feed mode, or filter control. Retain the current zinc surfaces, light/dark color scheme, rounded borders, dense resizable table, underlined links, explicit focus outlines, and native semantic controls.

The only new visual surfaces are the deterministic-rubric fields in Preferences, a page-level ranking-update notice on Dashboard, and the deterministic points/evidence table on job detail.

---

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight inline gaps and validation-message offsets |
| sm | 8px | Label/input gaps, compact status content, table-row subcontent |
| md | 16px | Form fields, banner padding, narrow-screen gutters |
| lg | 24px | Card padding, form groups, section separation |
| xl | 32px | Major Preferences and detail sections |
| 2xl | 48px | Reserved major page break |
| 3xl | 64px | Reserved page-level separation |

Exceptions: interactive controls are at least 36px high and at least 44px on coarse pointers. Rubric number inputs are 96px wide on desktop and remain at least 44px high on coarse pointers. Existing 1px borders, Dashboard column widths, and resize-handle geometry remain unchanged.

## Typography

Use exactly the inherited four sizes and two weights for all new Phase 03.4 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Helper / table header | 12px | 600 | 1.5 |
| Body / controls / table cells | 14px | 400 | 1.5 |
| Section heading | 16px | 600 | 1.3 |
| Page heading | 20px | 600 | 1.2 |

Rubric labels and evidence use sentence case. Uppercase tracking remains limited to table headers. Point totals use tabular numerals where available. Do not use display-size numerals, progress rings, charts, stars, or decorative score gauges.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#f8fafc`; dark `#09090b` | Page background and surrounding space |
| Secondary (30%) | Light `#ffffff` / `#fafafa`; dark `#18181b` / `#09090b` | Preference form, rubric card, status notice, detail table, Dashboard table |
| Accent (10%) | Blue `#2563eb`; dark `#60a5fa` | Existing input focus border/ring and New badge only |
| Destructive | Red `#b91c1c`; dark `#f87171` | Validation, save, load, and recalculation failure text only |

Accent is reserved for input focus and the existing New badge. Primary actions and active Dashboard filters retain the zinc-inverse treatment. Strong retains the existing emerald badge, Good retains the existing neutral badge, and Weak retains the existing plain text treatment. The updating notice uses the existing amber border/background/text family.

Color never carries validity, update state, error state, score, or tier alone. Every state also has visible copy and the appropriate native or ARIA semantics.

## Scope Guardrails

- Preserve the current Dashboard page order, full-width shell, columns, column widths, persistent resizing, newest-first default, Score sorting, company controls, score-tier dropdown, result count, Location, Best fit, Posted, Apply, Dismiss/Restore, detail routing, and responsive horizontal scrolling.
- Preserve the existing preference chip controls and unrelated preference semantics. Locations become a ranking signal but retain the current chip input.
- Do not restore the removed Dashboard Match reason column.
- Do not add a watchlist-only Dashboard filter, new feed mode, score visualization, manual AI-score action, or resume-tailoring control.
- Never display historical AI score, reason, covered-keyword, or gap data. Pending deterministic work must not appear as `Unranked`, as a synthetic `Weak`, or as a partially updated row.
- The browser displays the stored deterministic score and stored deterministic tier. It does not derive tier boundaries from the score.

## Page Anatomy

### Preferences

Retain the centered `max-w-2xl` Preferences page, heading, description, loading state, vertical rhythm, save feedback, and `Save preferences` CTA.

Form order:

1. Target titles.
2. Exclude title keywords.
3. Locations.
4. Maximum required experience (years).
5. Include keywords.
6. Exclude keywords.
7. Ranking rubric card.
8. Score thresholds within the rubric card.
9. Form-level validation or save feedback.
10. `Save preferences`.

The rubric is one bordered section after the existing preference inputs. It explains the calculation in place; it is not hidden in a modal, disclosure, or separate route. The section heading is `Ranking rubric`, followed by the helper `Choose how many points each match signal earns. Category maximums must total 100.`

### Dashboard

Retain the Phase 03.3 order:

1. Page heading and deterministic description.
2. `Show dismissed`.
3. Existing Companies and Score tiers controls.
4. Existing filter surface when open.
5. Ranking-update notice when a recalculation is building or failed.
6. Polite result-count status.
7. Existing full-width resizable results table or existing loading/error/empty region.

The update notice sits above the result count and table, spans the available Dashboard width, and never replaces or overlays the previous complete result set.

### Job detail

Retain the back link, job title/company/location/posted header, stored Score and tier, Apply action, and Job description card.

Order:

1. `← Back to matches`.
2. Existing job header with deterministic score/tier and ranked timestamp.
3. New `Ranking breakdown` card.
4. Existing `Job description` card.

Remove the entire `Gaps vs your … resume` card and `Match reasons` card. Do not leave empty placeholders, advisory resume-gap copy, covered-keyword chips, or historical AI content.

## Component Inventory

| Component | Contract |
|-----------|----------|
| Maximum-experience input | Native number input labeled `Maximum required experience (years)`, integer step 1, minimum 0, maximum 20. Blank is valid and awards no experience points; it never filters a job. |
| Ranking rubric card | Existing white/zinc bordered-card treatment, 24px padding, heading/helper, six category groups, total summary, and threshold group. No collapse interaction. |
| Point input | Native number input with visible `{signal} points` label, integer step 1, minimum 0, maximum 100, 96px desktop width, and inline error association. |
| Title category | Two editable point inputs: `Strict title match` and `Weak title match`. The strict value is the title-category maximum; weak is an alternate award and must not exceed strict. |
| Single-value categories | One editable input each for `Preferred location`, `Posted within 24 hours`, `Watchlist source`, and `Required experience below maximum`. |
| Description-keyword category | Five editable inputs labeled `1 match`, `2 matches`, `3 matches`, `4 matches`, and `5+ matches`. The 5+ value is the category maximum. |
| Rubric total | Persistent footer text `Category maximums: N / 100 points`. Use neutral text at 100 and red text plus an inline error otherwise. |
| Threshold inputs | Two editable point inputs labeled `Good starts at` and `Strong starts at`, followed by the live explanatory line `Weak: 0–G−1 · Good: G–S−1 · Strong: S–100` when valid. |
| Dashboard updating notice | Amber bordered status region with heading `Updating rankings…` and one-sentence assurance that the current results remain visible. No per-row Updating badges. |
| Dashboard failure notice | Red-text alert inside a neutral bordered surface, previous result table still rendered, and one `Retry update` action only while the failed revision remains retryable. |
| Retry action | Neutral outlined button. Pending label `Retrying…`; disabled while the retry request or deterministic run is active. The server-provided retryability state is authoritative. |
| Detail breakdown table | Native table with columns `Category`, `Points`, and `Evidence`, six fixed rows, then a total row. Horizontally scrollable on narrow screens. |
| Stored tier badge | Reuse the existing Strong/Good/Weak visual treatments. The label comes from stored deterministic tier rather than browser threshold calculation. |

### Rubric defaults

| Category / signal | Default points | Maximum used in 100-point total |
|-------------------|---------------:|--------------------------------:|
| Strict title match | 30 | 30 |
| Weak title match | 20 | — alternate title award |
| Preferred location | 10 | 10 |
| Posted within 24 hours | 10 | 10 |
| Watchlist source | 10 | 10 |
| Required experience below maximum | 20 | 20 |
| 1 description-keyword match | 3 | — intermediate step |
| 2 description-keyword matches | 5 | — intermediate step |
| 3 description-keyword matches | 10 | — intermediate step |
| 4 description-keyword matches | 15 | — intermediate step |
| 5+ description-keyword matches | 20 | 20 |

Default thresholds are `Good starts at 50` and `Strong starts at 75`.

### Detail breakdown rows

Use this fixed order and these labels:

1. `Title match`
2. `Preferred location`
3. `Posted within 24 hours`
4. `Watchlist source`
5. `Required experience`
6. `Description keywords`

The Points cell uses `earned / possible`, such as `20 / 30`, with an accessible label such as `20 of 30 points`. The total row uses `Total`, `{score} / 100`, and the stored tier label.

Evidence is stored evaluator output rendered as plain text, never as HTML. It names the exact grounded input when points are earned:

- matched configured title and whether the match was strict or weak;
- matched location keyword;
- posting timestamp within the 24-hour window;
- truthful watchlist company/source;
- parsed required years and configured maximum;
- matched description keywords and the unique match count.

When a category earns zero, show a bounded factual explanation such as `No preferred location keyword matched`, `Not posted within 24 hours`, or `No explicit required minimum found`. Use `—` only if no safe evidence or explanation was stored; never invent evidence in React.

## Interaction Contract

### Editing and saving the rubric

1. Hydrate every rubric value, both thresholds, and maximum experience from the authenticated persisted preference record. A missing rubric receives the declared defaults. A missing maximum experience remains blank; do not invent a numeric default.
2. Point and threshold edits remain local until `Save preferences` is pressed. Do not recalculate Dashboard rows in the browser.
3. On blur and submit, normalize only a syntactically valid whole-number string. Empty rubric or threshold fields are invalid; blank maximum experience remains valid.
4. Validate the complete form before mutation:
   - every rubric and threshold value is an integer from 0 through 100;
   - weak-title points do not exceed strict-title points;
   - strict title + preferred location + recency + watchlist + experience + 5+ keyword points equals exactly 100;
   - keyword steps are nondecreasing and no step exceeds the 5+ category maximum;
   - `0 < Good < Strong <= 100`;
   - maximum experience is blank or a whole number from 0 through 20.
5. Show one inline message beside the first invalid group and a form-level `Fix the highlighted ranking settings before saving.` alert. Focus the first invalid input after submit.
6. Browser validation is friendly preflight only. If authoritative save validation fails, retain every current form edit and show `Couldn’t save these ranking settings. Check the highlighted values and retry.`
7. While saving, disable all preference controls and chip-removal buttons and change the CTA to `Saving…`.
8. A successful save atomically persists preferences and starts deterministic recalculation. Do not remove or blank the cached feed. Show `Preferences saved. Updating rankings…` on Preferences and keep the submitted values visible.

### Validation messages

Use these exact bounded messages:

| Rule | Copy |
|------|------|
| Point value missing/out of range/non-integer | `Enter a whole number from 0 to 100.` |
| Weak exceeds strict | `Weak title points cannot exceed strict title points.` |
| Category maximum total | `Category maximums must total 100 points. Current total: N.` |
| Keyword step order | `Keyword points must stay the same or increase as matches increase.` |
| Keyword step above maximum | `Keyword steps cannot exceed the 5+ match maximum.` |
| Invalid thresholds | `Use whole-number thresholds where 0 < Good < Strong ≤ 100.` |
| Invalid maximum experience | `Enter a whole number from 0 to 20, or leave blank.` |

### Atomic Dashboard recalculation

1. Dashboard queries ranking-run state independently from the active feed and polls while a run is building.
2. While building, render the previous complete feed unchanged and show the amber notice:
   - heading `Updating rankings…`
   - body `Your current results stay visible until the full update is ready.`
3. The notice is a page-level `role="status"` with polite live behavior. Do not repeat Updating in Score cells and do not disable company filters, tier filters, sorting, detail links, Apply, Dismiss/Restore, or resizing.
4. After the complete snapshot is atomically published, refetch one feed projection, clear the notice, and announce `Rankings updated.` through the existing polite status region. There is no mixed-row transition animation.
5. If recalculation fails, leave the previous feed and all current Dashboard controls intact. Replace the updating notice with:
   - alert `Rankings couldn’t update. Your previous results are still shown.`
   - server-safe bounded detail when available;
   - outlined `Retry update` when the server says this revision is retryable.
6. Accept at most one user-initiated retry for a failed captured revision. Disable the button immediately and label it `Retrying…`. Duplicate clicks and concurrent retry requests must not create additional runs.
7. If that revision is no longer retryable, omit the button and show `Retry limit reached. Save preferences again to start a new update.` The client must not reset or guess the server retry count.
8. A general feed-query failure retains the existing `Couldn’t load your matches. Check your connection and retry.` region and its feed `Retry`; it is separate from recalculation failure.

### Score and tier presentation

- Dashboard keeps the `Score` column label, stored integer score, Strong/Good/Weak labels, newest-first default, and explicit score sort.
- Job detail keeps the score and tier beside the job metadata. Change `scored {relative time}` to `ranked {relative time}`.
- Tier dropdown behavior and copy remain exactly Phase 03.3. Its checkboxes filter by the stored tier label.
- A new job has no temporary row until hard filtering and deterministic ranking finish. Null or pending deterministic values do not map to Weak and do not render.
- Historical AI scores, reasons, gaps, covered terms, scored timestamps, or freshness fields never appear in list or detail queries.

### Detail breakdown

- The entire breakdown is visible by default; do not collapse rows or hide evidence behind tooltips.
- Long evidence wraps naturally. Keyword evidence may wrap as comma-separated plain text; do not add a new chip color system.
- Preserve truthful missing-location `—`, safe HTTPS Apply behavior, New/seen lifecycle, Back navigation, and sanitized Job description rendering.
- Opening a job continues to mark it seen. The breakdown has no edit, retry, AI-score, tailoring, or destructive control.

## State Matrix

| State | Visual and copy contract |
|-------|--------------------------|
| Preferences loading | Preserve existing `Loading…`; do not flash rubric defaults before hydration. |
| Default rubric | Declared 100-point defaults, Good 50, Strong 75, blank maximum experience unless already stored. |
| Valid custom rubric | Neutral `Category maximums: 100 / 100 points`; derived tier-range helper updates from local threshold values. |
| Invalid rubric total | Red `Category maximums must total 100 points. Current total: N.`; save blocked. |
| Invalid keyword ladder | Affected group marked invalid with exact keyword-order or maximum message; save blocked. |
| Invalid thresholds | Both threshold controls remain editable; exact threshold message; save blocked. |
| Preference save pending | All form controls disabled; CTA `Saving…`. |
| Preference save accepted | `Preferences saved. Updating rankings…`; previous Dashboard cache remains intact. |
| Recalculation building | Amber page-level `Updating rankings…`; prior complete rows and all existing controls remain usable. |
| Recalculation failed, retryable | Prior rows remain; failure alert plus enabled `Retry update`. |
| Retry request pending | Prior rows remain; disabled `Retrying…`. |
| Recalculation failed, exhausted | Prior rows remain; no retry button; save-again guidance. |
| Recalculation complete | One complete new projection renders; notice clears; polite `Rankings updated.` announcement. |
| New job ranking pending | No Dashboard row; no Unranked or synthetic Weak state. |
| Detail breakdown complete | Six category rows, total out of 100, stored tier, bounded plain-text evidence. |
| Category earned zero | `0 / possible` plus factual zero-point explanation or `—` if none was safely stored. |
| Detail load failure | Preserve `Couldn’t load this job. Check your connection and retry.` and `Back to matches`. |
| Feed loading/error/empty/filter-empty | Preserve Phase 03.3 structure; update only AI-era explanatory copy to deterministic ranking language. |

## Accessibility Contract

- Group title, keyword, single-value, and threshold controls with semantic `fieldset` and `legend` elements. Every number input has a unique visible label and `aria-describedby` connection to helper/error text.
- Mark invalid controls with `aria-invalid="true"`. Form-level errors use `role="alert"`; successful save and update progress use polite status semantics.
- Do not announce every keystroke in the rubric total. Update the visible total immediately, but announce validation only on blur or submit.
- The Dashboard update status never moves focus. Recalculation completion also preserves the user's current filter, sort, scroll, and focus state.
- Retry is keyboard operable, has a visible focus outline, and exposes native disabled state while pending.
- The detail table uses a caption or accessible name `Deterministic ranking breakdown`, scoped column headers, scoped row headers, and a semantically distinct total row.
- Evidence cannot rely on color, abbreviation, or tooltip-only content. `earned / possible` has a full accessible label.
- Preserve all Phase 03.3 company/tier trigger semantics, checkbox targets, polite result count, column resize separators, table-region label, horizontal keyboard access, `aria-sort`, link names, and Dismiss/Restore labels.

## Responsive Contract

- Preferences keeps its centered width. Rubric category rows use one label-and-input row above 640px and stack the input below its label on smaller screens.
- The five keyword-step inputs form a wrapping grid: five columns when space allows, two columns on narrow screens, and one column only when required to avoid overflow.
- Rubric and threshold controls never cause horizontal page overflow. Numeric values remain visible without truncation.
- Dashboard notices use the existing 16px gutters below 640px and 24px gutters from 640px upward; notice actions wrap below copy on narrow screens.
- The detail breakdown owns an `overflow-x-auto` region below 640px with a minimum table width of 640px. Do not hide categories, Points, or Evidence.
- Preserve all Dashboard columns and existing horizontal-scroll behavior below 768px; no responsive column hiding or reordering is introduced.

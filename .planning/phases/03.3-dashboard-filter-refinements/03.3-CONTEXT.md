# Phase 03.3: Dashboard Filter Refinements - Context

**Gathered:** 2026-07-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Refine the shipped Phase 03.2 Dashboard and preference controls without changing ingestion, scoring tiers, company identity, or persistence boundaries. Replace the required-experience preference with a dedicated persisted job-title exclusion list, replace company Reset with staged Clear all and Select all actions, and group Strong/Good/Weak into one accessible multi-select dropdown.

</domain>

<decisions>
## Implementation Decisions

### Job-title exclusions
- **D-01:** Remove maximum required experience from active Preferences and scoring/filter behavior. Replace it with a distinct persisted list of job-title exclusion keywords; the existing general Exclude keywords field continues to search title and description as before.
- **D-02:** Seed `president` and `PhD` for both existing and new users. They are editable defaults, not permanent rules: users may remove either or both.
- **D-03:** Title matching is case-insensitive and uses safe whole-word or contiguous-phrase boundaries. A short keyword must not match inside an unrelated longer word.
- **D-04:** `PhD` additionally matches punctuation and spacing variants `Ph.D.` and `Ph D`. It does not automatically expand to broader concepts such as `doctorate` or `doctoral`.
- **D-05:** `president` matches as a whole word anywhere in the title, including `Vice President` and `Senior Vice President`.
- **D-06:** Saving an empty title-exclusion list is valid and means no title-based exclusions.
- **D-07:** Changes reuse the existing per-user recent-job refilter lifecycle and expose a specific bounded filter reason. The transition must stop active use of `max_required_experience` and `experience_above_max` without risking an unsafe production migration.

### Company bulk actions
- **D-08:** Keep the truthful, session-only, staged current-feed company checklist. Remove Reset and add `Clear all` plus `Select all`; each affects every currently listed company in the draft, not only search matches, and does not affect results until Show results is pressed.
- **D-09:** Clear all may intentionally produce zero visible jobs after application. Bulk actions expose truthful disabled states when the entire current list is already cleared or selected, and newly refreshed companies remain selected by default.

### Score-tier dropdown
- **D-10:** Replace the three standalone Strong/Good/Weak buttons with one compact accessible multi-select dropdown containing the same three tiers.
- **D-11:** All tiers start selected each session. Zero, one, two, or all three selected states are valid; tier selection remains session-only and continues to compose with applied company visibility using AND semantics.
- **D-12:** Preserve current score thresholds, null-to-Weak ownership, result counts, Show dismissed behavior, sorting, and table behavior. This is a control consolidation, not a new eligibility mode.

### the agent's Discretion
- Exact database transition strategy for the dormant `max_required_experience` column, provided it is absent from active UI/filter behavior and deployment remains safe.
- Exact punctuation-normalization implementation used to equate `PhD`, `Ph.D.`, and `Ph D` without broad fuzzy matching.
- Tier-dropdown trigger copy, selected-count summary, popover placement, close behavior, and whether it stays open during multi-selection, provided selection feedback and keyboard behavior are clear.
- Exact button order, empty-result copy, and visual styling for company bulk actions within the existing zinc light/dark design system.

### Folded Todos
- **Replace experience cap with title exclusions:** Folded as D-01 through D-07; replaces active experience-year filtering with removable seeded title-only exclusions.
- **Refine company visibility controls:** Folded as D-08 and D-09; replaces Reset with staged full-list Clear all and Select all.
- **Consolidate score tier controls:** Folded as D-10 through D-12; groups the existing tier selections into one accessible multi-select control.

</decisions>

## Existing Code Insights

### Reusable Assets
- `Preferences.tsx` `ChipInput`: already supplies add-on-enter/comma, removal, deduplication, disabled state, and accessible chip controls for the new title-exclusion list.
- `filters.ts` `tokenize` and `containsTokenSequence`: existing literal whole-token/contiguous-phrase machinery can support title-only exclusions after deliberate punctuation-variant handling.
- `Dashboard.tsx` company draft/applied sets: bulk operations can mutate only `draftHiddenKeys` and continue through the existing Show results boundary.
- `dashboard.ts` `ALL_SCORE_TIERS`, `toggleScoreTier`, and `filterDashboardRows`: the dropdown can reuse the same selected-tier set and pure filtering contract.

### Established Patterns
- Preference saves upsert the caller's own row, then signal recent jobs for refilter and invalidate browser caches only after success.
- Cheap filters run provider-neutrally before routing, budget reservation, hashing publication, or AI.
- Dashboard company and tier state is component-local and resets each session; only column widths use browser persistence.
- UI controls use explicit accessible labels, focus-visible rings, truthful live result counts, and light/dark zinc styling.

### Integration Points
- Next migration and preference types/projectors for the persisted title-exclusion array and safe experience-cap retirement.
- Filter outcome/schema/database reason constraints, worker preference mapping, and scoring-input hash revision.
- Preferences form hydration/save behavior and Dashboard company/tier control composition.
- Existing unit, integration, release-verifier, security, build, and signed-in UAT gates from Phase 03.2.

</code_context>

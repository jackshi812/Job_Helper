## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Job-title exclusions
- **D-01:** Remove maximum required experience from active Preferences and scoring/filter behavior. Replace it with a distinct persisted list of job-title exclusion keywords; the existing general Exclude keywords field continues to search title and description as before.
- **D-02:** Seed `president` and `PhD` for both existing and new users. They are editable defaults, not permanent rules: users may remove either or both.
- **D-03:** Title matching is case-insensitive and uses safe whole-word or contiguous-phrase boundaries. A short keyword must not match inside an unrelated longer word.
- **D-04:** `PhD` additionally matches punctuation and spacing variants `Ph.D.` and `Ph D`. It does not automatically expand to broader concepts such as `doctorate` or `doctoral`.
- **D-05:** `president` matches as a whole word anywhere in the title, including `Vice President` and `Senior Vice President`.
- **D-06:** Saving an empty title-exclusion list is valid and means no title-based exclusions.
- **D-07:** Changes reuse the existing per-user recent-job refilter lifecycle and expose a specific bounded filter reason. The transition must stop active use of `max_required_experience` and `experience_above_max` without risking an unsafe production migration.

#### Company bulk actions
- **D-08:** Keep the truthful, session-only, staged current-feed company checklist. Remove Reset and add `Clear all` plus `Select all`; each affects every currently listed company in the draft, not only search matches, and does not affect results until Show results is pressed.
- **D-09:** Clear all may intentionally produce zero visible jobs after application. Bulk actions expose truthful disabled states when the entire current list is already cleared or selected, and newly refreshed companies remain selected by default.

#### Score-tier dropdown
- **D-10:** Replace the three standalone Strong/Good/Weak buttons with one compact accessible multi-select dropdown containing the same three tiers.
- **D-11:** All tiers start selected each session. Zero, one, two, or all three selected states are valid; tier selection remains session-only and continues to compose with applied company visibility using AND semantics.
- **D-12:** Preserve current score thresholds, null-to-Weak ownership, result counts, Show dismissed behavior, sorting, and table behavior. This is a control consolidation, not a new eligibility mode.

### the agent's Discretion

- Exact punctuation-normalization implementation used to equate `PhD`, `Ph.D.`, and `Ph D` without broad fuzzy matching.
- Tier-dropdown trigger copy, selected-count summary, popover placement, close behavior, and whether it stays open during multi-selection, provided selection feedback and keyboard behavior are clear.
- Exact button order, empty-result copy, and visual styling for company bulk actions within the existing zinc light/dark design system.

The backend-critical slice is a compatible schema and scoring-contract transition: add a per-user `title_exclude_keywords` text array seeded with `president` and `PhD`, add a new bounded reason such as `excluded_title_keyword`, remove every active browser/worker/hash read of `max_required_experience`, and keep the physical legacy column and legacy database reason temporarily for rolling-deployment and historical-row compatibility. The existing `containsTokenSequence` algorithm already supplies whole-token and contiguous-phrase behavior, but the title-exclusion tokenizer should preserve parenthetical title content and perform one narrow pre-tokenization fold of bounded `PhD`, `Ph.D.`, and `Ph D` to the token `phd`. The Dashboard work is entirely browser-local. Keep hidden normalized company keys as the single company representation: `Clear all` makes the draft contain every current option key, while `Select all` makes the draft empty. Keep the existing selected-tier `Set<Tier>` and render it through one native checkbox group popover; no data-layer or persistence changes are needed. Preserve the current `filterDashboardRows` pipeline, which already implements company+tier AND semantics, all-tier initialization, and null-to-Weak ownership. [VERIFIED: `web/src/lib/dashboard.ts`, `web/src/pages/Dashboard.tsx`, `web/src/lib/feed.ts`, approved `03.3-UI-SPEC.md`]

### Pattern 1: Additive compatibility migration, active-code retirement

**Use:** Add `title_exclude_keywords text[] not null default array['president', 'PhD']::text[]` with the same `cardinality(...) <= 50` guard as the four existing arrays. A constant default supplies the seeds to existing rows and to future inserts that omit the field; an explicit empty array remains an ordinary valid stored value. [CITED: https://www.postgresql.org/docs/17/sql-altertable.html] [VERIFIED: migration `0017` array checks]

Keep `max_required_experience` physically present but dormant during this phase. Remove it from browser selects/upserts, worker selects/mapping, `FilterPreferences`, filter evaluation, and the semantic hash. Recreate `user_jobs_filter_reason_check` to admit the new `excluded_title_keyword` and retain `experience_above_max` only as a legacy stored-value/rolling-release compatibility member. New code must never emit the legacy reason. [VERIFIED: D-07; migration `0030`; code projection grep]

This avoids three deployment hazards: an older web asset can coexist briefly with the schema, an older worker cannot have its writes rejected before replacement, and historical filtered rows do not make the new constraint fail validation. Physical column/reason cleanup should be a later migration after production convergence is proved, not part of the Phase 03.3 rollout. [VERIFIED: current schema/type coupling; D-07]

### Pattern 2: Dedicated literal title tokenizer with one narrow PhD fold

**Use:** Keep `containsTokenSequence`, but feed it title-only tokens produced by a literal tokenizer that does not remove parenthetical content. Before punctuation becomes spaces, replace bounded `/\bph(?:\.?\s*)d\.?\b/gi` with `phd`; then lowercase, replace other non-alphanumerics with spaces, collapse whitespace, and split. Apply the same fold to the configured keyword. [VERIFIED: D-03 through D-05; current `normalize` removes parenthetical content and current punctuation tokenization makes `Ph.D.` become `ph d`]

Run this gate before the existing general exclude/location/title-intent gates and return `{ reason: 'excluded_title_keyword', detail: normalizedNeedle }`. Never synonym-expand, stem, fuzzy-match, or search the description for this list. [VERIFIED: D-01/D-03/D-04; `filters.ts` current gate structure]

### Anti-Patterns to Avoid

- **Dropping `max_required_experience` in the first additive migration:** a still-cached old web asset selects and upserts it, and the old worker selects it. Keep it dormant until a later cleanup release. [VERIFIED: active projections in `preferences.ts` and `score-tick/index.ts`]
- **Removing `experience_above_max` from the database check immediately:** historical rows can make constraint creation fail, and an older worker can still emit it during rollout. Retain it as legacy compatibility, not active behavior. [VERIFIED: migration `0030`, D-07]
- **Reusing general exclude keywords:** that searches title plus description and would violate the title-only boundary. [VERIFIED: `filters.ts`, D-01]
- **Using the existing title-overlap normalizer unchanged:** it strips parenthetical content and converts `Ph.D.` to two tokens. Use a separate literal title-exclusion tokenizer. [VERIFIED: `filters.ts`]
- **Defaulting with `stored.length ? stored : seeds`:** this resurrects seeds after a user deliberately saves `[]`. Distinguish row absence from an empty stored array. [VERIFIED: D-06]
- **Bulk actions over search results:** search must not change which companies Clear all/Select all affect. [VERIFIED: D-08]
- **Replacing checkboxes with a single-select menu/listbox:** zero-to-three independent selections require checkbox semantics. [VERIFIED: D-10/D-11; W3C grouping guidance]
- **Persisting Dashboard filters:** only column widths persist; company and tier state remain component-local. [VERIFIED: D-08/D-11, Phase 03.2 contract]
- **Refactoring table/resizing during control consolidation:** Phase 03.2 table behavior is a regression boundary, not part of this phase's implementation surface. [VERIFIED: D-12]

## Common Pitfalls

### Pitfall 1: Explicit empty exclusions become defaults again
**What goes wrong:** `[]` is treated as missing and the UI restores `president`/`PhD` after refresh. [VERIFIED: D-06]
**How to avoid:** Seed only when there is no preference row; hydrate an existing empty array exactly. Test save/load of `[]`. [RECOMMENDED from verified state contract]

### Pitfall 2: Existing users are not actually seeded
**What goes wrong:** A client-only initial array helps new unsaved forms but existing database rows remain empty/missing. [VERIFIED: existing users already have preference rows]
**How to avoid:** Use a constant database default on `ADD COLUMN`, which PostgreSQL exposes for existing rows, and retain browser defaults for no-row users. [CITED: https://www.postgresql.org/docs/17/sql-altertable.html]

### Pitfall 3: `Ph.D.` fails or fuzzy concepts leak in
**What goes wrong:** Generic punctuation splitting produces `ph d`, or fuzzy normalization starts matching `doctoral`. [VERIFIED: current tokenizer behavior; D-04]
**How to avoid:** Fold only bounded `ph` + optional dots/spaces + `d` before tokenization and assert negative synonym cases. [RECOMMENDED]

### Pitfall 4: Parenthetical exclusions are missed
**What goes wrong:** The current shared `normalize` deletes text in parentheses, so `Analyst (PhD)` passes. [VERIFIED: `filters.ts normalize()`]
**How to avoid:** Give title exclusions a literal tokenizer that converts punctuation to spaces without deleting content. [RECOMMENDED]

### Pitfall 5: Database rejects the new worker reason
**What goes wrong:** `score-tick` writes `excluded_title_keyword` while the `0030` constraint knows only four old reasons. [VERIFIED: migration `0030`]
**How to avoid:** Apply the additive reason migration before deploying the worker; pin the final compatible set structurally. [RECOMMENDED]

### Pitfall 6: Rolling release breaks old assets or historical rows
**What goes wrong:** Dropping the experience column or reason immediately breaks cached web queries, old worker selects/writes, or constraint validation. [VERIFIED: active projections and historical reason possibility]
**How to avoid:** Retain dormant physical compatibility while proving new source has no active usage. [RECOMMENDED]

### Pitfall 7: Semantic hash still tracks the retired cap or omits the new list
**What goes wrong:** A changed title exclusion can incorrectly reuse a stale score, or a dormant cap change still invalidates scores. [VERIFIED: current hash contains `maxRequiredExperience`]
**How to avoid:** Replace the hash field, canonicalize the array, and bump `filter-v3` to `filter-v4`; test case/order equivalence plus semantic differences. [RECOMMENDED]

### Pitfall 8: “Recent” tests encode a contract the RPC no longer has
**What goes wrong:** Comments and verifier copy say seven days, but migration `0027` marks every caller-owned open job. [VERIFIED: migration `0027`]
**How to avoid:** Test own-user/open-job/revision/reset behavior and correct stale comments; do not add a seven-day assertion. [RECOMMENDED]

### Pitfall 9: Clear all only clears search matches
**What goes wrong:** The action consumes `searchedCompanyOptions`, contradicting the full-list contract. [VERIFIED: D-08]
**How to avoid:** Pure bulk helpers consume `companyOptions`; test under a non-empty search. [RECOMMENDED]

### Pitfall 10: Disabled state lies after feed refresh
**What goes wrong:** `draftHiddenKeys.size === companyOptions.length` can be false because hidden keys include a company no longer in the current list. [VERIFIED: feed refetch and hidden-key design]
**How to avoid:** Compute all-cleared/all-selected over current option keys, not raw set cardinality. [RECOMMENDED]

### Pitfall 11: Click-outside focus bounces back to the tier trigger
**What goes wrong:** A generic close helper always restores trigger focus, stealing focus from the destination clicked. [VERIFIED: approved accessibility contract]
**How to avoid:** Restore focus on Escape and trigger-close; on outside pointer close, allow the clicked destination to keep focus. [RECOMMENDED]

### Pitfall 12: Popover refactor changes eligibility

### Narrow PhD fold and literal whole-phrase matching

```typescript
function literalTitleTokens(value: string): string[] {
  const normalized = value
    .normalize('NFKC')
    .toLowerCase()
    .replace(/\bph(?:\.?\s*)d\.?\b/g, 'phd')
    .replace(/[^a-z0-9 ]/g, ' ')
    .replace(/\s+/g, ' ')
    .trim()
  return normalized ? normalized.split(' ') : []
}

function excludedTitleKeyword(title: string, keywords: readonly string[]): string | null {
  const titleTokens = literalTitleTokens(title)
  for (const keyword of keywords) {
    const needle = literalTitleTokens(keyword)
    if (containsTokenSequence(titleTokens, needle)) return needle.join(' ')
  }
  return null
}
```

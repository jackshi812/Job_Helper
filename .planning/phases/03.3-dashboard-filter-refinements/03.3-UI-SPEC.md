# Phase 03.3 — UI Design Contract

> Visual and interaction contract for Dashboard Filter Refinements. Generated by gsd-ui-researcher and approved by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing manual Tailwind CSS design language; no shadcn initialization |
| Preset | Not applicable |
| Component library | None; use native semantic HTML and existing React patterns |
| Icon library | None; a restrained Unicode chevron may be used as a decorative dropdown cue |
| Font | Inter with the existing `ui-sans-serif`, system fallback stack |

Phase 03.3 refines the approved Phase 03.2 interface. It must not introduce a new visual language, dependency, component library, registry, persistent Dashboard-filter state, or alternate feed mode. Retain the existing zinc surfaces, light/dark color scheme, rounded borders, dense table, underlined links, explicit focus outlines, and native semantic controls.

---

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight inline gaps and dropdown offsets |
| sm | 8px | Chip gaps, checkbox-label gaps, compact control padding |
| md | 16px | Form spacing, panel padding, narrow-screen gutters |
| lg | 24px | Desktop gutters and section separation |
| xl | 32px | Dashboard heading-to-results separation |
| 2xl | 48px | Reserved major section break |
| 3xl | 64px | Reserved page-level separation |

Exceptions: interactive controls are at least 36px high and at least 44px on coarse pointers. Checkbox rows and company search remain at least 44px high. Existing 1px borders and the Phase 03.2 column-resize rule remain unchanged.

## Typography

Use exactly the inherited four sizes and two weights for new Phase 03.3 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Helper / table header | 12px | 600 | 1.5 |
| Body / controls / table cells | 14px | 400 | 1.5 |
| Section heading | 16px | 600 | 1.3 |
| Page heading | 20px | 600 | 1.2 |

Controls use sentence case. Uppercase tracking remains limited to table headers. Chips use the existing 12px semibold badge treatment. Dropdown state is communicated in visible text, not by color or chevron direction alone.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#f8fafc`; dark `#09090b` | Page background and space surrounding forms/table |
| Secondary (30%) | Light `#ffffff` / `#fafafa`; dark `#18181b` / `#09090b` | Preference form, company panel, dropdown, table, neutral controls |
| Accent (10%) | Blue `#2563eb`; dark `#60a5fa` | Existing text-input focus border/ring and New badge only |
| Destructive | Red `#b91c1c`; dark `#f87171` | Save/load error text only; no destructive action in this phase |

Accent is reserved for input focus and the existing New badge. Primary actions and active/narrowed filter triggers use the existing zinc inverse treatment. Checkbox state, selected-count copy, `aria-expanded`, and checked state provide non-color equivalents. Strong retains its existing emerald badge; updating retains amber. Phase 03.3 does not assign new colors to Good or Weak.

## Page Anatomy

### Preferences

Retain the current centered `max-w-2xl` Preferences page, heading, description, loading state, vertical form rhythm, save status, and `Save preferences` CTA. Form order is:

1. Target titles.
2. Exclude title keywords — the new chip field replacing maximum required experience.
3. Locations.
4. Include keywords.
5. Exclude keywords — the existing title-and-description field.
6. Save feedback and CTA.

There is no maximum-required-experience input, validation message, helper copy, or empty gap left in its former position.

### Dashboard

Retain the Phase 03.2 full-width Dashboard shell and this order:

1. Page heading and description.
2. Existing `Show dismissed` control.
3. One filter row containing the `Companies` trigger and one score-tier dropdown trigger.
4. The inline company panel when open; the score popover is anchored to its trigger and overlays without shifting the results table.
5. Polite result-count status.
6. The unchanged full-width resizable results table.

Controls wrap without overlap. On narrow screens the filter row may wrap and the company panel spans the available width. Only one filter surface should be open at a time: opening Companies closes Score tiers, and opening Score tiers closes Companies without applying or changing staged company state.

## Component Inventory

| Component | Contract |
|-----------|----------|
| Title-exclusion chip input | Reuse the existing `ChipInput` visual and keyboard pattern. Label `Exclude title keywords`; seed removable `president` and `PhD` chips for existing and new users. Empty is valid. |
| Company filter trigger | Keep the outlined `Companies` trigger, `aria-expanded`, and `aria-controls`. Show `Companies` when all are visible and `Companies (N selected)` when narrowed, including `Companies (0 selected)`. |
| Company panel | Preserve the inline bordered panel, heading, search field, independently scrolling full-list checklist, staged draft, Escape behavior, and sticky footer. |
| Company bulk actions | Replace Reset with secondary `Clear all` and `Select all` buttons. Both operate on the complete current company list, never only the search subset, and never apply results themselves. |
| Company primary action | Preserve zinc-inverse `Show results`; it is the only action that commits the company draft. |
| Score-tier trigger | One compact dropdown button. Visible copy is `Score tiers: All`, `Score tiers: None`, or `Score tiers: N selected` for a partial selection. Include a decorative chevron and expose expanded state programmatically. |
| Score-tier dropdown | A bordered zinc popover containing a labeled native checkbox group in fixed order Strong, Good, Weak. It is multi-select, remains open while checkboxes change, and applies each tier change immediately. |
| Result table | Preserve Phase 03.2 columns, widths, sorting, horizontal overflow, detail access to match reasons, Location, Dismiss/Restore, and persistent resizing exactly. |

### Preference chip details

- Label: `Exclude title keywords`.
- Helper: `Jobs are excluded when their title contains one of these words or phrases. PhD also matches Ph.D. and Ph D.`
- Placeholder: retain `Type and press Enter or comma`.
- Initial chips: visible exactly as `president` and `PhD`; each has an accessible `Remove {keyword}` button.
- Enter, comma, or blur commits a trimmed chip. Backspace on an empty input removes the last chip, matching existing fields.
- Duplicate entries compare case-insensitively after Unicode normalization; retain the first-entered display casing.
- Removing every chip is allowed. No warning, automatic restoration, or required-field indicator appears.
- `Exclude keywords` remains a separate field and keeps its existing `Any hit discards the posting before scoring.` helper.

### Company footer layout

Desktop order is `Clear all`, `Select all`, then flexible space, then `Show results`. On narrow screens the footer wraps while preserving that reading and tab order. `Show results` remains visually primary; the two bulk actions remain neutral outlined buttons.

- Disable `Clear all` when there are no companies or every current company is already unchecked in the draft.
- Disable `Select all` when there are no companies or every current company is already checked in the draft.
- Search never changes these rules: bulk disabled state reflects the complete current company list.
- Disabled controls remain legible, expose native `disabled`, and use reduced opacity without relying on cursor treatment alone.

### Score-tier popover geometry

- Anchor immediately below the trigger with an 8px gap, align its start edge to the trigger, place above the table with local stacking, and keep it within the viewport.
- Minimum width 220px; use the available width minus 16px gutters on narrow screens.
- Each checkbox row is at least 44px high, with an easy-to-target label and visible checked state.
- The narrowed trigger (`None` or a partial selection) uses the existing active zinc-inverse treatment; `All` uses the neutral outlined treatment.

## Interaction Contract

### Title exclusions

1. Loading Preferences hydrates the persisted title-exclusion list. Existing and new users who have never customized this field receive `president` and `PhD` as editable seeded chips.
2. Chip changes remain local form edits until `Save preferences` is pressed.
3. Saving an empty list persists an empty list and excludes no job titles; defaults must not reappear after refresh once the user has deliberately saved empty.
4. Matching is case-insensitive and title-only. `president` matches the whole word anywhere in titles such as `Vice President` and `Senior Vice President`, but not inside an unrelated longer word.
5. `PhD` matches whole-title tokens written `PhD`, `Ph.D.`, or `Ph D`; it does not match or expand to `doctorate` or `doctoral`.
6. Save pending disables every chip input and remove button and changes the CTA to `Saving…`, as today.
7. Save success retains `Preferences saved — recent jobs re-filtering.` and refreshes the feed through the existing delayed refilter lifecycle. Save failure retains the user's unsaved form edits and the existing bounded retry message.

### Company filtering

1. Dashboard mount starts with every truthful current-feed company visible; state remains session-only.
2. Opening Companies copies applied hidden keys into the draft and clears search. Search narrows only the visible checklist.
3. Individual checkboxes, `Clear all`, and `Select all` edit only the draft. The result table and `{N} jobs shown` status do not change before `Show results`.
4. `Clear all` unchecks every company in the complete current list even when search displays only a subset. `Select all` checks every company by removing all current keys from the hidden draft.
5. `Show results` commits the draft, closes the panel, clears search, returns focus to Companies, and updates the polite result count.
6. Escape closes without applying the draft, clears search, and returns focus to Companies. Reopening starts again from the applied selection.
7. A newly refreshed truthful company is selected by default because state stores only hidden existing keys; bulk operations never alter ingestion or future eligibility.
8. Applying zero visible companies is valid and shows the filter-empty state.

### Score-tier filtering

- All three tiers start selected on every Dashboard mount. Tier state is session-only.
- Activate the trigger with pointer, Enter, or Space to open. Focus moves to the first tier checkbox. Escape closes and returns focus to the trigger; activating the trigger again or clicking outside also closes.
- Checkbox activation updates selected-tier state and the result table immediately while the dropdown remains open. Do not add an Apply, Reset, Select all, or Clear all action to this three-option dropdown.
- Zero, one, two, or three selected tiers are valid. Never silently restore a tier.
- The trigger copy and active treatment update immediately for all, none, and partial states. The polite `{N} jobs shown` status announces the changed count without moving focus.
- Applied company visibility and selected tiers retain AND semantics. Show dismissed remains independent and does not reset either control.
- Tier ownership remains Strong ≥75, Good 50–74, and Weak <50, with eligible scoreless rows owned by Weak. No threshold or eligibility copy appears inside the compact dropdown unless exposed as nonessential accessible description.

### Preserved Phase 03.2 behavior

- Keep the full-width Dashboard route while header/banner and all non-Dashboard pages stay centered.
- Keep Match reason absent from the table and available on job detail.
- Keep Location truthful with `—` when absent.
- Keep score sorting and its independent keyboard target.
- Keep validated versioned local persistence for column widths only; no width reset control.
- Keep pointer and keyboard column resizing, min/max clamps, coarse-pointer hit areas, and accessible separator values.
- Keep current loading, feed-error, no-feed, dismissed, responsive horizontal-scroll, and row-action behavior.

## State Matrix

| State | Visual and copy contract |
|-------|--------------------------|
| Title exclusions at default | Two removable chips: `president`, `PhD` |
| Title exclusions empty | No chips; input stays available; save is allowed; defaults do not reappear after saved empty |
| Preference save pending | All fields disabled, CTA `Saving…` |
| Company draft all selected | `Select all` disabled; `Clear all` enabled; applied results unchanged |

| Feed loading/error/no data | Preserve the Phase 03.2 loading, retry, and `No matches yet` contracts |

## Accessibility Contract

- Every trigger exposes `aria-expanded` and `aria-controls`; the score trigger has a visible state summary in its accessible name.
- The score popover is a labeled checkbox group, not a single-select listbox or menu. Native checked and disabled semantics are authoritative.
- Company and tier checkboxes have associated full-row labels, visible focus indicators, and at least 44px coarse-pointer targets.
- Opening a dropdown establishes a predictable focus target. Escape closes without unintended selection and returns focus to its trigger.
- Click-outside closure must not steal focus from the destination the user clicked.
- The existing polite status region announces committed company changes and immediate tier changes as `{N} jobs shown`; draft company edits are not announced as result changes.
- Chip removal buttons retain specific accessible names. Keyboard-only users can add, traverse, remove, clear, save, and restore exclusions without relying on drag or pointer gestures.
- Do not use color alone for all/partial/none, checked/unchecked, error, score, or pending state.
- Preserve Phase 03.2 table-region label, horizontal keyboard access, `aria-sort`, resize separator semantics, link names, and Dismiss/Restore labels.

---

## Responsive Contract

- Preserve 16px Dashboard gutters below 640px and 24px gutters from 640px upward.
- Filter controls wrap rather than shrink below readable target sizes. The score trigger remains a single compact button.
- The score popover stays inside viewport gutters and may widen to the available content width on narrow screens.
- The company panel stays full-width when wrapped; its checklist remains independently scrollable and its sticky footer may wrap without changing action order.
- Retain all table columns and the Phase 03.2 horizontally scrollable region below 768px; no responsive hiding or content reordering is introduced.

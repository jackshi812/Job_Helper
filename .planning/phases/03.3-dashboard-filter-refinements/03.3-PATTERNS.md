**Whole-token/contiguous-phrase pattern** (`filters.ts:158-181`):

```typescript
function tokenize(value: string): string[] {
  const normalized = normalize(value)
  return normalized.length === 0 ? [] : normalized.split(' ')
}

function containsTokenSequence(haystack: string[], needle: string[]): boolean {
  if (needle.length === 0) return false
  if (needle.length === 1) return haystack.includes(needle[0])
  for (let i = 0; i + needle.length <= haystack.length; i += 1) {
    let match = true
    for (let j = 0; j < needle.length; j += 1) {
      if (haystack[i + j] !== needle[j]) {
        match = false
        break
      }
    }
    if (match) return true
  }
  return false
}
```

Reuse `containsTokenSequence`, but feed it a dedicated literal-title tokenizer. That tokenizer must preserve parenthetical content, normalize NFKC/case, narrowly fold bounded `PhD`/`Ph.D.`/`Ph D` to `phd`, then convert remaining punctuation to spaces. Do not use the current `normalize()` unchanged because it removes parentheticals. Do not interpolate user keywords into regexes, stem, expand synonyms, or inspect descriptions.

**Ordered gate seam** (`filters.ts:254-273`):

```typescript
export function cheapFilter(job: FilterJobInput, prefs: FilterPreferences): FilterOutcome {
  const titleTokens = tokenize(job.title)
  const locationTokens = tokenize(job.location ?? '')
  const descriptionTokens = tokenize(job.descriptionText)

  // existing ordered gates follow
  const excludeHaystack = [...titleTokens, ...descriptionTokens]
  for (const keyword of prefs.excludeKeywords) {
    const needle = tokenize(keyword)
    if (containsTokenSequence(excludeHaystack, needle)) {
      return { pass: false, reason: 'excluded_keyword', detail: needle.join(' ') }
    }
  }
```

Insert the title-only gate first and return `{ reason: 'excluded_title_keyword', detail: normalizedNeedle }`. Preserve general exclude -> location -> title-intent -> include-signal behavior after it.

## Shared Patterns

### Authentication and authorization

- `preferences` remains protected by existing own-row RLS (`0017_preferences.sql:26-45`); no new policy or browser service-role path is needed.
- `score-tick` remains the only service-role preference projection and keeps its cron-secret/method guards (`score-tick/index.ts:417-444`).
- Dashboard filters consume only already-authorized feed rows and never write network state.

### Error handling and release compatibility

- Thin Supabase helpers throw returned errors; pages retain unsaved local edits and existing bounded copy.
- Worker writes keep bounded filter reasons, revision CAS, and content-free diagnostic logging.
- Deploy schema compatibility before the worker, and the worker before web assets. Keep the physical cap and legacy reason until a later cleanup release proves production convergence.

### Validation and normalization

- Database caps title-exclusion arrays at 50; browser trims/deduplicates; backend independently tokenizes untrusted strings.
- Never construct a regex from a user keyword. The only regex is the fixed bounded PhD fold before ordinary token comparison.
- Explicit `[]` differs from a missing preference row. Do not implement `stored.length ? stored : defaults`.

### State and accessibility

- Company draft/applied hidden-key sets and selected tiers stay React-local and session-only; only column widths remain persisted.

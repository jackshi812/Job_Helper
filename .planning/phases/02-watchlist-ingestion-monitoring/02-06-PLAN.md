<objective>
Close verification gaps 5 and 6. Gap 5: `discovery-sweep` counts per-query failures (lines ~125-146) but always returns HTTP 200 (lines ~216-223) and persists nothing monitoring can see — every seed query can fail while the pipeline stays green. Gap 6: `0007_discovery.sql` schedules discovery at `0 * * * *` (hourly), but the corrected MVP story promises aggregator jobs inside the same 5-15 minute window as watched boards.

Budget-safe cadence (adopted, not an override of the promise during waking hours): the four seed rows contain 3 DISTINCT (what, where_loc) pairs; deduping before fetch makes each sweep cost 3 requests. Scheduling every 15 minutes during 11:00-02:59 UTC (≈ 06:00-21:59 America/Chicago, 64 sweeps) plus hourly during 03:00-10:00 UTC (8 sweeps) totals 72 sweeps × 3 = 216 requests/day — under the existing 240 hard cutoff (Adzuna free tier ~250/day, per .claude/CLAUDE.md). Full 24h 15-minute coverage would need 96 × 3 = 288/day and is infeasible on the free tier; the overnight hourly window is documented in the migration as an explicit budget carve-out for verification to record.

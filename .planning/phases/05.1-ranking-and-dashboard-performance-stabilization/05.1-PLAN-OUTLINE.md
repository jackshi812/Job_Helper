# Phase 05.1 Simplified Plan Outline

## Outcome

Ship two surgical fixes after the already deployed 0063 containment boundary:

1. Routine score ticks process only genuine inserted/ranking-relevant changed jobs in bounded batches, with one set-based staging RPC and atomic publication.
2. Dashboard Dismiss removes one card immediately, leaves unrelated cards interactive, restores exactly that card on RPC failure, and moves refill/resume routing after durable RPC settlement.

Historical provenance and retention/cleanup are not implementation prerequisites. Migration 0064 remains local until a new exact release receipt is obtained.

## Reachability and Pre-Mortem

- Changed job → trigger → owner/job change row → bounded enqueue → claimed item → one batch stage → atomic finalize → existing Dashboard feed.
- Dismiss click → synchronous target removal → durable RPC → success commit or exact-row rollback → detached refill/routing.
- Plan 05/06 summaries → fresh Plan 08 digest receipt → one Plan 09 release → new Plan 10 observation.

Most likely failure modes and gates:

1. A routine path still scans/seeds the catalog: pgTAP empty-tick, exact N×M, 25-bound, retry-membership, and worker call-count tests fail Plan 05.
2. Whole-cache rollback clobbers concurrent cards: deferred-promise/current-cache tests fail Plan 06.
3. Release scope drifts to 0065/retention or stale authority: Plan 08 exact allowlist/receipt and Plan 09 independent parity/effect counters stop before mutation.

## Concrete Patterns

### Frozen identity re-resolution

Every Oracle call receives the object returned by
`resolveBrandedIdentity(ORACLE_JPMC_SOURCE_KEY)`. The adapter rejects cloned or
mutated objects before network access:

```ts
resolveBrandedIdentity(identity.sourceKey) !== identity
```

Extend that same object with six exact title facets and one exact posting-date
facet. Do not add caller parameters.

### Slice reconciliation

The current Oracle loop already:

- pages by the fetched slice length;
- freezes the first `TotalJobsCount`;
- rejects later total drift;
- rejects duplicate IDs inside a slice;
- deduplicates the cross-slice union;
- rejects cross-slice identity drift;
- hydrates every selected detail within one invocation budget.

Keep this loop. Replace category identity checks with title-family plus
posting-date identity checks.

### Selective recency lifecycle

`pollWorkdayRecent` is the accepted rolling-window precedent:

```ts
completeness: 'complete',
credibleForClosure: true,
allowMissingClosure: selectiveScope ? false : ...
```

JPMorgan must return the same closure semantics. Complete means “the selected
seven-day window was fully observed,” not “the entire open board was observed.”

### Separate clocks

The Oracle adapter already uses a monotonic injected `now()` for its invocation
deadline. Workday recency parsing uses an injected epoch-millisecond clock.
Add a separate wall-clock dependency to Oracle; never use `performance.now()`
as a posting timestamp.

### Persistence revalidation

`poll-tick` does not trust adapter evidence blindly. It calls
`createBrandedScopeEvidence` again and compares normalized label, matched term,
and digest. Extend this central revalidation with Oracle's exact source-specific
family mapping rather than adding a bypass.

### Forward-only exact authority

Migration `0043` replaced shared RPC bodies and limited them to Workday exact
keys. Migration `0045` should replace those functions again, preserving every
existing branch while adding only:

- `ats_type = 'oracle_recruiting'`;
- `source_key = 'oracle:jpmc:CX_1001'`.

Do not re-grant the old multi-company branded finalizer. Create a JPMorgan-only
terminal boundary or replace it with a source-specific implementation.

### Hash-bound rollout

The Phase 03.8 runner establishes the release sequence:

1. local immutable manifest;
2. calculated file/object/function hashes;
3. `--dry-run` produces the exact approval string;
4. mutation mode rejects any other approval;
5. remote schema/function identity is rechecked before and after each stage;
6. verifier cleanup runs in `finally`;
7. reruns consume terminal evidence instead of duplicating mutations.

Reuse the pattern but keep the Phase 03.9 inventory small and JPMorgan-only.

`web/tests/branded-adapters.test.ts`:

Generalize them to accept title-family and posting-date facets. Required new
cases:

- exact finder contains country/title/date facets;
- title facet ID/label/total drift;
- posting facet ID/label/total drift;

- Strategy and Program Analysts evidence accepted only for JPMorgan;

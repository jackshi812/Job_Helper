# Quick Task 260716-nw6: Enforce current-password reauthentication

## Problem

`web/src/pages/Settings.tsx` `changePassword()` calls
`supabase.auth.updateUser({ current_password, password })`. The `current_password`
attribute is only honored when the Supabase project flag
`security_update_password_require_reauthentication` is ON — and it is OFF on this
project (empirically confirmed by `scripts/verify-reauth.ts`). So the reauthentication
silently no-ops: a live/hijacked session can change the password without knowing the
current one. Tracked as code-review CR-01 and security threat T-01-07 (reopened).

Chosen fix (option B): reauthenticate in application code, independent of any dashboard
flag, so the guarantee holds regardless of project config.

## Tasks

### Task 1 — Reauthenticate in code before updating the password

**Files:** `web/src/lib/supabase.ts`, `web/src/pages/Settings.tsx`, `web/src/pages/Settings.test.ts`

**Action:**
- Add `reauthenticate(email, password)` to `web/src/lib/supabase.ts`. It creates a
  short-lived isolated Supabase client (`persistSession: false`, `autoRefreshToken: false`)
  and calls `signInWithPassword({ email, password })`, returning `{ error }`. The isolated
  client avoids disturbing the active session or firing the app's `onAuthStateChange`.
- Rewrite `changePassword(email, currentPassword, newPassword)`: call `reauthenticate`
  first and throw on error, then `supabase.auth.updateUser({ password: newPassword })`
  (drop the ignored `current_password` field).
- Update the Settings component call site to pass `session.user.email`, throwing a clear
  error if the email is missing.
- Update `Settings.test.ts`: the reauth test asserts `reauthenticate` is called with the
  email + current password and `updateUser` with only `{ password }`; add a test proving a
  failed reauth throws and never calls `updateUser`.

**Verify:** `cd web && npm run test` (all pass), `npm run lint` (clean), `npm run build`
(typecheck + build pass).

**Done:** Password change requires the correct current password by application logic, not
by an unset server flag. Wrong current password → reauth error → no `updateUser` call.

## Must-haves

- **Truth:** A password change with a wrong current password fails without changing the password, regardless of the Supabase reauth flag.
- **Artifact:** `web/src/lib/supabase.ts` exports `reauthenticate`; `changePassword` calls it before `updateUser`.
- **Key link:** `Settings.tsx` → `reauthenticate` → isolated `signInWithPassword`; failure short-circuits before `updateUser`.

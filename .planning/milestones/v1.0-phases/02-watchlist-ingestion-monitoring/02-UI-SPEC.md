# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase 2 UI surface:** the Watchlist page (replaces the Phase 1 stub at `web/src/pages/Watchlist.tsx`) plus a global stale-pipeline banner rendered in the app shell. Everything inherits Phase 1's locked decisions: D-14 (system theme, light + dark auto-switch) and D-15 (clean minimal, neutral palette, dense tables, function over flair).

## Spacing Scale

Tailwind default scale (4px base), confirmed against Phase 1 code. Declared values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | Nav item gaps, inline chip gaps |
| sm | 8px (`gap-2`) | Button groups, table action clusters |
| md | 16px (`px-4`, `gap-4`) | Table cell horizontal padding, form field gaps |
| lg | 24px (`mt-6`, `p-6`) | Space between page intro and add form |
| xl | 32px (`mt-8`, `py-8`) | Space above the table card; main content vertical padding |
| 2xl | 48px | Major section breaks (not expected on this page) |
| 3xl | 64px | Page-level spacing (not expected on this page) |

Exceptions (inherited from Phase 1 dense-table convention — keep, do not "fix"):

- `py-2.5` (10px) table header vertical padding, `py-3` (12px) table cell vertical padding — the D-15 density values from `Resumes.tsx`
- `py-1.5` (6px) / `px-2.5` (10px) on compact buttons and row actions
- `gap-1.5` (6px) between a form label and its input
- Badge padding `px-2 py-0.5` (8px/2px) — new in this phase, matches compact-control convention

## Typography

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|----------|-------|
| Body | 14px | 400 | 1.5 (Tailwind `text-sm` default ≈1.43 — acceptable for dense tables) | `text-sm` | Table cells, form inputs, helper text, banner copy, dialog body |
| Label | 12px | 500 | 1.4 | `text-xs font-medium` | Table headers (uppercase + `tracking-wide`), health badges, compact row-action buttons |
| Heading | 16px | 600 | 1.3 | `text-base font-semibold` | Dialog titles, empty-state heading |
| Display | 20px | 600 | 1.2 | `text-xl font-semibold tracking-tight` | Page title ("Watchlist") |

Weight note: two contract weights for new decisions — 400 (body) and 600 (headings). Weight 500 (`font-medium`) is a documented Phase 1 inheritance used ONLY where Phase 1 already uses it: buttons, form labels, table headers, badges, and emphasized cells (e.g. company name, mirroring the filename cell in `Resumes.tsx`). Never introduce 700+. Source: `web/src/pages/Resumes.tsx`, `web/src/components/Shell.tsx`.

## Color

Neutral zinc/slate monochrome per D-15. Values are Tailwind palette tokens (light / dark).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` slate-50 / `#09090b` zinc-950 | Page background (set in `Shell.tsx` + `index.css`) |
| Secondary (30%) | `#ffffff` white / `#18181b` zinc-900, with `zinc-200`/`zinc-800` borders | Header, table card, add-form inputs, dialogs; table header strip `zinc-50`/`zinc-950` |
| Accent (10%) | `#18181b` zinc-900 / `#f4f4f5` zinc-100 (inverted monochrome) | See reserved list below |
| Destructive | `red-700` text/bg, `red-400` text in dark; `red-300`/`red-900` borders | Remove-company action, failing-state text, confirm button in `ConfirmDialog` |

Accent reserved for: the primary "Add company" button and the active nav item (Phase 1 convention). Nothing else — row actions stay bordered-neutral, links stay neutral with hover.

### Status palette (new in Phase 2 — semantic, not accent)

Health badges and the stale banner need status colors. Subtle tinted pills, never saturated fills:

| Status | Light | Dark | Applied to |
|--------|-------|------|------------|
| OK | `bg-emerald-50 text-emerald-700 border-emerald-200` | `dark:bg-emerald-950 dark:text-emerald-400 dark:border-emerald-900` | Health badge "OK" |
| Failing | `bg-red-50 text-red-700 border-red-200` | `dark:bg-red-950 dark:text-red-400 dark:border-red-900` | Health badge "Failing" (`consecutive_failures >= 3`, D-06) |
| Stale | `bg-amber-50 text-amber-700 border-amber-200` | `dark:bg-amber-950 dark:text-amber-400 dark:border-amber-900` | Health badge "Stale"; the global stale-pipeline banner |

Rule: status colors appear ONLY on badges, the banner, and inline error text. They are not decoration and never appear on buttons except the existing destructive-confirm pattern.

## Copywriting Contract

Voice (Phase 1 convention): sentence case everywhere, plain declarative sentences, errors state the problem then the next step, in-flight button labels use "Verb…" with ellipsis.

| Element | Copy |
|---------|------|
| Page title | `Watchlist` |
| Page intro | `Companies polled every few minutes for new postings. Shared between both users.` |
| URL input label | `Careers page URL` |
| URL input placeholder | `https://boards.greenhouse.io/company` |
| Primary CTA | `Add company` (pending: `Verifying…`) |
| Empty state heading | `No companies watched yet` |
| Empty state body | `Paste a careers page URL above to start monitoring. Works with Greenhouse, Lever, and Ashby job boards.` |
| Unsupported-URL rejection (D-04) | `This URL isn't a supported job board. Job Copilot works with Greenhouse, Lever, and Ashby. Look for a link like boards.greenhouse.io/company, jobs.lever.co/company, or jobs.ashbyhq.com/company — usually where the careers page's Apply buttons point.` |
| Verification-failed rejection (D-04) | `We couldn't verify this board — it may not exist or the URL may be misspelled. Check the address and try again.` |
| Duplicate company | `{Company} is already on the watchlist.` |
| Generic load error | `Unable to load the watchlist: {message}` |
| Destructive confirmation | Remove company — title: `Remove {company}?` · message: `Polling stops immediately. Jobs already captured stay in the system.` · confirm label: `Remove company` (pending: `Removing…`) |
| Health badge labels | `OK` / `Failing` / `Stale` |
| Health badge hover (D-05) | `Last successful poll: {relative time, e.g. "4 minutes ago"}` — never-succeeded: `No successful poll yet` |
| Stale-pipeline banner (D-07) | `Job monitoring hasn't run since {time} — new postings may be missed.` |

## Component Inventory

### 1. Watchlist page (`web/src/pages/Watchlist.tsx`, replaces stub)

Layout, top to bottom (mirrors `Resumes.tsx` exactly):

1. `<h1>` Display "Watchlist" + `mt-2` intro paragraph (`text-sm text-zinc-600 dark:text-zinc-400`)
2. `mt-6` add form: URL input (`type="url"`, required) styled like the Resumes file input (`rounded-md border border-zinc-300 bg-white px-3 py-2 text-sm` + dark variants) beside the primary "Add company" button (`rounded-md bg-zinc-900 px-4 py-2 text-sm font-medium text-white hover:bg-zinc-700` + inverted dark). `flex flex-wrap items-end gap-3`.
3. `mt-3` rejection/error message (`role="alert"`, `text-sm text-red-700 dark:text-red-400`) — inline under the form, not a toast. Rejection copy per table above; input keeps its value so the user can correct it.
4. `mt-8` table card: `overflow-x-auto rounded-lg border border-zinc-200 bg-white dark:border-zinc-800 dark:bg-zinc-900`. Loading / error / empty states render as a `p-4 text-sm` line inside the card (Phase 1 pattern).

Dense table columns:

| Column | Content | Cell style |
|--------|---------|-----------|
| Company | Company name | `font-medium`, truncate at `max-w-sm` |
| Source | ATS name, capitalized: `Greenhouse` / `Lever` / `Ashby` | muted (`text-zinc-600 dark:text-zinc-400`) |
| Health | Health badge (component 2) | — |
| Added | Date added, `Intl.DateTimeFormat` `dateStyle: 'medium'` | muted |
| Actions | Right-aligned `Remove` button — bordered destructive style from Resumes delete (`rounded-md border border-red-300 px-2.5 py-1 text-xs font-medium text-red-700 hover:bg-red-50` + dark variants) | `flex justify-end` |

Header row: `text-xs font-medium tracking-wide uppercase` on `zinc-50`/`zinc-950` strip; body rows `divide-y`. No zebra striping, no row hover color (Phase 1 tables have none). Must stay legible at 100+ rows — no pagination needed for v1, rely on density.

### 2. Health badge (new, `web/src/components/` if shared or local to Watchlist)

- Pill: `inline-flex items-center gap-1.5 rounded-full border px-2 py-0.5 text-xs font-medium` + status palette classes.
- Leading 6px dot (`size-1.5 rounded-full`) in the status's solid tone (`bg-emerald-500` / `bg-red-500` / `bg-amber-500`) — color is never the only signal; the text label always shows (accessibility).
- Hover reveals last-success time via `title` attribute (sufficient for 2 desktop users; a styled tooltip is optional polish, not contract).
- Derivation (from RESEARCH Pattern 6): `Failing` = `consecutive_failures >= 3` (D-06); `Stale` = `last_success_at` older than ~30 min without 3 failures; else `OK`.

### 3. Stale-pipeline banner (new, rendered in `Shell.tsx` below the header)

- Full-width strip, visible on every page while active: `border-b border-amber-200 bg-amber-50 text-amber-800` / `dark:border-amber-900 dark:bg-amber-950 dark:text-amber-300`, inner container `mx-auto max-w-6xl px-4 py-2 text-sm sm:px-6` with `role="status"`.
- Shows when `pipeline_heartbeat.last_success_at` is > 30 minutes old (D-07); disappears on recovery. No dismiss button — it reflects live state.
- Copy per contract table; `{time}` is a relative time ("since 10:42 AM" acceptable alternative if relative-time formatting is noisy).

### 4. Remove confirmation — reuse `web/src/components/ConfirmDialog.tsx` as-is

No modifications; props per the copywriting table. Single confirm (D-11 pattern for per-item deletes).

## Interaction States

| Surface | State | Behavior |
|---------|-------|----------|
| Add form | idle | Button enabled when input non-empty |
| Add form | verifying | Button `Verifying…`, disabled, `disabled:cursor-wait disabled:opacity-60`; input disabled |
| Add form | rejected | Inline alert with D-04 guidance; input retains value and refocuses |
| Add form | success | Input clears; new row appears in table (TanStack Query invalidation, Resumes pattern) |
| Table | loading | `Loading watchlist…` line in card |
| Table | error | `Unable to load the watchlist: {message}` alert line in card |
| Table | empty | Empty-state heading + body in card (`p-4`, heading `text-base font-semibold`, body `mt-1 text-sm` muted) |
| Remove | confirming | `ConfirmDialog` pending state (`Removing…`), row removed on success |
| Focus | all interactive elements | Browser default focus ring is acceptable (Phase 1 does not customize); do not remove outlines |

Data fetching: TanStack Query, `queryKey: ['watchlist']`; health data comes with the same companies query (badge fields are columns on `companies`). Poll/refetch interval for health + heartbeat: `refetchInterval: 60_000` so badges and the banner track reality within a minute without manual refresh.

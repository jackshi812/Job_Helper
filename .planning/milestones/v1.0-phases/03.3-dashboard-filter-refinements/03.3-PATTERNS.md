```typescript
function containsTokenSequence(haystack: string[], needle: string[]): boolean {
  if (needle.length === 0) return false
  if (needle.length === 1) return haystack.includes(needle[0])
  for (let i = 0; i + needle.length <= haystack.length; i += 1) {
    let match = true
    for (let j = 0; j < needle.length; j += 1) {
      if (haystack[i + j] !== needle[j]) {
        match = false
        break
      }
    }
    if (match) return true
  }
  return false
}
```

**Gate-order and bounded-error pattern** (`filters.ts`, lines 254-273):

```typescript
export function cheapFilter(job: FilterJobInput, prefs: FilterPreferences): FilterOutcome {
  const titleTokens = tokenize(job.title)
  const locationTokens = tokenize(job.location ?? '')
  const descriptionTokens = tokenize(job.descriptionText)

  // hard-discard gate
  const excludeHaystack = [...titleTokens, ...descriptionTokens]
  for (const keyword of prefs.excludeKeywords) {
    const needle = tokenize(keyword)
    if (containsTokenSequence(excludeHaystack, needle)) {
      return { pass: false, reason: 'excluded_keyword', detail: needle.join(' ') }
    }
  }
```

Place the new title-only gate first, then preserve general exclusion, location, title-intent, and soft-include ordering. Return only `{ pass: false, reason: 'excluded_title_keyword', detail: normalizedNeedle }`; no exception path is needed because this is a pure transform.

## Shared Patterns

### Authentication and ownership

**Sources:** `supabase/migrations/0017_preferences.sql` lines 26-45; `web/src/lib/preferences.ts` lines 38-60.

- Browser code uses the authenticated Supabase client and omits `user_id` on upsert.
- Database defaults `user_id` to `auth.uid()` and own-row RLS enforces select/insert/update/delete.
- Do not add service-role browser access or a new endpoint for title exclusions.

### Error handling

**Sources:** `web/src/lib/preferences.ts` lines 38-68; `Preferences.tsx` lines 129-140; `score-tick/index.ts` lines 253-283.

- Data helpers throw Supabase errors; components own stable user-facing copy and retain unsaved form state.
- Worker writes bounded reason/detail values, clears stale score fields, checks the captured revision, maps database failure to `score_write_failed`, and treats a lost CAS as `stale_discarded`.
- Pure filter/dashboard helpers do not catch; they return deterministic values.

### Validation and normalization

**Sources:** `0017_preferences.sql` lines 14-17; `preferences.ts` lines 24-36; `filters.ts` lines 163-181.

- Cap arrays at 50 in the database.
- Compare chip duplicates using NFKC + trim + lowercase while preserving first display casing.
- Compare title exclusions as literal token sequences; never interpolate user input into regex or SQL and never fuzzy-expand PhD.

### Refilter and cache ordering

**Sources:** `preferences.ts` lines 52-68; `Preferences.tsx` lines 120-140; `0025_scoring_freshness.sql` lines 33-58.

```text
own-row upsert succeeds
  -> mark_recent_jobs_for_refilter()
  -> cancel/remove stale feed cache
  -> invalidate feed and preferences
  -> worker reclaims caller-owned open rows with a new desired revision
```

Do not encode the stale seven-day comment as a test; the current RPC targets every caller-owned open job.

### Session-only Dashboard state

**Sources:** `dashboard.ts` lines 49-71; `Dashboard.tsx` lines 147-160 and 247-268.

- Hidden company keys and selected tiers are fresh component-local `Set`s.
- Search is presentation-only; applied company state changes only through Show results.
- Tier changes apply immediately; zero selections are valid.
- Only column widths use browser persistence.

### Test style

**Sources:** `preferences.test.ts`, `Preferences.test.tsx`, `dashboard.test.ts`, `Dashboard.test.tsx`, `filters.test.ts`, `scoring-input.test.ts`.

- Pure behavior: direct table-driven Vitest assertions.
- Supabase sequencing: hoisted mocks plus invocation order.
- Pages: `renderToStaticMarkup` for initial semantics and `?raw` source assertions for event/focus contracts not exercised by the current non-DOM stack.
- Worker/migration integration: structural source ordering plus focused pure imports; no new DOM or E2E dependency.

## Trust Boundaries

| Boundary | Description |
|---|---|
| User chip input → RLS-owned preferences row | Untrusted text is normalized client-side but remains authorized by existing own-row database policy. |
| Preference mutation → refilter/cache lifecycle | UI success must correspond to both persisted data and the server revision signal. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03.3-06 | Tampering | preference upsert | high | mitigate | Keep the existing authenticated Supabase client and own-row RLS; send no user_id override or service-role credential from the browser. |
| T-03.3-07 | Denial of service | chip arrays | medium | mitigate | Trim/deduplicate values and enforce the same 50-entry/4,096-byte JSON-encoded limit in browser validation and migration 0031 before refilter or worker processing. |
| T-03.3-08 | Spoofing / Repudiation | save success and feed cache | medium | mitigate | Preserve upsert-before-RPC and cache eviction only after both succeed; retain unsaved edits and bounded failure copy otherwise. |
| T-03.3-09 | Information disclosure | browser filter state | low | accept | Title exclusions are intentionally persisted preferences under RLS; no new logging, storage key, analytics event, or cross-user read path is added. |
| T-03.3-SC | Tampering | package supply chain | high | mitigate | Install no packages and reuse the existing ChipInput, React Query, and Supabase client. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| RLS-scoped feed rows → client company/tier filters | The browser may only narrow already-authorized truthful rows; local controls must not widen data access. |
| DOM/document events → React focus/state | Pointer and keyboard events control conditional panels and must cleanly release listeners/focus. |
| Browser storage → Dashboard | Only validated versioned column widths may cross this boundary; new filters remain memory-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03.3-10 | Information disclosure / Elevation of privilege | `filterDashboardRows` | high | mitigate | Leave RLS-scoped `listFeed` and current eligibility unchanged; client filters only remove rows and tests pin AND composition. |
| T-03.3-11 | Tampering | company bulk state | medium | mitigate | Use immutable hidden-key sets over the complete current option list, preserve staged draft/apply separation, and test stale/refreshed keys. |
| T-03.3-12 | Denial of service | document listeners | medium | mitigate | Install listeners only while the popover is open and remove them on close/unmount; add source lifecycle assertions. |
| T-03.3-13 | Spoofing / Accessibility | tier trigger/dropdown state | medium | mitigate | Use native button/fieldset/checkbox semantics, visible All/None/N copy, `aria-expanded`/`aria-controls`, and deterministic focus return. |
| T-03.3-14 | Information disclosure | browser persistence | low | accept | Company/tier selections are non-sensitive narrowing state and remain component-local; tests reject any new filter storage key/use. |
| T-03.3-SC | Tampering | package supply chain | high | mitigate | Install no packages; use native semantic controls and existing React/Tailwind patterns. |
</threat_model>

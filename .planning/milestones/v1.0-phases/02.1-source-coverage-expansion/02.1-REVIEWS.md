Today this is harmless because `verify-board` only performs an outbound fetch and writes nothing (supabase/functions/verify-board/index.ts:59-87 — no auth inspection anywhere). After Plan 02 it performs service-role inserts/updates on the shared `companies` table, and after Plan 05 it drives `record_connector_observation`. Plans 02 and 05 repeatedly say "any gateway-authenticated user," which papers over anon-vs-authenticated. Fix: Plan 02 Task 2 must require `verify-board` to resolve the caller's JWT to a real user (e.g., `auth.getUser(token)` / assert `role = authenticated`) before any service-role write, with a test asserting anon-key invocation is rejected, and Plan 07 should probe it hosted.

Claude and OpenCode reviewed the repository directly. Antigravity reviewed the complete 45k-token planning package without repository file tools; its source-code claims are therefore treated as open questions and weighted below the two grounded reviews.

### Agreed Strengths

- The execution order is sound: closure-safe observations precede provider expansion; exhaustive registry dispatch precedes source-union expansion; activation precedes hosted proof; schema push precedes assertions; SHA-matched deployment precedes UAT.
- The plans preserve fail-closed behavior and honest source states. Unsupported finance sites remain catalog-only, Workday remains Experimental, and ambiguous observations retain last-known jobs rather than authorizing closure.
- Server-time activation windows, replay constraints, the pinned Capital One source key, and the separate source-coverage catalog are strong cross-plan contracts.
- No reviewer recommended architectural rework. Overall risk remains MEDIUM and concentrated in authorization, regression ownership, and third-party-provider behavior.

### Agreed Concerns

1. **HIGH — Migration 0012 breaks existing Phase 2 hosted verifiers.** Claude and OpenCode independently found authenticated `companies` inserts in `scripts/verify-watchlist.ts` and `scripts/verify-pipeline.ts`. After authenticated insert/update is revoked, the watchlist verifier can delete a seed row and fail to restore it. A plan must migrate these scripts to the server-authoritative path or explicitly retire and replace them before treating existing-provider regression proof as complete.
2. **MEDIUM — The disposable hosted failure probe needs race/crash tolerance.** Claude identified a live-cron claim race; OpenCode identified heartbeat/banner side effects; Antigravity noted orphaned probe data after a process crash. The verifier should use unique markers, clean stale prior probes on startup, reset/observe state safely, and assert resulting row state regardless of whether the verifier or cron performed the claim.

### High-Priority Single-Reviewer Findings

- **HIGH — OpenCode:** `verify-board` relies on gateway JWT validation, which may accept the public anon-key JWT. Because Plans 02/05 add service-role writes and activation recording, the plan should require an in-function real-user/authenticated-role check and a hosted anon-key rejection probe.
- **MEDIUM — Claude:** Activation progress must be persisted atomically into the `companies` progress columns consumed by the Watchlist; a ledger-only count could leave the UI at `0 of 3`.
- **MEDIUM — OpenCode:** `ConfirmDialog` is shared by Resumes and Settings. The company-specific busy label should be prop-driven and existing consumer tests must stay green.
- **MEDIUM — OpenCode:** Recruitee lacks a controlled tenant-loss disposition comparable to SmartRecruiters.

### Divergent or Lower-Confidence Views

- Antigravity proposed ledger pruning, lock-timeout/`SKIP LOCKED` handling, probe TTL cleanup, and a bounded Cloudflare wait. These are useful design checks, but it could not inspect the repository; validate them against actual expected observation volume and RPC locking before expanding scope.
- Claude considered the gateway JWT a real guard but did not flag anon-key acceptance; OpenCode treated it as the primary blocker. This disagreement should be resolved against Supabase runtime semantics during replanning, not dismissed.
- SmartRecruiters pagination churn and exact count reconciliation were viewed as acceptable fail-closed degradation by the grounded reviews; Antigravity suggested tolerance. Preserve exact reconciliation unless evidence shows a safe tolerance rule.

2. Assign ownership for updating or retiring the Phase 2 verifier scripts broken by migration 0012.
3. Make the hosted disposable probe race-, crash-, and retry-safe.

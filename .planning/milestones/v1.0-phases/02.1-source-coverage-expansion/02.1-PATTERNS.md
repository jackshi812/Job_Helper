### `supabase/migrations/0012_source_coverage_expansion.sql`

**Analogs:** `0005_watchlist.sql`, `0006_jobs_pipeline.sql`, `0009_discovery_health_cadence.sql`, and `0010_atomic_discovery_reservations.sql`.

**Closed checks and identity** (`0005_watchlist.sql` lines 7-18; `0006_jobs_pipeline.sql` lines 5-22):

```sql
create table public.companies (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  ats_type text not null check (ats_type in ('greenhouse', 'lever', 'ashby')),
  board_token text not null,
  unique (ats_type, board_token)
);

create table public.jobs (
  source text not null check (source in ('greenhouse', 'lever', 'ashby', 'adzuna')),
  unique (source, external_id)
);
```

Keep both allowlists closed. Expand only for implemented adapters: SmartRecruiters, Recruitee, and possibly experimental Workday. Do not add Oracle, iCIMS, SuccessFactors, or Eightfold merely because they appear in the evidence matrix.

**Additive columns** (`0009_discovery_health_cadence.sql` lines 6-9):

```sql
alter table public.pipeline_heartbeat
  add column last_discovery_at timestamptz,
  add column last_discovery_success_at timestamptz,
  add column discovery_status text check (discovery_status in ('ok', 'degraded', 'failed'));
```

Follow this style for `careers_url`, multi-part identity (`site_token`/`source_key`), `activation_state`, activation counters, `last_verified_at`, `last_error_code`, and `last_observation_count`. Backfill existing Greenhouse/Lever/Ashby rows as active and derive HTTPS canonical board links where the original paste was not retained.

**Claim function** (`0006_jobs_pipeline.sql` lines 55-75): preserve the update-and-returning queue and explicit service-role grant, but require `activation_state = 'active'` in the SQL selection. Disabled/experimental exclusion must exist at the database claim boundary, not only in application dispatch.

**Authorization caveat:** `0005_watchlist.sql` lines 25-42 grants authenticated users full company update with `using (true)`/`with check (true)`. That is unsafe for server-owned activation and health fields. No field-level authorization analog exists. Prefer a narrowly scoped authenticated RPC for user-editable watchlist fields and service-role-only operational transitions, following `0010_atomic_discovery_reservations.sql` lines 7-46:

```sql
create or replace function public.admit_discovery_slot(...)
language plpgsql
security definer
set search_path = ''
...
revoke execute on function ... from public, anon, authenticated;
grant execute on function ... to service_role;
```

Do not weaken RLS or make activation/browser health counters writable while preserving the shared-table behavior.

### `adapters/types.ts` and the connector registry

**Analog:** `adapters/types.ts` lines 1-12 for normalized records and `poll-tick/index.ts` lines 42-50 for current dispatch.

```typescript
export interface NormalizedJob {
  source: 'greenhouse' | 'lever' | 'ashby' | 'adzuna'
  externalId: string
  title: string
  location: string | null
  absoluteUrl: string
  ...
}
```

Keep `NormalizedJob` as the stable ingestion payload. Add a separate `PollObservation` carrying jobs, completeness, closure credibility, page/count evidence, and bounded warnings. There is no in-repo analog for this distinction; implement the RESEARCH.md contract rather than treating `NormalizedJob[]` as successful observation.

**Dispatch anti-pattern to replace** (`poll-tick/index.ts` lines 42-50):

```typescript
if (company.ats_type === 'greenhouse') return pollGreenhouse(...)
if (company.ats_type === 'lever') return pollLever(...)
return pollAshby(company.board_token)
```

The implicit Ashby fallback would misroute every new provider. Replace it with an exhaustive closed registry or switch whose provider entry owns detection, endpoint construction, verification, and polling. Unknown, disabled, and unsupported providers must fail closed before any fetch.

No existing file combines typed tenant/site identities, activation capability, and exhaustive provider dispatch. Build this seam from RESEARCH.md Recommended Architecture, not by copying a longer conditional chain.

## Shared Patterns

### Authentication and authorization

**Sources:** `poll-tick/index.ts` lines 251-272; `supabase/config.toml` lines 385-392; `0005_watchlist.sql` lines 21-42; `0006_jobs_pipeline.sql` lines 31-36.

- `poll-tick` is JWT-disabled but fail-closed behind `x-cron-secret` and uses service role.
- `verify-board` stays gateway-JWT protected and is invoked by the signed-in client.
- Authenticated users read shared companies/jobs; jobs remain service-role write-only.
- Phase 02.1 must narrow activation/health transitions because current company update grants are too broad.

### SSRF and target construction

**Source:** `detect.ts` lines 35-80 and `detect.test.ts` lines 25-36, 45-69.

Parse with `URL`, match exact approved hosts, validate conservative identity pieces, and construct fixed targets. Never fetch `careers_url`. HTTPS, redirects, ports, credentials, DNS/private addresses, and Workday relative paths need new defenses.

### Adapter and lifecycle behavior

**Sources:** `lever.ts` lines 34-81; `greenhouse.ts` lines 47-81; `lifecycle.ts` lines 30-68; `poll-tick/index.ts` lines 166-248.

Keep provider-local DTOs, pure mappers, normalized records, contextual errors, and per-company batch isolation. New pagination must yield completeness evidence. Closure retains exact-ID/reopen/grace behavior but gains a mandatory complete-and-credible gate. Adzuna never repairs direct-source health.

### Migration and client data access

**Sources:** `0005_watchlist.sql` lines 7-42; `0009_discovery_health_cadence.sql` lines 6-9; `web/src/lib/watchlist.ts` lines 7-85.

Use additive lowercase SQL, strict checks, explicit grants/policies, and backfills. Client services use explicit columns, DB-shaped interfaces, `{ data, error }` destructuring, and thrown errors.

### Watchlist UI and hosted verification

**Sources:** `Watchlist.tsx` lines 67-90, 100-202; `ConfirmDialog.tsx` lines 15-31; `verify-watchlist.ts` lines 80-95, 220-269; `verify-pipeline.ts` lines 120-217, 243-266, 416-500.

Reuse React Query invalidation, one-minute refresh, semantic dense tables, Tailwind dark-mode pairs, mutation alerts, bounded hosted probes, cleanup in `finally`, and explicit PASS/FAIL assertions. Activation and health remain independent visible states.

## Boundary and Planning Warnings

1. Do not expand provider unions/checks before dispatch is exhaustive; current fallback routes unknown providers to Ashby.
2. HTTP 200 is not credible success. Validate content type, schema, counts, pages, and required details.
3. A non-empty partial observation must never close omitted jobs.
4. Never store/fetch a user-supplied polling endpoint. `careers_url` is display/navigation only.
5. Do not mark credentialed, WAF-blocked, prohibited, or unresolved sources Active.
6. Do not let browser clients mutate server-owned activation/health.
7. Do not change the approved Adzuna cadence or use Adzuna to improve direct-source health.
8. DISC-08 remains a human checkpoint: links plus honest unsupported dispositions are validation evidence, not proof every finance company is directly monitored.

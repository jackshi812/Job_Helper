# Phase 02.1 — UI Design Contract

> Visual and interaction contract for source coverage expansion. Generated from the Phase 02.1 context, research, requirements, and existing Watchlist implementation.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual Tailwind utility classes using current project patterns |
| Preset | Not applicable |
| Component library | None; retain hand-built React components |
| Icon library | None; use a text external-link glyph (`↗`) with `aria-hidden="true"` |
| Font | Inter with the existing system sans-serif fallback stack |
| Third-party registries | None |

Do not initialize shadcn, add a UI package, or introduce a new icon dependency in this phase. Reuse the current rounded borders, compact table, neutral zinc/slate palette, light/dark media-query behavior, and existing `ConfirmDialog` flow.

## Information Architecture

Phase 02.1 modifies only the existing Watchlist page. Navigation and page shell remain unchanged.

The desktop table column order is:

1. **Company** — company display name.
2. **Link** — safe canonical careers/job-search link.
3. **Source** — detected provider or branded/custom source label.
4. **Activation** — `Active`, `Experimental`, or `Disabled`.
5. **Health** — operational status and visible supporting detail.
6. **Added** — existing created date.
7. **Actions** — existing destructive remove action.

Activation and health are separate concepts and must never be collapsed into one ambiguous badge. Activation answers whether scheduled polling is allowed. Health answers whether the latest observations are trustworthy. Unsupported entries remain useful links, but are explicitly disabled and not monitored.

## Spacing Scale

All new layout values use multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge internals and icon-to-label gaps |
| sm | 8px | Compact controls, control gaps, stacked status lines, and table cell vertical padding |
| md | 16px | Table cell horizontal padding and default container padding |
| lg | 24px | Form-to-content and section spacing |
| xl | 32px | Table separation from the form |
| 2xl | 48px | Major section breaks only |
| 3xl | 64px | Page-level spacing only |

Minimum interactive height is 36px for pointer layouts and 44px when `pointer: coarse`. The external-link target must provide at least 36px of combined line-height/padding without enlarging the entire row. No other spacing exceptions.

## Typography

Only two font weights are permitted in Phase 02.1 additions: regular and semibold.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Table metadata | 12px | 400 | 1.4 | Status detail, timestamps, concise errors |
| Body | 14px | 400 | 1.5 | Table cells, page description, links, messages |
| Label | 14px | 600 | 1.4 | Controls, badges, table headers, company names |
| Section heading | 16px | 600 | 1.2 | Empty/error section headings and dialog title |
| Page heading | 20px | 600 | 1.2 | Existing `Watchlist` heading |

Table headers remain uppercase with tracking, but use 12px/600. Do not communicate state through weight alone.

## Color

The 60/30/10 allocation describes visual hierarchy, not an exact pixel audit. Both light and dark modes are required.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | Slate 50 `#f8fafc` | Zinc 950 `#09090b` | App background and open page space |
| Secondary (30%) | White `#ffffff` | Zinc 900 `#18181b` | Table, header, dialog, input surfaces |
| Accent (10%) | Zinc 900 `#18181b` | Zinc 100 `#f4f4f5` | Primary `Add company`, active navigation, focus outline, underlined careers links |
| Destructive | Red 700 `#b91c1c` | Red 400 `#f87171` | Remove button, destructive confirmation, destructive errors only |

Accent is reserved for the primary Add action, active navigation, keyboard focus outlines, and careers-link text/underline. It is not a general decoration color.

### Semantic status colors

| State | Light presentation | Dark presentation | Contract |
|-------|--------------------|-------------------|----------|
| Active | Zinc 100 background, Zinc 700 text/border | Zinc 800 background, Zinc 300 text/border | Neutral activation badge; active does not imply healthy |
| Experimental | Amber 50 background, Amber 800 text, Amber 200 border | Amber 950 background, Amber 300 text, Amber 900 border | Amber activation badge; always includes progress and `Scheduled polling off` |
| Disabled | Zinc 100 background, Zinc 600 text/border | Zinc 800 background, Zinc 400 text/border | Muted activation badge; never green |
| OK | Emerald 50 background, Emerald 700 text, Emerald 200 border | Emerald 950 background, Emerald 400 text, Emerald 900 border | Green health badge with visible `OK` text |
| Degraded | Amber 50 background, Amber 800 text, Amber 200 border | Amber 950 background, Amber 300 text, Amber 900 border | Amber health badge with visible `Degraded` text; not red because jobs are retained |
| Unsupported | Zinc 50 background, Zinc 600 text, Zinc 200 border | Zinc 950 background, Zinc 400 text, Zinc 700 border | Muted capability label paired with `Not monitored` |

Every badge includes visible text. A 6px colored dot may remain as decoration, but it is `aria-hidden` and never the only status signal. All text/background pairs must meet WCAG AA contrast in both modes.

## Watchlist Table Contract

### Link column

- Visible label: **Open jobs** followed by an `↗` glyph.
- Accessible name: **Open {company name} jobs in a new tab**.
- Render only server-stored canonical URLs that parse as HTTPS.
- Use `target="_blank"` and `rel="noopener noreferrer"`.
- The glyph is decorative and receives `aria-hidden="true"`.
- Links are underlined by default, not only on hover, so they remain recognizable without color.
- Hover increases underline thickness; focus uses a 2px accent outline with 2px offset and rounded corners.
- A missing or invalid legacy URL renders **Unavailable** in muted text. It must not render raw URL text or a disabled anchor.
- Prefer the canonical searchable careers page. The visible link does not expose internal polling endpoints.

### Activation column

**Active**

- Neutral `Active` badge.
- Scheduled polling is enabled.
- Never infer or color this badge from health.

**Experimental**

- Amber `Experimental` badge.
- Supporting line: **{completed} of 3 checks passed**.
- Second supporting line: **Scheduled polling off**.
- The row may independently show OK or Degraded health from verification observations.

**Disabled**

- Muted `Disabled` badge.
- Supporting line: **Scheduled polling off**.
- Used for unsupported, prohibited, blocked, or manually disabled sources.

### Health column

**Active / OK**

- Emerald `OK` badge.
- Supporting line: **Last success {relative time}**.
- Use a semantic `<time datetime="…">`; expose the localized full date/time in its accessible label or title.

**Active / Degraded**

- Amber `Degraded` badge.
- Supporting line: **Last success {relative time}**, or **No successful sync yet**.
- Concise error line appears visibly beneath it, up to two lines/120 characters.
- Final fixed line: **Last-known jobs retained.**
- Never expose response bodies, stack traces, secrets, endpoint query strings, or unbounded provider text.

Approved user-facing error translations:

| Error class | Visible detail |
|-------------|----------------|
| Timeout/network | `Timed out while syncing.` |
| 401/403/WAF | `Access blocked by source.` |
| Schema/content change | `Source response changed.` |
| Pagination/detail incomplete | `Source returned an incomplete job list.` |
| Implausible empty result | `Unexpected empty result.` |
| Unknown bounded failure | `Latest sync could not be completed.` |

**Experimental**

- Health is still rendered independently as OK or Degraded using the same rules.
- Last success refers to verification/soak observations, not scheduled polling.
- The activation column is the only place that shows the 3-check gate.

**Disabled / Unsupported**

- No green or amber health badge.
- Muted `Unsupported` capability label.
- Fixed line: **Not monitored**.
- One concise reason, for example **Public API requires employer credentials**, **Automated access is blocked**, or **No stable public feed**.
- Do not show `OK`, a polling cadence, last-success freshness, or language implying ingestion.
- The Link column remains fully functional so the entry is still useful for manual checking.

### Row interaction

- Rows are not clickable.
- Hover/focus-within may use Zinc 50 in light mode and Zinc 800 at 50% opacity in dark mode.
- Company names truncate only after a readable minimum width and expose the full value through normal text selection/title if truncation occurs.
- Actions remain right-aligned.
- Removing and later re-adding a supported company follows the current flow without a new edit affordance.

## Responsive Behavior

- At all widths, preserve the semantic `<table>` and every column; do not convert rows into cards or hide Link, Activation, or Health.
- The bordered table wrapper is a labeled horizontal-scroll region on narrow screens. Use `overflow-x-auto` and a minimum table width of 68rem (1088px).
- Give the scroll region `tabIndex="0"` only when needed for keyboard scrolling and accessible label **Watchlist; scroll horizontally to view all columns**.
- At 768px and above, the table fits the normal `max-w-6xl` shell when space allows.
- Below 768px, the form continues to wrap and the URL input becomes full width. The Add button remains at least 44px high for coarse pointers.
- Do not use a hover-only disclosure for errors or timestamps. All required status information remains visible while horizontally scrolling.
- Long health details wrap within a 17rem maximum column; they do not widen the entire page.

## Interaction and Accessibility

- Native anchors, buttons, labels, inputs, table headers, and `<time>` elements are required; no clickable `div` elements.
- All interactive controls show a 2px `focus-visible` outline with a 2px offset in both themes.
- Keyboard order follows visual order: URL input → Add company → row links/actions from top to bottom.
- External links activate with Enter and never hijack the row click target.
- Query refresh must not move focus, reopen dialogs, or announce unchanged data.
- Changed activation/health after a user-triggered verification may be announced through a polite live region; background one-minute refreshes do not repeatedly announce routine unchanged statuses.
- Status cannot rely on color, title attributes, or hover tooltips.
- Motion is limited to existing color transitions and respects `prefers-reduced-motion`; no animated status pulses.
- The remove dialog uses `role="dialog"`, `aria-modal="true"`, title association, a keyboard focus trap, Escape to keep the company when idle, initial focus on **Keep company**, and focus restoration to the originating Remove button after close.
- While removal is pending, both dialog buttons are disabled and the confirm label becomes **Removing…**. The current mutation error remains visible on the page as an alert.

## Loading, Empty, Error, and Destructive States

| State | Exact copy and behavior |
|-------|-------------------------|
| Page description | `Companies and career sites tracked for new postings. Monitoring state and source health are shown separately.` |
| Primary CTA | `Add company`; pending: `Verifying…` |
| Table loading | `Loading watchlist…` in the bordered surface; retain layout without fake rows |
| Empty heading | `No companies watched yet` |
| Empty body | `Paste a public careers or job-search URL above. Supported sources are verified before monitoring begins.` |
| List error | `Unable to load the watchlist. Refresh the page to try again.` followed by bounded technical detail only when safe |
| Add unsupported | `This careers site can be saved as a link, but it cannot be monitored automatically.` when the catalog flow supports link-only entries |
| Add failure | `Couldn’t add this company. Check that the URL is public and supported, then try again.` |
| Remove failure | `Remove failed: {bounded safe message}` |
| Destructive title | `Remove {company name}?` |
| Destructive body | `Polling stops immediately. Jobs already captured stay in the system.` |
| Non-destructive dialog CTA | `Keep company`; receives initial focus |
| Destructive CTA | `Remove company`; pending: `Removing…` |

Use `role="alert"` for actionable load/add/remove failures. Use `role="status"` or `aria-live="polite"` only for user-triggered, non-error state changes. Do not announce the same background health result once per minute.

## Data-to-UI Mapping

| Data condition | Activation UI | Health UI | Link UI |
|----------------|---------------|-----------|---------|
| Active connector, latest complete credible observation | Active | OK + last success | Open jobs ↗ |
| Active connector, failed/partial/implausibly empty observation | Active | Degraded + last success + safe error + retained-jobs message | Open jobs ↗ |
| Experimental connector, latest observation complete | Experimental + progress + polling off | OK + verification last success | Open jobs ↗ |
| Experimental connector, latest observation failed/partial | Experimental + progress + polling off | Degraded + safe error + retained-jobs message | Open jobs ↗ |
| Disabled source with no supported public contract | Disabled + polling off | Unsupported + not monitored + reason | Open jobs ↗ |
| Legacy row with invalid/missing canonical URL | Preserve truthful activation | Preserve truthful health | Unavailable |

Never derive `Active` from a recent success, and never derive `OK` from `activation_state`. Adzuna results do not improve or replace the direct source's displayed health.

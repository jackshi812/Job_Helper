## Shared Patterns

### Authentication and authorization

No new auth code is needed. Browser reads/writes remain through the authenticated Supabase client; `preferences` retains own-row RLS (`0017_preferences.sql:26-45`), feed reads remain RLS-scoped (`feed.ts:186-204`), and `score-tick` remains service-role. Company/tier/width controls do not create a network authorization path.

### Error handling

- Thin Supabase helpers throw returned errors (`preferences.ts:36-43,50-65`; `feed.ts:193-204`).
- Pages own bounded, actionable UI copy (`Preferences.tsx:125-136`; `Dashboard.tsx:205-219`).
- Storage is an exception: all access/parse/write failures silently fall back to defaults per the approved UI contract.
- Worker logs/errors remain bounded codes; do not log job descriptions or parsed experience text.

### Validation boundaries

- Preference UX validates blank or integer `0..20`; PostgreSQL repeats the bound as the authority.
- Required-years parsing fails open on uncertainty, but a confidently explicit required minimum above the cap fails closed for that row.
- Stored width JSON is untrusted: allow only known keys and finite numbers, clamp to the UI-SPEC min/max.
- Company options use only `companyName(row)` from already authorized feed rows.

### Visual and accessibility conventions

Reuse native semantic elements, Tailwind zinc/light-dark styles, `focus-visible:outline-2`, 36px controls with 44px coarse-pointer targets, the existing scroll-region label, and no new dependency. The company panel is inline, search is a checklist filter rather than arbitrary entry, and resize handles follow separator semantics.

## Ordering and Dependencies

1. **Schema contract first:** create and structurally test migration 0030 (nullable preference column + expanded reason check).
2. **Pure backend contract:** extend `filters.ts`, `scoring-input.ts`, and their tests before changing the worker.

6. **UI composition:** add `ColumnResizeHandle`, route-aware `Shell`, and Dashboard controls/table using the pure model; retain detail reasons.
7. **Full local gate:** focused tests, then `cd web && npm test && npm run build && npm run lint`.
8. **Explicit hosted checkpoint:** schema `0030` -> updated `score-tick` -> web build/deploy. Do not deploy web projections before the schema exists; do not mutate providers/polling or make paid-AI test calls for this phase.

# Phase 03.2 — UI Design Contract

> Visual and interaction contract for Dashboard Precision & Company Visibility. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing manual Tailwind CSS design language; no shadcn initialization |
| Preset | Not applicable |
| Component library | None; use native semantic HTML and existing React patterns |
| Icon library | None; retain the existing restrained Unicode arrows where needed |
| Font | Inter with the existing `ui-sans-serif`, system fallback stack |

The phase extends the current dense zinc table, light/dark color scheme, rounded borders, underlined text links, and explicit focus outlines. It must not introduce a new visual language, dependency, component library, or third-party registry.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight inline gaps and resize indicator offsets |
| sm | 8px | Checkbox-label gaps, compact controls, table header vertical padding |
| md | 16px | Page gutters on narrow screens, table cell horizontal padding, panel fields |
| lg | 24px | Desktop page gutters, control-panel padding, section separation |
| xl | 32px | Dashboard heading-to-results separation |
| 2xl | 48px | Reserved major section break |
| 3xl | 64px | Reserved page-level separation |

Exceptions: interactive controls are at least 36px high with a 44px minimum on coarse pointers; the visible resize rule is 1px, centered inside a 16px pointer/keyboard hit area and a 44px coarse-pointer hit area.

## Typography

Use exactly these four sizes and two weights throughout new Phase 03.2 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Helper / table header | 12px | 600 | 1.5 |
| Body / controls / table cells | 14px | 400 | 1.5 |
| Section heading | 16px | 600 | 1.3 |
| Page heading | 20px | 600 | 1.2 |

Uppercase tracking remains limited to table headers. Company names, locations, button labels, and helper copy use sentence case. Truncate dense table values visually only when needed; preserve the full value in the accessible name or `title` text.

Accent is reserved for the company-search focus treatment and the existing New badge. Strong score status retains existing emerald; updating status retains existing amber. Color never carries selected, score, error, or resize state alone: text, `aria-pressed`/checked state, labels, and cursor/focus treatment provide redundant meaning.

## Page Anatomy

### Shell and width

- Keep the navigation/header, heartbeat banner, page background, and vertical rhythm unchanged.
- Keep the header and banner content centered at the existing `max-w-6xl` width.
- Only the Dashboard route removes the main content `max-w-6xl` ceiling. Its content uses the full remaining viewport width with 16px gutters below 640px and 24px gutters from 640px upward.
- Preferences and every non-Dashboard route retain their existing content width.

### Dashboard order

The full-width results table is the Dashboard's primary visual anchor. The filter controls are a compact supporting layer above it and must not visually compete with the job rows.

1. Page heading and descriptive sentence.
2. Existing `Show dismissed` control.
3. A filter row containing the company-panel trigger and Strong, Good, and Weak score-tier toggles.
4. The inline expandable company panel, when open.
5. Result count/status text.
6. Full-width results table inside its existing bordered, horizontally scrollable region.

The controls wrap without overlap. On narrow screens, each group occupies a full row and the company panel spans the available width.

## Component Inventory

| Component | Contract |
|-----------|----------|
| Company filter trigger | Zinc outlined button labeled `Companies` when all are visible and `Companies (N selected)` when narrowed. It exposes the inline panel with `aria-expanded` and `aria-controls`; opening does not change results. |
| Company search | 44px-high text input labeled `Search companies`, placeholder `Search current companies`. It filters only the checkbox list and never creates a company. |
| Company checkbox list | Truthful, case-insensitively alphabetized names from the currently authorized loaded feed. Each row has a 24px checkbox, full company label, and at least 44px row height. Checked means visible. The list is capped at 320px high and scrolls independently. |
| Company panel footer | Sticky footer with secondary `Reset` and zinc-inverse primary `Show results`. Reset affects company selection only; it has no relationship to saved column widths. |
| Score-tier toggles | Three independent `aria-pressed` buttons: `Strong`, `Good`, `Weak`. All begin selected. Existing tier boundaries remain Strong ≥75, Good 50–74, Weak <50; existing scoreless rows represented as Weak follow the same presentation helper. |
| Experience preference | Native number input on Preferences labeled `Maximum required experience`, minimum 0, maximum 20, integer step 1. Blank means no maximum. It uses the existing preference form and `Save preferences` CTA. |
| Result table | Dense native table ordered New, Job, Company, Location, Score, Best fit, Posted, Apply, Action. `Match reason` is absent. The Job link opens existing detail where Match reasons remain unchanged. |
| Resize handle | One semantic separator at the right edge of each resizable header except the last. Visible as a 1px zinc rule on hover, focus, or active drag; cursor `col-resize`; no added icon dependency. |

## Interaction Contract

### Company filtering

1. On each Dashboard mount, every currently loaded company is visible and the company search is empty. State is in-memory only and resets on refresh or navigation.
2. Opening the panel copies the currently applied visible-company set into a draft set.
3. Search matches company names case-insensitively and only narrows the visible checklist. It does not alter checked state or the result table.
4. Checking/unchecking edits the draft. `Show results` commits the draft, closes the panel, clears search, and moves focus back to the trigger.
5. `Reset` checks every current company in the draft. The user confirms that reset with `Show results`; no persisted preference or ingestion state changes.
6. If a background feed refresh introduces a truthful new company while the Dashboard remains mounted, add it checked by default so new feed rows are not silently hidden.
7. An empty draft is allowed and produces the filter-empty state. The panel must never offer arbitrary company entry; new employers continue through Watchlist URL entry.

### Score-tier filtering

- Strong, Good, and Weak toggles apply immediately and independently; all are selected on mount.
- Tier state is session-only. At least zero tiers may be selected so the zero-results state is explicit rather than silently overriding the user's choice.
- Applied company visibility and selected tiers use AND semantics after current preference-pass and dismissed eligibility: a row must have a visible company and a selected tier.
- Changing Show dismissed does not reset company or tier selection.

### Resizing and persistence

- Pointer drag updates a preview width continuously, clamps to the declared minimum/maximum, and persists the final width on pointer-up.
- Each handle is keyboard focusable with `role="separator"`, `aria-orientation="vertical"`, `aria-label="Resize {Column} column"`, and current/min/max numeric values. Left/Right Arrow changes width by 8px; Shift+Arrow changes it by 24px; Home/End move to the declared minimum/maximum.
- Prevent text selection during active drag, use pointer capture, and restore the normal cursor on pointer-up or pointer-cancel.
- Persist only column widths in same-origin local storage under a versioned key such as `job-copilot.dashboard.column-widths.v1`. Read once on Dashboard initialization, validate finite numbers, ignore unknown columns, and clamp values before use.
- Storage denial, malformed JSON, or out-of-range values silently falls back per-column to defaults. No reset-width control is present.

### Responsive behavior

- At widths below 768px, retain the desktop column set and accessible horizontal scrolling instead of hiding data columns.
- Filter controls wrap; the company panel becomes full width; its checkbox list remains independently scrollable.
- Resize handles remain keyboard operable. Coarse-pointer hit areas expand to 44px without changing the 1px visual rule or the saved width value.
- The scroll region retains `tabIndex=0` and its existing accessible label explaining horizontal scrolling.

### Preference field

- Blank maximum experience is the default and communicates no experience cap.
- Reject decimal, negative, or values above 20 inline with `Enter a whole number from 0 to 20, or leave blank.` Do not submit while invalid.
- Helper copy states that explicit required minimum years above the saved value are filtered; preferred, desired, bonus, nice-to-have, missing, ambiguous, and unparseable experience remain eligible.
- Saving follows the existing pending/success/error states and refilter message. This field is persisted per user; it is distinct from session-only Dashboard controls.

## State Matrix

| State | Visual and copy contract |
|-------|--------------------------|
| Feed loading | Existing bordered result region with `Loading…`; filters may remain disabled until company options exist. |
| Feed error | Red alert: `Couldn’t load your matches. Check your connection and retry.` and existing `Retry` button. |
| No feed data | Heading `No matches yet`; retain existing explanation and Preferences link when preferences are absent. |
| Filters produce zero rows | Heading `No jobs match these filters`; body `Select more companies or score tiers, or reset the company filter.` Keep controls available above it. |
| Company search produces zero options | In-panel text `No current companies match your search.` Existing checked selections remain untouched. |
| All companies visible | Trigger label `Companies`; all checkboxes checked after panel opens. |
| Company selection narrowed | Trigger label `Companies (N selected)` and result count updates only after `Show results`. |
| All score tiers cleared | Filter-empty state; all three toggles visibly unselected with accurate `aria-pressed=false`. |
| Missing location | Render `—`; never infer a location. |
| Invalid stored widths | Use declared defaults with no blocking warning. |

## Accessibility Contract

- Every filter control exposes state programmatically (`aria-expanded`, checked state, or `aria-pressed`), has a visible focus outline, and works without a pointer.
- The company panel has an accessible heading and a labeled checkbox group. Search results are not a combobox accepting arbitrary values; they are a filtered checklist.
- Announce committed result count changes through a polite status region: `{N} jobs shown`.
- Do not move focus when tier toggles update results. `Show results` returns focus to the company trigger; Escape closes an open panel without applying the draft and returns focus to the trigger.
- Column resize handles use separator semantics and numeric ARIA values. Active keyboard resizing does not trigger table sorting.
- Score sorting remains on its nested button and retains `aria-sort` on the Score header; the resize handle is a separate focus target.
- Table links, Dismiss/Restore actions, badges, and row hover/focus treatments preserve the current keyboard and contrast behavior.

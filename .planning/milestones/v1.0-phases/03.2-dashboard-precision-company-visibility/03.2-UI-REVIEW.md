## Top 3 Priority Fixes

1. **Bring experience-field validation and copy back to contract** — users currently see feedback only after submit and assistive technology is not told that the field is invalid — validate on change/blur, use the approved label/helper/error strings, and bind helper/error text through `aria-describedby` plus `aria-invalid`.
2. **Replace off-scale spacing in new controls** — the filter panel and dense table mix 6px, 10px, and 12px intervals with the approved rhythm — map `gap-1.5`, `py-1.5`, `px-2.5`, `py-2.5`, and new `gap-3`/`mt-3` uses to the declared 4/8/16/24/32px tokens.
3. **Enforce the approved type and accent rules** — new labels/buttons use 500 weight and the preference input inherits blue focus despite the two-weight and restricted-accent contract — use 400/600 weights and either document the preference-field focus exception or keep its focus treatment neutral.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING — preference strings diverge from the signed-off copy.** The contract specifies `Maximum required experience`, the full “explicit required minimum” helper, and `Enter a whole number from 0 to 20, or leave blank.` The implementation uses `Maximum required experience (years)`, a shorter helper, and adds `for no cap` to the error (`web/src/pages/Preferences.tsx:149,177-180`). The meaning is close, but exact reviewed wording and terminology were not preserved.
- Dashboard copy is otherwise pinned correctly: `Companies`, `Search companies`, `Search current companies`, `Reset`, `Show results`, score-tier labels, the filter-empty state, search-empty state, and feed error are present at `web/src/pages/Dashboard.tsx:340-459`.
- **Human needed:** confirm the revised preference helper is understandable in the complete form and that the company trigger count is clear with real company data.

### Pillar 2: Visuals (3/4)

- **WARNING — rendered hierarchy is not evidenced.** Code places heading, base filters, precision controls, expandable company panel, live result count, and full-width table in the contract order (`web/src/pages/Dashboard.tsx:305-494`). Shell code widens only `/` while preserving centered chrome (`web/src/components/Shell.tsx:16-19,53-97`). This supports the intended table-first hierarchy, but no screenshot proves the panel remains supporting rather than visually competing.
- The table keeps all nine columns, uses fixed layout with a current-width minimum, and preserves horizontal overflow (`web/src/pages/Dashboard.tsx:432-552`). Because it combines `w-full` with a summed `minWidth`, a wide viewport may distribute surplus width beyond persisted column values; whether this feels spreadsheet-like requires rendered inspection.
- New/score/updating/best-fit badges, underlined links, row hover/focus treatments, and the restrained separator rule preserve the established dense-table language (`web/src/pages/Dashboard.tsx:565-667`; `web/src/components/ColumnResizeHandle.tsx:117-138`).
- **Human needed:** authenticated production rendering at desktop width, visual balance of the expanded panel, column truncation/wrapping, row density, and resize-rule visibility.

### Pillar 3: Color (3/4)

- **WARNING — accent scope is wider than declared.** Dashboard reserves blue for the existing New badge and company-search focus (`web/src/pages/Dashboard.tsx:54-55,382`), but the shared preference input class also gives the new experience field a blue focus border/ring (`web/src/pages/Preferences.tsx:11-13,179`). The UI-SPEC reserves accent to company-search focus and New.
- Neutral surfaces and selected controls follow the light/dark zinc inverse contract (`web/src/pages/Dashboard.tsx:99-102,368,407,432-494`). Red is used for errors, emerald for Strong, and amber for updating status; labels and ARIA state provide non-color cues.
- The only hard-coded base colors in the audited stylesheet are the approved light/dark background and foreground values (`web/src/index.css:12-13,33-34`).
- **Human needed:** real light/dark contrast, focus-ring visibility, selected/unselected tier differentiation, and the practical 60/30/10 balance.

### Pillar 4: Typography (3/4)

- **WARNING — a third weight violates the approved two-weight system.** Across the audited Phase UI, the code uses only the declared `text-xs`, `text-sm`, `text-base`, and `text-xl` sizes, but it contains five `font-medium` uses in addition to 18 `font-semibold` uses. New examples include the company-search label (`web/src/pages/Dashboard.tsx:373`) and experience label/save control (`web/src/pages/Preferences.tsx:177,215`). The contract permits only 400 and 600.
- Table headers correctly use 12px semibold uppercase tracking, body/cells use 14px, section headings use 16px semibold, and page headings use 20px semibold (`web/src/pages/Dashboard.tsx:307,370,486,494`).
- Dense values retain full accessible/title text where truncation occurs for job, company, location, and posted date (`web/src/pages/Dashboard.tsx:578-597`; `web/src/pages/Dashboard.tsx:80-93`).
- **Human needed:** verify actual Inter loading/fallback, line-height and two-line job-title clipping, and scanning legibility at the widest and narrowest columns.

### Pillar 5: Spacing (2/4)

- **WARNING — off-scale values are systematic, not isolated.** The audited Phase UI contains six `gap-1.5` uses (6px), six `px-2.5` uses (10px), five `py-0.5` uses (2px), four `py-1.5` uses (6px), one `py-2.5` use (10px), and repeated `gap-3`/`mt-3`/`px-3` uses (12px). The contract declares 4/8/16/24/32px tokens and says the scale is based on multiples of four.
- Specific new-control examples are the filter buttons at `web/src/pages/Dashboard.tsx:97-102`, filter rows and panel at `web/src/pages/Dashboard.tsx:312-407`, and table header/badges at `web/src/pages/Dashboard.tsx:494,569-623`.
- Contract-aligned geometry is also present: 16/24px responsive Dashboard gutters (`web/src/components/Shell.tsx:16-19`), 32px separation before the table (`web/src/pages/Dashboard.tsx:432-436`), 44px search/checklist/coarse-pointer targets (`web/src/pages/Dashboard.tsx:382-400`; `web/src/components/ColumnResizeHandle.tsx:133`), and a 320px company-list cap (`web/src/pages/Dashboard.tsx:384`).
- **Human needed:** assess wrap rhythm at mobile widths and whether the independently scrolling checklist/footer has enough breathing room with long company names.

### Pillar 6: Experience Design (3/4)

- **WARNING — experience validation is not inline.** Invalid values are checked only inside form submit and the error persists until another submit (`web/src/pages/Preferences.tsx:143-153,177-180`). The input has native min/max/step, but it does not expose `aria-invalid` or associate helper/error copy with `aria-describedby`.
- Dashboard state coverage matches the contract: loading, connection error with Retry, no feed, filter-empty, search-empty, result-count status, missing location, and invalid-width fallback all have implementations (`web/src/pages/Dashboard.tsx:426-483,593-597`; `web/src/lib/dashboardColumns.ts:42-113`).
- Interaction wiring is strong in code: staged company apply/reset/Escape/focus return, immediate tier toggles, polite count announcement, focusable scroll region, separate Score sort target, semantic resize separators, pointer capture/cancel rollback, keyboard steps, guarded versioned persistence, and coarse-pointer hit areas (`web/src/pages/Dashboard.tsx:247-302,331-436,508-526`; `web/src/components/ColumnResizeHandle.tsx:39-138`).
- Static/unit tests verify state reducers, ARIA markup, storage guards, column bounds, source contracts, and no company/tier persistence (`web/src/lib/dashboard.test.ts`; `web/src/pages/Dashboard.test.tsx`). They do not simulate authenticated focus, pointer capture, touch, responsive rendering, or live refresh.
- **Human needed:** pointer resize feel/cancellation, Arrow/Shift+Arrow/Home/End focus behavior, Score-sort isolation, reload persistence, staged filter focus/announcements, session reset, newly refreshed companies, responsive horizontal scrolling, and coarse-pointer target usability.

## Human Verification Required

1. **Authenticated production rendering:** compare Dashboard, Preferences, and Job Detail in light and dark themes; confirm only Dashboard is full width, Location truncates truthfully, Match reason is absent from the table, and Match reasons remain on detail.
2. **Filter interaction:** exercise company search, draft checkboxes, Reset, Show results, Escape, tier toggles, result announcements, navigation/reload reset, and a feed refresh adding a new company.
3. **Resize interaction:** drag and cancel every representative handle, use all keyboard commands, reload for persistence, sort Score, and verify company Reset does not affect widths.
4. **Responsive/coarse pointer:** test narrow mobile/tablet widths and a touch/coarse-pointer device; confirm all columns remain reachable, filter groups wrap cleanly, and 44px resize targets do not obscure neighboring controls.
5. **Visual judgment:** inspect table/panel hierarchy, persisted-width fidelity on very wide screens, typography, contrast, truncation, and spacing rhythm.

## Shared Patterns

### Exact identity admission

**Source:** `workday-identities.ts:43-106`, `connectors.ts:280-289`, `0036:47-70`  
**Apply to:** registry, detection/verification, scheduled polling, migration, tests.

Admission requires the same exact tuple at application and database boundaries. A successful Nasdaq observation cannot authorize S&P Global, Morningstar, State Street, or an unknown Workday tenant.

### Live facet proof and fail-closed closure

**Source:** `workday.ts:579-653,669-853`, `_shared/lifecycle.ts:49-57,112-124`  
**Apply to:** Workday adapter, verifier, poll worker, Workday tests.

Validate facet structure and counts, apply the registered scope on every page, reconcile the scoped total, reject drift, and set `credibleForClosure: false` plus `allowMissingClosure: false` on any uncertainty.

### Experimental-to-Active observation

**Source:** `verify-board/index.ts:180-205,256-308`, `0035:54-254`  
**Apply to:** all four new Workday identities.

Only complete, credible, warning-free server-timed evidence advances one exact company's three-window progress.

### Per-user lifecycle authorization

**Source:** `0019_user_jobs_scoring.sql:28-84`, `0032:499-503`  
**Apply to:** migration and all lifecycle mutations.

Lifecycle belongs on `user_jobs`; RLS matches `auth.uid()` to `user_id`; authenticated grants name only permitted lifecycle columns. Shared `jobs` rows are never updated or deleted by Dashboard actions.

### Query-before-limit and stable ordering

**Source:** `feed.ts:153-170`, `feed.test.ts:157-176`  
**Apply to:** every lifecycle feed request, company option request, Load more, and backfill.

All eligibility/lifecycle/company/tier filters must be in the server query before `.limit(200)`. Every ordering ends with a unique key and the cursor carries the same tuple.

### Optimistic mutation rollback

**Source:** `Dashboard.tsx:247-279`  
**Apply to:** Mark Applied, Dismiss, Undo Applied, Restore.

Cancel matching queries, snapshot exact cache state, optimistically update/remove, restore the exact snapshot on error, then invalidate/refetch affected lifecycle queries. Backfill failure does not roll back a lifecycle mutation that already succeeded.

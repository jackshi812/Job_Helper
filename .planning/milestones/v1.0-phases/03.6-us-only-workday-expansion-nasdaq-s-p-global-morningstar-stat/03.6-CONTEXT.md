# Phase 03.6: US-Only Workday Expansion & Dashboard Queue - Context

**Gathered:** 2026-07-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Add Nasdaq, S&P Global, Morningstar, and State Street as four exact, independently monitored Workday sources that ingest only United States jobs. Extend the existing Dashboard lifecycle so a user can manually move a job between Active, Applied, and Dismissed without deleting the shared job, and retrieve qualifying Active jobs beyond the first 200.

This phase is a bounded precursor to Phase 4. It persists a reversible applied state but does not build the full application tracker, resume tailoring, application notes, or application-stage workflow.

</domain>

<decisions>
## Implementation Decisions

### Carried Workday Safety Contract
- **D-01:** Admit only these exact validated Workday identities:
  - `https://nasdaq.wd1.myworkdayjobs.com/Global_External_Site`
  - `https://spgi.wd5.myworkdayjobs.com/SPGI_Careers`
  - `https://morningstar.wd5.myworkdayjobs.com/morningstar`
  - `https://statestreet.wd1.myworkdayjobs.com/Global`
- **D-02:** All four sources are United-States-only. Their live country facet uses ID `bc33aa3152ec42d4995f4791a106ed09` for `United States of America`; Morningstar exposes it through a nested `locationMainGroup` → `locationCountry` structure that the adapter must discover and reconcile.
- **D-03:** Preserve the exact-registry, live-CXS verification, complete-count reconciliation, fail-closed closure, and Experimental-to-Active observation model established in Phase 03.5.
- **D-04:** Observe and activate each company independently. Drift or failure in one identity must not authorize, close jobs for, or block another identity.
- **D-05:** Capital One, Fidelity, other connectors, deterministic ranking, and existing source-health semantics remain unchanged.

### Applied-Job Flow
- **D-06:** A job becomes Applied only when the user explicitly selects a separate **Mark Applied** action. Opening the external Apply link must not infer that an application was completed.
- **D-07:** Active, Applied, and Dismissed are mutually exclusive per-user lifecycle states. Undo Applied or Undo Dismissed returns the job to Active.
- **D-08:** Mark Applied removes the row from the Active view immediately and presents a brief Undo notification; no confirmation dialog is required.
- **D-09:** Phase 03.6 persists `applied_at` through a stable, RLS-protected mutation path. The future tracker will extend that action to create or update the tracker entry.
- **D-10:** Lifecycle changes affect only the user's `user_jobs` state and never delete or mutate the shared job record.

### Dashboard Lifecycle Views
- **D-11:** Review Applied jobs in the existing Dashboard through a **Show applied** control beside the existing **Show dismissed** control.
- **D-12:** Active is the default view. Active, Applied, and Dismissed views are mutually exclusive rather than combined.
- **D-13:** Existing keyword, company, tier, and location filters remain available and behave consistently in all three lifecycle views.
- **D-14:** Order Applied by newest `applied_at` and Dismissed by newest `dismissed_at`. Preserve the established deterministic ordering for Active jobs.

### Dashboard Loading and Capacity
- **D-15:** Use an explicit **Load more** interaction, not infinite scrolling or numbered pages.
- **D-16:** Fetch 200 qualifying jobs initially and 200 more per Load more action. Apply lifecycle and other active query filters before the batch limit so Applied and Dismissed rows never consume Active slots.
- **D-17:** Use stable cursor pagination with no duplicates or unstable reordering between batches.
- **D-18:** When an Active row is marked Applied or Dismissed, remove it immediately and automatically fetch the next eligible job to fill the slot.
- **D-19:** If no replacement or further qualifying job exists, allow the visible count to fall below 200, show **You're all caught up**, and disable **Load more**.

### the agent's Discretion
- Choose the forward-only migration name and exact schema constraint used to encode the mutually exclusive lifecycle states.
- Choose the opaque cursor representation and query composition needed for stable, filtered pagination.
- Reuse or introduce the smallest accessible notification primitive for the brief Undo action.
- Choose implementation-level component boundaries and test helpers while preserving the existing compact Dashboard surface.

### Folded Todos
- **Pilot Workday polling for 10 companies** (`.planning/todos/pending/2026-07-20-pilot-workday-polling-for-10-companies.md`): fold its reliability requirements into this phase—exact per-tenant authorization, independent scheduling and health, truthful completeness, safe closure, and failure isolation. Phase 03.6 implements the four companies explicitly named in its boundary; it does not implicitly authorize the todo's other candidate employers.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `WORKDAY_IDENTITIES` and its parser/lookup helpers in `supabase/functions/_shared/workday-identities.ts` provide the exact-registry admission boundary; extend the identity metadata instead of introducing a parallel registry.
- The generic adapter in `supabase/functions/_shared/adapters/workday.ts` already parameterizes origin, tenant, site, pagination, discovery, and reconciliation. Add reusable U.S.-facet metadata/discovery capable of both flat and nested country facets.
- `listFeed`, feed row/detail selects, and lifecycle mutations in `web/src/lib/feed.ts` are the natural data boundary for server-side status filtering and cursor pagination.
- Existing optimistic Dismiss/Restore behavior in `web/src/pages/Dashboard.tsx` is the interaction pattern for Mark Applied, Undo, backfill, and lifecycle view changes.

### Established Patterns
- Workday identities are frozen and exact; a successful tenant never authorizes another tenant implicitly.
- A source stays Experimental until repeatable clean observations support activation; source drift degrades only that source and must fail closed for job closure.
- Schema changes are forward-only migrations. Deployed migrations are never edited.
- `user_jobs` owns reversible per-user lifecycle state under RLS; shared `jobs` rows are not deleted when a user dismisses or applies.
- Active Dashboard filtering must happen in the database before limiting results. Client-only hiding cannot satisfy the 200-slot contract.

### Integration Points
- Extend `WorkdayIdentity` with reusable U.S.-scope/facet metadata and register the four exact identities.
- Update verification and polling paths to carry the registered identity scope into the adapter and health evidence.
- Add `applied_at` and the required authenticated column grant while retaining existing RLS ownership guarantees.
- Extend feed queries and mutations for mutually exclusive lifecycle views, lifecycle-specific ordering, stable cursors, and automatic slot backfill.
- Extend Dashboard controls and tests without changing the external Apply link's meaning.

</code_context>

<specifics>
## Specific Ideas

- Live read-only scouting on 2026-07-24 confirmed all four public pages and exact CXS endpoints. Snapshot totals were Nasdaq 186/48 U.S., S&P Global 274/93 U.S., Morningstar 192/65 U.S., and State Street 1,292/518 U.S.; these are volatile observations, not hard-coded expectations.
- The user's mental model is a focused Active queue: marking a job Applied or Dismissed frees a slot immediately, while older qualifying jobs remain reachable through Load more.
- The future application tracker should consume the stable Mark Applied mutation rather than requiring users to repeat the action.

</specifics>

<deferred>
## Deferred Ideas

- Full application tracking—tracker rows, stages, notes, deadlines, and richer application metadata—remains in Phase 4. Phase 03.6 only establishes the reversible `applied_at` lifecycle seam.
- Workday employers from the broader 10-company pilot todo other than Nasdaq, S&P Global, Morningstar, and State Street remain outside this phase and require explicit exact-identity admission in a future scope.

</deferred>

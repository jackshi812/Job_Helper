# Phase 03.7 Context: Watchlist-First Jobs Dashboard

## Goal

Give higher priority to postings collected from explicitly watched career URLs without rebuilding the existing job feed.

## Locked Decisions

1. The default jobs destination is a watchlist-only Dashboard.
2. The existing combined watchlist-plus-external Dashboard remains available as `All Jobs`.
3. A job belongs to the watchlist-only view only when the existing normalized `jobs → companies` relationship is present. Employer-name guessing or alias matching is out of scope.
4. The watchlist-only page keeps the company filter and every existing ranking, lifecycle, table, detail, and apply behavior.
5. The existing Watchlist management page remains separate and unchanged.
6. No external-only Dashboard, company directory, new filter persistence, database migration, ingestion change, provider change, or production-data mutation is part of this phase.
7. The lightweight view is bounded by the existing server-authoritative Dashboard result window; Phase 03.7 does not create a second feed contract.

## Routes and Labels

- `/` — `Watchlist Jobs`, default and full-width.
- `/all-jobs` — `All Jobs`, the existing combined feed and full-width.
- `/watchlist` — existing watched-career-URL management page.

## Verification Boundary

- Pure source-scope tests must prove that watched rows have a normalized company relationship and external rows do not.
- Static render tests must prove the default and secondary route labels, counts, and source separation.
- The complete existing web test/build/lint gates must stay green.
- A signed-in deployed check is still required because the local browser-control surface was unavailable during implementation.

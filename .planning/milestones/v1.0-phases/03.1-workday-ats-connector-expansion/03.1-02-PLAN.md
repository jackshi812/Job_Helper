<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| bearer token → verify-board | Untrusted callers approach service-role writes and provider network access. |
| company row → connector dispatch | Persisted state may be forged or drifted before scheduled polling. |
| PollObservation → lifecycle | Partial or malicious provider evidence could incorrectly authorize closure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03.1-06 | Elevation of privilege | verify-board | high | mitigate | Require `auth.getUser` plus authenticated role before service client, provider fetch, or activation RPC; ignore client activation fields. |
| T-03.1-07 | Spoofing / Tampering | Paylocity dispatch | high | mitigate | Re-resolve board UUID and assert exact source key, null region/site, active state, and server-owned mapping before fetch. |
| T-03.1-08 | Tampering | activation evidence | high | mitigate | Only complete, positive, warning-free, count-reconciled server observations reach the service-role-only database RPC. |
| T-03.1-09 | Denial of service | company polling | medium | mitigate | Reuse bounded adapter and `Promise.allSettled`; one employer failure cannot block or close another employer. |
| T-03.1-10 | Information disclosure | handler errors/logs | medium | mitigate | Store and return bounded codes/copy only; never expose feed keys, payloads, tokens, response bodies, or database errors. |
</threat_model>

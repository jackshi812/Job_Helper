### `supabase/functions/_shared/provider-identities.ts` (config, transform)

**Analogs:** `supabase/functions/_shared/adapters/workday.ts` fixed exported source identity; `supabase/functions/_shared/detect.ts:18-35,70-80`; `supabase/functions/_shared/connectors.ts:217-223`.

The new module should be the single server-owned authority for the two Paylocity tokens:

- public board UUID: `d6628b21-949b-4400-a3d0-c9082bbf3eb1`
- separate Job Feed V2 key: `f3f28b00-201d-4fba-a7dd-532a9e558191`
- expected root/job company identity: `The Only Facial`
- exact canonical public board URL

Copy the exported-literal approach used for Capital One rather than deriving the feed key from input. The dispatch backstop in `connectors.ts:217-223` demonstrates the required second identity check:

```typescript
if (company.ats_type === 'workday') {
  if (
    company.board_token !== 'capitalone'
    || company.region !== 'wd12'
    || company.site_token !== 'Capital_One'
    || company.source_key !== CAPITAL_ONE_WORKDAY_SOURCE_KEY
  ) throw new Error('inactive_connector:workday_identity_not_allowed')
}
```

Recommended exported shape:

```typescript
export const PAYLOCITY_IDENTITIES = Object.freeze({
  'd6628b21-949b-4400-a3d0-c9082bbf3eb1': Object.freeze({
    feedKey: 'f3f28b00-201d-4fba-a7dd-532a9e558191',
    displayName: 'The Only Facial',
    canonicalUrl:
      'https://recruiting.paylocity.com/recruiting/jobs/All/d6628b21-949b-4400-a3d0-c9082bbf3eb1/The-Only-Facial',
  }),
})
```

Use the board UUID for `board_token` and the source key (recommended `paylocity:global:d6628b21-949b-4400-a3d0-c9082bbf3eb1`). Use the feed key only inside the server-constructed request URL. Do not return it from detection, persist it in `companies`, accept it from the client, or treat it as a secret.

### `supabase/functions/_shared/adapters/paylocity.ts` (provider, request-response/transform)

**Primary analog:** `supabase/functions/_shared/adapters/recruitee.ts:86-123,125-174` because both providers return a bounded whole-board JSON snapshot and malformed sibling rows must retain valid rows while denying closure.

**Transport pattern** (`recruitee.ts:86-123`):

```typescript
response = await fetchImpl(url, {
  redirect: 'error',
  signal: AbortSignal.timeout(15_000),
  headers: { accept: 'application/json' },
})
// ... status, JSON content type, declared byte cap, actual byte cap ...
const text = await response.text()
return JSON.parse(text) as unknown
```

The explicit `Accept: application/json` header is part of the proven Paylocity contract, not an optional preference. A response without it was observed with a non-JSON content type.

**Partial-row observation pattern** (`recruitee.ts:125-137,152-173`):

```typescript
function failed(code: string, jobs: NormalizedJob[] = [], expectedCount?: number) {
  return {
    jobs,
    completeness: jobs.length > 0 ? 'partial' : 'unknown',
    credibleForClosure: false,
    pageCount: jobs.length > 0 ? 1 : 0,
    ...(expectedCount === undefined ? {} : { expectedCount }),
    warnings: [code.slice(0, 64)],
  }
}

const parsed = offers.map(parseOffer)
const valid = parsed.filter((offer): offer is RecruiteeOffer => offer !== null)
const jobs = valid.map(mapRecruiteeOffer)
if (valid.length !== offers.length) {
  return failed('provider_schema_invalid', jobs, offers.length)
}
```

Paylocity-specific validation must additionally prove all of the following before returning a complete observation:

1. HTTP 200, JSON content type, declared/actual byte caps, parseable object root.
2. Root `displayName` equals the allowlisted expected name exactly after only bounded whitespace normalization.
3. Root `jobs` is an array and is nonempty; a zero snapshot is `implausible_empty`, never healthy closure evidence.
4. Every row has a stable `jobId`, nonblank title, safe provider HTTPS job/apply URLs, bounded strings, and parseable dates when present.
5. Every present `companyName` matches the expected company; every `listUrl` contains the allowlisted public board UUID and exact Paylocity host/path identity.
6. `String(jobId)` values are unique. Duplicate IDs degrade the whole observation.
7. Any malformed row preserves safely normalized siblings as `partial`, sets `credibleForClosure: false`, and reports one bounded reason code.

The provider returns no independent total or pagination contract, so successful `pageCount` is `1` and `expectedCount` is the validated root `jobs.length`. Combine `description` and `requirements` into the immutable description snapshot, set `descriptionText` with the existing bounded HTML-to-text style, prefer `publishedDate` and then `createdUtc` for `postedAt`, and set `source: 'paylocity'`.

Do not copy SmartRecruiters pagination/detail fan-out. Its reusable safety details are only the exact request hardening and bounded `ProviderError` codes (`smartrecruiters.ts:142-190`).

## Shared Patterns

### Authentication and Zero-Fetch Rejection

**Source:** `supabase/functions/verify-board/index.ts:210-242`

Apply to every Paylocity verification journey. Bearer parsing, `auth.getUser`, and authenticated-role validation precede service-role creation and provider access. Test diagnostic fetch count remains zero for auth and identity rejection.

### Bounded Provider Errors

**Source:** `supabase/functions/_shared/adapters/recruitee.ts:19-23,86-137`

Provider errors are stable codes, never response bodies. Warning codes are sliced to 64 characters. Network/status/content-type/byte/JSON/schema failures become closure-ineligible observations.

### Closure Safety and Common Persistence

**Source:** `supabase/functions/poll-tick/index.ts:189-289`

`pollConnector` returns `PollObservation`; `planCompanySync` owns closure. Empty results against existing open rows are forced to `implausibly_empty` (`216-223`). Normalized jobs use common snapshot, fingerprint, upsert, reopen, health, and close paths. Do not add Paylocity-specific persistence or dashboard code.

### Company Failure Isolation

**Source:** `supabase/functions/poll-tick/index.ts:320-358`

```typescript
const settled = await Promise.allSettled(
  companies.map((company) => processCompany(admin, company)),
)
```

One Paylocity failure updates only that company and cannot delay or close another company. The existing scheduler and heartbeat remain shared.

### Immutable Provider Identity

**Source:** `supabase/functions/poll-tick/index.ts:138-186`; `02.1-12-SUMMARY.md` immutable identity decision.

Use `source,external_id` upsert conflict handling and stable `jobId`; do not deduplicate Paylocity by title. Fingerprint repost refresh advances lifecycle only and does not overwrite first-sight identity.

### Database-Timed Activation

**Source:** `supabase/migrations/0015_activation_windows.sql:30-230`; `verify-board/index.ts:168-193`.

Callers provide evidence shape, not time or activation target. PostgreSQL owns the window, company lock, replay guard, ledger insert, three-observation cap, and promotion. Paylocity uses this same path.

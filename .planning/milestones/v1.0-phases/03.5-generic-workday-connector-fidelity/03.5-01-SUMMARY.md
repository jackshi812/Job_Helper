- Fidelity branch: an unfiltered discovery request reads the live `facets` array, verifies every named excluded family is present and that kept+excluded counts reconcile to the provider total (else `category_filter_unverified`, jobs empty, prior jobs retained), then applies the kept-family IDs as `appliedFacets.jobFamilyGroup`. No hardcoded Fidelity facet IDs, no whole-board detail fan-out.

## Decisions Made
- **Discovery request for Fidelity:** Because Workday facets are inclusion-only and list rows carry no `jobFamilyGroup`, the kept-family IDs must be learned live. Chose one unfiltered discovery request (reads `total` + `facets`) before the scoped recent-window loop. This is the concrete resolution of D-06's open technical question (apply-all-other-family-facets).
- **Capital One path untouched at runtime:** `keptFacetIds` present → the existing single facet-applied path with page-0 applied-subset reconciliation runs verbatim (no discovery request), preserving byte-identical request counts and bodies. Discovery is gated to `excludedJobFamilyGroups` identities.
- **Reconciliation strictness:** For Fidelity, fail closed unless (a) every named excluded family is present in the facets array, (b) all values are well-formed `{descriptor,id,count}`, and (c) sum(all counts) equals the provider total. New (unnamed) families are kept by default.

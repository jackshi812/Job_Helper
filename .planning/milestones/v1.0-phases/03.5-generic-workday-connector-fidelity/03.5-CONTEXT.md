# Phase 03.5: Generic Workday Connector & Fidelity - Context

**Gathered:** 2026-07-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Generalize the existing single-tenant (Capital One) Workday connector so additional Workday employers can be ingested through the normal watchlist flow, and onboard **Fidelity** (`https://wd1.myworkdaysite.com/en-US/recruiting/fmr/FidelityCareers`) as the first new tenant.

In scope: parameterizing the Workday adapter across the two real Workday URL shapes; teaching `verify-board` to detect + parse Workday board URLs; a forward-only migration that admits non–Capital-One Workday identities; category-facet-scoped ingestion for Fidelity.

Out of scope: resume tailoring / tracker (Phase 4); vanity/proxy-domain Workday boards; bot-wall header handling; over-cap recency-fallback for very large tenants (Fidelity fits under caps).

</domain>

<decisions>
## Implementation Decisions

### Generalization scope
- **D-01:** Generalize the adapter to the **two known Workday URL shapes**, no more:
  - Form A: `{tenant}.{region}.myworkdayjobs.com/{site}` (Capital One) — tenant in subdomain
  - Form B: `{region}.myworkdaysite.com/{locale}/recruiting/{tenant}/{site}` (Fidelity) — tenant in path
  - The CXS path `/wday/cxs/{tenant}/{site}` is identical across both; only origin construction differs.
- **D-02:** Reject any pasted URL that does not cleanly resolve to a CXS endpoint. No proxy/vanity-domain resolution this phase (deferred).

### How a company is added
- **D-03:** Adds happen through the **existing Watchlist paste-URL UI**. `verify-board` auto-detects Workday and parses `tenant`/`region`/`site` from the URL — same UX as Greenhouse/Lever/Ashby. Adding future Workday employers becomes a runtime action, not dev work.
- **D-04:** `verify-board` remains the authoritative SSRF/validation boundary (Phase 02 decision carried forward). Watchlist edits stay remove + re-add (polling identity is derived from live verification).

### Ingestion breadth + filtering
- **D-05:** Fidelity ingestion is **category-facet-scoped**, like Capital One's model. Exclude the `jobFamilyGroup` families **Sales, Customer Service, and Sales Support** at/around the source.
- **D-06:** Because Workday facets are **inclusion-only** and Fidelity's whole board (706) is under the 2000-job cap, the exclusion may be implemented as fetch-whole-board-then-drop-excluded-families OR apply-all-other-family-facets — **research/planner picks** the cleaner mechanism. (Open technical question, not a user decision.)
- **D-07:** The **"experience < 3 years" rule is enforced downstream**, by the existing dashboard experience/title filters — NOT parsed from JD text at ingestion. Keeps a single filtering surface and avoids fragile free-text parsing.

### Activation & health
- **D-08:** Fidelity matches the **Capital One activation model**: lands Experimental, auto-promotes to Active after 3 clean server-timed observation windows (per migration 0028 pattern). Reuse the existing OK/Degraded/Unsupported health badges.

### Folded Todos
- **"Pilot Workday polling for 10 companies"** (api, score 0.4): this phase's generalization is the enabling step — a paste-URL Workday connector + Fidelity as first real tenant is the pilot's foundation. Remaining "10 companies" breadth stays a follow-on.

</decisions>

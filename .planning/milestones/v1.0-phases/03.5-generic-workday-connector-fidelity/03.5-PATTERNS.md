## Shared Patterns

### Identity registry (the spine of this phase)
**Source:** `supabase/functions/_shared/provider-identities.ts` (whole file, 30 lines)
**Apply to:** the new Workday identity module + every consumer (detect, connectors, verify-board, workday.ts).
Paylocity proves the exact shape the planner should generalize: an exported frozen source-key constant, a frozen identity object, a frozen keyed map, and a `resolveX(key): Identity | null` pure resolver.
```typescript
export const PAYLOCITY_SOURCE_KEY = `paylocity:global:${PAYLOCITY_BOARD_UUID}` as const
const paylocityIdentity: PaylocityIdentity = Object.freeze({ boardUuid: ..., feedKey: ..., displayName: ..., canonicalUrl: ..., sourceKey: PAYLOCITY_SOURCE_KEY })
export const PAYLOCITY_IDENTITIES = Object.freeze({ [PAYLOCITY_BOARD_UUID]: paylocityIdentity })
export function resolvePaylocityIdentity(boardUuid: string): PaylocityIdentity | null {
  return boardUuid === PAYLOCITY_BOARD_UUID ? paylocityIdentity : null
}
```
**Generalize to:** `resolveWorkdayIdentity(tenant, region, site, hostForm): WorkdayIdentity | null` returning `{ origin, cxsRoot, publicBoard, tenant, site, region, hostForm, sourceKey, companyName, excludedJobFamilyGroups }`. Keep `CAPITAL_ONE_WORKDAY_SOURCE_KEY = 'workday:wd12:capitalone:Capital_One'` (currently exported from `workday.ts` L49, re-imported by `connectors.ts` L8 and `verify-board` L5) byte-identical as one frozen entry; add Fidelity (`workday:wd1:fmr:FidelityCareers`) as a second. **Note A1 (research):** region alone cannot disambiguate `myworkdayjobs` (Form A) vs `myworkdaysite` (Form B) — the registry must be keyed on the full tuple and carry `hostForm`/`origin`, or persist host-form. Do NOT invent a "wd1 ⇒ myworkdaysite" rule.

### SSRF origin-equality guard (must survive parameterization intact)
**Source:** `workday.ts::safeDetailPath` (L161-198)
**Apply to:** all detail-fetch paths in the parameterized adapter.
The invariants (starts `/job/`, no `\`, `?`, `#`, no `%2f`/`%5c`, no `..`/`.` segments, origin equality, no creds/port) are origin-agnostic. Currently closes over module constants `PUBLIC_ORIGIN`/`CXS_ROOT`/`PUBLIC_BOARD` (L183-195). Refactor to `safeDetailPath(value, origin, cxsRoot, publicBoard)` (or a closure bound to the resolved identity). Never relax any invariant.

### Fail-closed category-filter verification (reuse verbatim for Fidelity)
**Source:** `workday.ts::pollCapitalOneRecent` facet reconciliation (L573-596)
**Apply to:** Fidelity kept-family inclusion facets (D-05/D-06 → research recommends **inclusion of kept families**).
Reads the returned `facets` array, matches each expected `{descriptor,id}`, and asserts `sum(counts) === providerTotal`, else `incomplete([], 'category_filter_unverified', ...)`. For Fidelity, invert the config: hold the *excluded* descriptor set `{Sales, Customer Service, Sales Support}`, discover IDs live from the `facets` array, take all `jobFamilyGroup` values whose `descriptor ∉ excludedSet` as the inclusion list, and assert `sum(kept) + sum(excluded) === total`. New families are included by default.
```typescript
const facets = Array.isArray(page.facets) ? page.facets : []
const categoryFacet = facets.find((f) => f && typeof f === 'object'
  && (f as { facetParameter?: unknown }).facetParameter === 'jobFamilyGroup') as { values?: unknown } | undefined
const values = Array.isArray(categoryFacet?.values) ? categoryFacet.values : []
// ...match descriptor+id, sum counts, compare to providerTotal → 'category_filter_unverified' on mismatch
```

# Phase 03 Plan 07: Feed-only closeout

## Objective

Remove the notification subsystem completely, retain scoring and feed behavior, then prove and deploy the feed-only Phase 3 release.

## Context

Plans 03-05 and 03-06 built push/email notification infrastructure. On 2026-07-19 the owner removed notifications from product scope. Their implementation history remains in summaries and applied migrations, but no notification runtime, UI, active requirement, or hosted service should remain after this plan.

## Tasks

### Task 1: Remove notifications locally

- Delete `notify-tick`, push/quiet-hours helpers, service worker, browser push client, notification verifier, VAPID generator/key, and notification-specific tests.
- Remove notification controls and fields from Settings/preferences.
- Add migration 0024 to unschedule `notify-tick`, replace `delete_my_data`, drop notification RPC/tables, and drop notification preference columns.
- Remove notification assumptions from active verification scripts and project/planning authority docs.
- Preserve historical applied migrations 0017 and 0020 unchanged.

Verification:

```sh
cd web && npm test -- --run
cd web && npm run build
cd web && npm run lint
```

### Task 2: Hosted feed-only cleanup and deployment [APPROVAL]

After explicit approval:

1. Push migration 0024. This permanently deletes hosted notification ledger rows, push subscriptions, and notification preference values.
2. Delete hosted Edge Function `notify-tick`.
3. Remove notification-only Supabase secrets: `VAPID_KEYS`, `RESEND_API_KEY`, and `RESEND_FROM`.
4. Push the approved commits to `origin/main`, let Cloudflare Pages rebuild, and remove `VITE_VAPID_PUBLIC_KEY` from its environment.
5. Bind acceptance evidence to the exact commit, function inventory, migration head, and immutable frontend asset hash.
6. Run one explicitly approved `verify-scoring.ts` hosted invocation; do not loop or retry without renewed approval.

### Task 3: Human UAT [CHECKPOINT]

On the exact deployed release:

1. Save titles, locations, and include/exclude keywords.
2. Confirm irrelevant jobs are cheaply filtered before AI use.
3. Review a representative 20-job sample; at least 16 scores/reasons should be judged useful.
4. Confirm the feed and job detail show score, reasons, posted time, apply link, JD snapshot, and advisory gaps.
5. Confirm Settings has no notification controls and the browser receives no new job alerts.

`exactUatApproval`.

The `source_commit` is the clean commit containing all implementation,
rollout, activation, hosted-verification, UAT-helper, safety-test, and initial
PENDING evidence-template bytes from Plans 01-04. The manifest and preflight
are release metadata created after that commit; they do not redefine it.
Validation compares every path in the manifest's immutable source inventory
to its Git object at `source_commit` and current SHA-256. PENDING evidence
records are a separate mutable-artifact inventory: the manifest binds their
initial template hashes, exact allowed writers, schema, and state transitions;
after an approved write, the verifier checks the evidence hash chain rather
than pretending the PENDING template remains unchanged. A later metadata
commit is allowed only when all immutable bound path objects remain identical;
any immutable bound-path edit fails closed.

Manifest creation is one-way. Plan 06 consumes the exact file without adding
actions, paths, hashes, exceptions, approvals, or alternate bytes.
